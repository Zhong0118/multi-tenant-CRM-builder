# 项目说明书

版本：0.1
状态：待审阅

## 1. 产品定义

### 1.1 一句话定位

面向仍以 Excel、文件夹和员工个人表格管理业务的中小企业，由平台方快速配置并交付的多租户在线 CRM。

### 1.2 要解决的问题

- 同一公司的数据分散在多个员工文件中，管理员无法实时掌握全局。
- 表格由多人自由修改，字段值不统一、权限不明确、历史不可追溯。
- 每家公司业务字段不同，直接开发固定 CRM 难以复用。
- 统计依赖人工汇总，指标口径不稳定。
- 飞书、电话 Bot 等入口缺少统一身份、权限和主数据来源。

### 1.3 产品价值

```text
客户提供 Excel 与业务规则
→ 平台管理员配置业务模板或租户配置
→ 导入历史数据并创建成员
→ 员工在统一系统处理自己的工作
→ 租户管理员实时查看全量数据与统计
```

平台的目标不是让客户在首期自己搭建任意系统，而是提高平台方交付 CRM 的效率和一致性。

## 2. 产品边界

### 2.1 通用平台 MVP 包含

- 单一代码库、单一部署服务多个租户。
- 平台管理员创建、启用、停用租户。
- 用户账号、租户成员和三类人类角色。
- 业务模板、业务对象、字段和视图的受控配置。
- 动态表单、分页表格、筛选、排序、详情抽屉。
- `ALL` / `OWN` 数据范围及字段级三态权限。
- 记录活动、附件、审计日志。
- 固定配置的 Dashboard。
- Excel/CSV 导入预览和导出。
- 对飞书、电话 Bot 和 Webhook 预留统一集成框架。

### 2.2 首家公司首期包含

- 电话 Bot 线索结果的人工审核入口；电话 Bot 真正接入可后置。
- 人工外呼线索录入。
- 线索分配、转跟单。
- 跟单主记录、跟进活动和阶段推进。
- 跟单成功后转为客户，保留完整来源链路。
- 客户管理。
- 期刊记录，部分字段仅管理员可编辑。
- 管理 Dashboard 与员工业绩统计。

### 2.3 明确不做

- 租户自助创建任意关系、公式、汇总字段和工作流。
- 部门层级、经理继承、多角色组合或 ABAC。
- 每家公司一套代码、一套部署或默认一套数据库。
- 用户任意设计 Dashboard。
- 微服务、事件总线和独立数据仓库。
- AI 自动决策或未经确认直接写入关键业务数据。
- 原生移动 App。
- 计费、套餐购买和在线支付。

## 3. 用户与职责

| 角色 | 作用范围 | 主要职责 | 明确限制 |
|---|---|---|---|
| 平台管理员 | 整个平台 | 管理租户、模板、租户配置、集成和平台状态 | 默认不直接参与租户日常业务 |
| 租户管理员 | 当前租户 | 管成员、看全部数据、分配记录、统计、导入导出 | 不能管理其他租户或平台能力 |
| 员工 | 当前租户 | 处理获准模块中自己负责的数据 | 不能查看他人记录或管理权限 |
| 集成身份 | 绑定租户及权限集 | 通过 API 读写获准数据 | 不能交互式登录，权限不得高于配置 |

### 3.1 平台代管模式

平台管理员需要协助排错或配置租户数据时，必须：

1. 选择目标租户并填写进入原因。
2. 界面持续显示“正在代管某租户”。
3. 所有操作记录平台管理员、目标租户和代管原因。
4. 默认只读；写操作需要再次确认。

## 4. 核心概念与原则

### 4.1 模板不是代码副本

业务模板是业务对象、字段、视图、状态和权限的配置集合。应用模板后生成租户配置；后续修改模板不会自动覆盖租户已调整内容，必须经过显式升级。

### 4.2 员工表是视图，不是独立表

公司内同一业务对象只有一套记录。员工页面自动应用 `owner_member_id = 当前成员`；管理员页面使用 `ALL` 范围。

### 4.3 动态配置与固定业务动作并存

字段、表单和列表由元数据驱动；需要事务和明确规则的动作由后端显式实现，例如“线索转跟单”和“跟单转客户”。不允许使用前端复制记录模拟状态转换。

### 4.4 PostgreSQL 是主数据源

CRM 网站、飞书机器人和电话 Bot 都通过同一授权服务访问 PostgreSQL 中的主数据。飞书多维表格不作为系统主数据库。

## 5. 通用业务流程

### 5.1 新租户交付

```text
创建租户
→ 选择业务模板
→ 创建首位租户管理员
→ 调整业务对象与字段
→ 配置权限和 Dashboard
→ 导入历史数据并预检
→ 租户管理员验收
→ 启用租户
```

### 5.2 员工日常处理

```text
登录
→ 进入当前租户
→ 查看我的工作台
→ 打开获准模块
→ 搜索/筛选自己的记录
→ 在详情抽屉更新字段或追加活动
→ 查看保存结果及下一步任务
```

### 5.3 租户管理员管理

```text
查看 Dashboard
→ 识别待分配、逾期或异常数据
→ 在全量列表筛选并批量分配
→ 查看员工明细
→ 导出授权数据或调整成员状态
```

## 6. 功能优先级

### P0：没有则不能上线

- 身份认证、租户上下文和数据隔离。
- 三种角色与集成身份。
- 租户、成员、业务对象、字段、记录和活动。
- ALL/OWN 数据范围、动作权限和字段权限。
- 首家公司获客、跟单、客户转换闭环。
- 审计日志、基础搜索筛选和错误状态。

### P1：首期交付应包含

- Dashboard、期刊、导入导出、附件。
- 模板应用与平台配置界面。
- 批量分配、保存视图、移动端关键操作。

### P2：框架预留，后续实现

- 飞书账号绑定、机器人查询/录入和通知。
- 电话 Bot Webhook、通话结果与 AI 摘要。
- 通用 Webhook、定时自动化。
- 租户自定义域名、自定义角色和自助字段配置。

## 7. 指标与口径原则

- 每个 Dashboard 指标必须定义：对象、时间字段、过滤条件、去重键和权限范围。
- “新增”按记录 `created_at`；“成交”按成功转换时间，不按最后更新时间。
- 转化率必须显示分子、分母和统计期间。
- 员工业绩默认归属成交时负责人；负责人变更后的历史归属规则需在首家公司确认。
- 已删除记录默认不参与统计；恢复后重新参与。

## 8. 安全与合规基线

- 密码使用成熟密码哈希算法，不自行实现加密。
- 登录、导入、导出、集成入口和敏感查询限流。
- Session/Token 撤销、成员停用和租户停用应即时生效。
- 电话、邮箱等敏感字段是否脱敏由字段定义控制。
- 导出、批量修改、权限变更、代管和集成调用必须审计。
- 附件使用私有对象存储和短时签名 URL。
- 数据备份与恢复演练是上线要求，而非部署后的补充项。

## 9. 非功能目标

| 维度 | 首期目标 |
|---|---|
| 可用性 | 月度 99.5%，计划维护除外 |
| 性能 | 常用列表 P95 < 800ms，普通写操作 P95 < 500ms |
| 容量假设 | 20–100 个租户，单租户 50 名成员、10 万业务记录 |
| 数据恢复 | RPO ≤ 24h，RTO ≤ 4h；商业上线前再提高 |
| 浏览器 | 最新两个主要版本的 Chrome、Edge、Safari、Firefox |
| 可访问性 | 键盘可操作、可见焦点、语义标签、颜色非唯一信息载体 |
| 可观测性 | 请求 ID、结构化日志、错误告警、关键任务指标 |

## 10. 首期验收条件

- 两个测试租户使用相同对象和相同记录 ID 尝试越权时均被拒绝。
- 员工不能通过页面、API、批量接口或导入修改只读字段。
- 租户管理员可查看全员记录，员工只看到自己的记录。
- 转换动作重复提交不会产生重复跟单或客户。
- 每条跟进活动可追溯到操作者和时间，不能覆盖旧活动。
- Dashboard 数字能通过明细列表复算。
- 停用成员后其现有会话不可继续访问。
- 导入失败不会写入半批数据，错误可下载并修正。

## 11. 待业务样表确认项

以下内容不阻碍平台设计，但会影响首家公司模板最终字段：

- 各系统现有 Excel 表头、示例数据和必填规则。
- 跟单阶段及允许的阶段迁移。
- 重复客户判断规则（电话、公司名或组合）。
- “业绩”的金额、数量、归属和退款处理口径。
- 期刊两列受保护字段的实际名称和审批时机。
- 电话 Bot 供应商、回调结构和失败重试语义。
- 飞书中需要支持的查询、录入和通知命令清单。
