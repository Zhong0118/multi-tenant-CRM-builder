# 百杰 CRM 落地页改版：设计说明

## 任务

- **页面：** `crm.baijiehub.com` 的公开产品页。
- **读者：** 中国中小企业的老板、销售主管，以及每天用表格跟客户的员工。
- **主动作：** 已有账号的人登录工作区；新用户用手机号创建个人账号（公开注册已开启，加入公司仍需管理员邀请）；第一次来的人看懂它能替代哪些表格。
- **设备：** 桌面为主，平板和手机浏览器必须完整可读、可操作。
- **事实来源：** 只写当前部署版本（`main` = 生产 `e25d3d2`）里已有的能力。#43、#44 里的功能写进“正在路上”，标明尚未上线。

## 品类与标杆

**品类：** 可配置的 B2B CRM。看了两家（截图在 `refs/`，2026-10-22 实拍）：

- **Attio：** 居中粗黑体大标题、单色界面，首屏下方一个真实工作区，里面打字演示 AI 提问。
- **Twenty：** 衬线标题配等宽导航、切角按钮，品牌蓝的像素条做数据纹理，首屏下方是整张公司表。

| | 做法 | 理由 |
| --- | --- | --- |
| **留下** | 产品界面就是主视觉（基线） | 买 CRM 的人要先看到“它长什么样、我每天怎么用” |
| **换掉** | 居中大标题、AI 打字演示 | 改成左对齐的一条标题带，主视觉换成本产品最核心的动作“领取线索” |
| **换掉** | 英文衬线与等宽字 | 中文页面用系统中文黑体；数字用等宽 |

## 方向（三选一，自定 A）

三个首屏在 `explore/style-explorer.html`：

- **A 打开就是在用**（选定）
- **B 一行一行往前推**（方格标志放大成首屏）
- **C 一眼看完一家公司的业务**（界面碎片拼贴）

**选 A 的理由：**

- 目标读者要先看到产品；A 的信息最清楚。
- 和标杆不撞脸：左对齐标题带，三栏工作区，品牌青绿与墨色。
- 首屏可以做成真的可操作。

B 的“方格里一行被往前推”是品牌标志本来讲的故事，并入 A 当记忆点：在首屏点“领取”，这一行被提起，移进“待联系”，期限开始倒数。C 的面太散，没有主角，不取。

## 方向卡

| 项 | 选择 |
| --- | --- |
| 北极星 | 打开就是在用：每一段都让读者亲手推进一条业务，而不是读功能清单 |
| 调性 | 能量偏安静（工作工具）；完成度精致；密度中偏密（真实工作区）；分量中；严肃度偏庄重（企业采购） |
| 生成引擎 | 一个具体场景：禾木办公家具这家虚构经销商的一个工作日，全页共用同一批客户、同事和数字 |
| 首屏骨架 | 画面即界面。顶部一条标题带（标题、两句说明、两个按钮）约占首屏高度 28%；下方三栏工作区（导航 / 公海列表 / 记录详情）约占 62%，阅读从标题开始，视线落到高亮的那一行和“领取” |
| 页面结构 | 单列滚动的章节，每章是“一句判断 + 一个能动手的界面片段 + 三到四条可核对的细节”，章节之间用底色硬切 |
| 字体 | PingFang SC / HarmonyOS Sans SC / Noto Sans SC。展示标题 650 字重，44–52px；章节标题 30–34px；正文 17px，行高 1.75；界面片段 14px；数字 `tabular-nums` |
| 色彩 | 底色 `#f3f6f8`；纸面 `#ffffff`；墨色 `#17232d`（标题、深色章节）；主强调 `#167568`（动作、选中）；其软底 `#e7f3f0`；提醒 `#c66c18`，软底 `#fff3e5`（期限、待确认）；描边 `#d8e0e5`。全部来自产品现有设计变量 |
| 主视觉 | 产品界面本身，用真实组件的样子手写成静态 / 可交互片段，不放截图 |
| 图标 | 不用图标库；品牌方格标志，加字符 → ↗ · |
| 控件语法 | 8px 圆角、1px 描边，主按钮实心青绿，按下缩到 0.97；选中用会移动的底块；标签是全圆角软底小字 |
| 动效 | 手感是“咔嗒 + 抽屉阻尼”：领取像把一张卡片从架上取下，短促到位。三处基本动效：领取按钮的按下与交接、工作区标签页的滑块、首次进入时工作区先到。滚动：各章节按内容出场一次；“线索公海”一章做一段一镜到底，主角是一张客户卡片，沿“线索池 → 待联系 → 跟进中 → 成交保护”走完，每段停下时出现说明 |
| 结构性突破 | 首屏不是标题加截图，而是一个能领取线索的工作区 |
| 记忆点 | 首屏领取：这一行被提起，滑进“待联系”，联系期限从 24 小时开始倒数 |
| 放弃什么 | 不放客户评价、客户标志和业绩数字（没有真实可用的）；不放功能卡片墙；不用渐变光晕 |

## 滚动分镜

1. **首屏：** 首次进入时工作区先到，标题带随后（420ms）。
2. **“搭表”：** 字段列表按阅读方向依次落位；“发布”按钮可点，员工视图跟着更新。
3. **“线索公海”：** 一镜到底。舞台固定约 220vh；客户卡片沿四段轨道移动，每段约 55vh；文字在卡片停下的区间出现。往回滚倒放；减少动态效果时排成四个静止画面。
4. **“数据进出”和“流程”：** 列表行依次展开，流程连线沿方向描出。
5. **“权限”：** 两个视角的表格同时落下，员工那边的隐藏列收起。
6. **AI：** 深色章节，问题、回答、来源依次出现；“确认执行”可点。

实现：没有引入动效库（用户要求避免不必要的依赖），用 CSS 滚动驱动动画（`animation-timeline`）。浏览器不支持时退成静止画面；首次出场用 IntersectionObserver。

## 交付记录（2026-10-22）

- **实现：** `apps/web/src/features/landing/`。所有可核对的说法集中在 `content.ts`，逐条对过 `main` 的代码；只在未合并 PR 里的功能放在 `ROADMAP`，页面上标“尚未上线”。
- **可操作片段（虚构数据，不发请求、不保存）：** 首屏领取线索并开始 24 小时倒数；搭表草稿发布后员工列表多出一列；AI 助手的确认 / 拒绝。
- **动效：** 首屏工作区先到、标题带随后；领取时整行提起移出，“待联系”计数跳一下，期限卡落位；各章节出场一次（IntersectionObserver）；线索公海一镜到底（CSS `animation-timeline`，舞台吸顶约 240vh）。减少动态效果、窄屏（< 960px）或浏览器不支持时，线索公海是静态的四段列表，出场动画不启用。
- **证据：** `final/` 下是本地预览截图（1440×900 桌面、375×812 手机）：首屏、领取后、公海第二段、每天、AI、页脚备案号、手机首屏、手机公海静态版。
- **评审：** 未派独立评审，由实现者对照截图自查一轮；修正了工作区表格在 1024px 换行、首屏线索备注写死、公海卡片在时间线启动前叠字、手机小表格换行。
- **减法：** 去掉了旧版的五步演示、产品窗口和“百杰出品”落款；每章只留一句判断、一个片段和可核对的细节。
- **没做：** Open Graph 分享图（需要随项目打包中文字体，另做）；`refs/` 里的竞品截图只留在本地，不进仓库。
