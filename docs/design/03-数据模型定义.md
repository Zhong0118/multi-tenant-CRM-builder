## 1. 建模原则

1. `tenant_id` 是安全边界，不是普通筛选字段。
2. 稳定、可关联、需约束或高频索引的数据使用普通列。
3. 租户自定义字段值放入 `records.data JSONB`，字段结构由 `field_definitions` 定义。
4. 历史行为使用追加式活动或审计记录，不用“第一次跟进、第二次跟进”列。
5. 用户账号与租户身份分离；用户可以暂不属于租户，也可以属于多个租户。
6. 业务模板是版本化配置，应用后形成独立租户配置。
7. 删除默认是软删除或停用；审计、来源和关联记录不得级联消失。

## 3. 标识与通用字段

- 主键统一使用 UUIDv7 或数据库可排序 UUID；禁止前端生成具有授权含义的 ID。
- 所有时间使用 `timestamptz`，服务端保存 UTC，界面按用户时区显示。
- 租户业务表至少包含 `tenant_id`、`created_at`、`updated_at`。
- 可编辑聚合根包含 `version integer`，更新时进行乐观锁检查。
- 软删除使用 `deleted_at`，查询默认排除；审计日志不允许软删除。
- 代码字段 `code` 在所属范围内唯一，发布后不可随意修改。

## 4. 身份与租户

### 4.1 `users`

登录账号，不直接表示某家公司员工。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `display_name` | varchar(100) | 必填 |
| `email` | varchar(320) | 可空；保存前规范化为小写，存在时唯一 |
| `phone` | varchar(32) | 首期必填，E.164/国内规范化后唯一 |
| `phone_verified_at` | timestamptz | 注册成功时必填 |
| `password_hash` | text | 必填；公司管理员不可读取或代设 |
| `is_platform_admin` | boolean | 默认 false；仅平台授权流程可改 |
| `status` | enum | `ACTIVE` / `DISABLED` / `LOCKED` |
| `last_login_at` | timestamptz | 可空 |
| `created_at` / `updated_at` | timestamptz | 必填 |

规则：首期使用已验证手机号作为唯一登录标识，按中国大陆手机号校验并存为 `+86` E.164 格式；邮箱为可选联系资料，不用于首期认证。注册成功并不要求存在 `tenant_members`。密码重置撤销当前会话之外的全部会话。

### 4.2 `tenants`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `name` | varchar(200) | 展示名 |
| `code` | varchar(64) | 全局唯一，`[a-z0-9-]+` |
| `status` | enum | `DRAFT` / `ACTIVE` / `SUSPENDED` / `CLOSED` |
| `timezone` | varchar(64) | 默认 `Asia/Shanghai` |
| `locale` | varchar(16) | 默认 `zh-CN` |
| `settings` | jsonb | 品牌、格式等低频配置 |
| `activated_at` | timestamptz | 可空 |
| `created_at` / `updated_at` | timestamptz | 必填 |

### 4.3 `tenant_domains`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | FK tenants |
| `domain` | citext | 全局唯一 |
| `type` | enum | `PLATFORM_SUBDOMAIN` / `CUSTOM_DOMAIN` |
| `status` | enum | `PENDING` / `VERIFIED` / `DISABLED` |
| `verified_at` | timestamptz | 可空 |

MVP 可仅启用统一域名和工作空间选择，但保留该表支持后续子域名。

### 4.4 `tenant_members`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK，也是记录负责人引用值 |
| `tenant_id` | uuid | FK tenants |
| `user_id` | uuid | FK users |
| `role` | enum | `TENANT_ADMIN` / `EMPLOYEE` |
| `status` | enum | `ACTIVE` / `DISABLED` |
| `employee_no` | varchar(64) | 可空，租户内唯一 |
| `joined_at` | timestamptz | 可空 |
| `created_at` / `updated_at` | timestamptz | 必填 |

唯一约束：`(tenant_id, user_id)`。停用成员前必须处理其负责记录，记录不能因为成员停用而删除。

成员关系只在用户接受有效邀请时创建。邀请等待、过期和拒绝状态不得塞入 `tenant_members.status`。

### 4.5 `tenant_invitations`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | 目标租户 |
| `target_phone` | varchar(32) | 规范化手机号 |
| `target_user_id` | uuid | 可空；手机号已有用户时关联 |
| `role` | enum | `TENANT_ADMIN` / `EMPLOYEE` |
| `permission_overrides` | jsonb | 可空，员工模块权限初始值 |
| `invitation_code_hash` | text | 邀请码哈希，不存明文 |
| `status` | enum | `PENDING` / `ACCEPTED` / `DECLINED` / `REVOKED` / `EXPIRED` |
| `created_by_user_id` | uuid | 平台管理员或租户管理员对应 User |
| `expires_at` | timestamptz | 必填 |
| `accepted_by_user_id` | uuid | 接受后填写，手机号必须匹配 |
| `accepted_at` | timestamptz | 可空 |
| `created_at` / `updated_at` | timestamptz | 必填 |

同一租户与手机号同时只能存在一个有效 `PENDING` 邀请。接受邀请和创建 `tenant_members` 必须在同一事务中完成，并对重复提交保持幂等。

独立用户查询邀请时，只能按当前 User 的已验证手机号读取经过裁剪的公司名称、角色、邀请人和有效期，不能借邀请接口读取目标租户的其他配置或成员。尚未关联 `target_user_id` 的邀请，在手机号匹配后由接受事务绑定当前 User。

### 4.6 `verification_challenges`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `phone` | varchar(32) | 规范化手机号 |
| `purpose` | enum | `REGISTER` / `RESET_PASSWORD` / `CHANGE_PHONE` |
| `code_hash` | text | 验证码哈希 |
| `status` | enum | `PENDING` / `CONSUMED` / `EXPIRED` / `LOCKED` |
| `attempt_count` | smallint | 超限后锁定 |
| `expires_at` / `consumed_at` | timestamptz | 过期与使用时间 |
| `request_ip` | inet | 风控与限流 |
| `created_at` | timestamptz | 必填 |

验证码短时有效、一次性使用，按手机号、IP 和设备维度限制发送与验证频率。接口响应不得暴露手机号是否已有账号。

### 4.7 `sessions`

保存可撤销会话摘要：`user_id`、令牌哈希、过期时间、最后使用时间、IP/设备摘要和撤销时间。数据库不得保存明文访问令牌。

## 5. 模板与配置

### 5.1 `business_templates`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | PK |
| `name` / `code` | varchar | 名称与全局唯一代码 |
| `description` | text | 适用业务 |
| `status` | enum | `DRAFT` / `PUBLISHED` / `ARCHIVED` |
| `created_by` | uuid | 平台管理员 user_id |

### 5.2 `template_versions`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | PK |
| `template_id` | uuid | FK business_templates |
| `version` | integer | 模板内递增唯一 |
| `configuration` | jsonb | 完整不可变配置快照 |
| `change_summary` | text | 变更说明 |
| `published_at` | timestamptz | 发布后不可修改 |

模板应用必须记录来源模板和版本，但租户配置不依赖模板在线读取。

### 5.3 `object_definitions`

代表获客、跟单、客户、期刊等业务对象。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | FK tenants |
| `name` | varchar(100) | 展示名称 |
| `code` | varchar(64) | 租户内唯一，发布后稳定 |
| `kind` | enum | `GENERIC` / `LEAD` / `OPPORTUNITY` / `CUSTOMER` / `JOURNAL` |
| `title_field_key` | varchar(64) | 记录主标题字段 |
| `icon` | varchar(64) | 受控图标键 |
| `status` | enum | `DRAFT` / `ACTIVE` / `ARCHIVED` |
| `settings` | jsonb | 编号、附件、活动等开关 |
| `source_template_version_id` | uuid | 可空 |
| `version` | integer | 乐观锁 |

`kind` 用于挂接受控领域动作，不允许用租户名称或 ID 写专属判断。

### 5.4 `field_definitions`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | 冗余安全边界，与对象一致 |
| `object_id` | uuid | FK object_definitions |
| `field_key` | varchar(64) | 对象内唯一，发布后稳定 |
| `label` | varchar(100) | 界面名称 |
| `type` | enum | 见字段类型表 |
| `required` | boolean | 默认 false |
| `is_system` | boolean | 系统字段不可删除 |
| `is_sensitive` | boolean | 影响脱敏、导出和审计 |
| `default_value` | jsonb | 可空，须符合类型 |
| `validation` | jsonb | 长度、范围、格式等 |
| `config` | jsonb | 选项、单位、附件限制等 |
| `sort_order` | integer | 表单顺序 |
| `status` | enum | `ACTIVE` / `INACTIVE` |

MVP 字段类型：

| 类型 | JSON 值 | 说明 |
|---|---|---|
| `TEXT` / `TEXTAREA` / `PHONE` / `EMAIL` | string | 电话按字符串保存，避免丢失前导零 |
| `NUMBER` / `MONEY` | number 或十进制字符串 | 金额统一精度和币种配置 |
| `DATE` | `YYYY-MM-DD` string | 不含时区 |
| `DATETIME` | ISO 8601 string | 服务端转 UTC |
| `SINGLE_SELECT` | option key | 选项键稳定，标签可变 |
| `MULTI_SELECT` | option key array | 去重 |
| `MEMBER` | tenant_member uuid | 必须属于当前租户且有效 |
| `BOOLEAN` | boolean | 不用字符串 yes/no |
| `ATTACHMENT` | file id array | 文件必须属于当前租户 |

暂不支持公式、汇总、查找和任意关系字段。

### 5.5 `view_definitions`

保存列表列、固定筛选、默认排序、可见角色和视图类型。MVP 支持 `TABLE`；看板视图后置。个人临时筛选不应修改共享视图。

### 5.6 `object_permissions`

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenant_id` / `object_id` | uuid | 复合范围 |
| `subject_type` | enum | `ROLE` / `MEMBER` |
| `subject_role` | enum | subject_type=ROLE 时使用，首期为 `EMPLOYEE` |
| `subject_member_id` | uuid | subject_type=MEMBER 时使用，必须同租户 |
| `can_create/read/update/delete/export` | boolean | 动作权限 |
| `read_scope` | enum | `ALL` / `OWN` / `NONE` |
| `update_scope` | enum | `ALL` / `OWN` / `NONE` |

角色策略提供租户默认值，成员策略只覆盖该成员。首期员工通常 `read_scope=OWN`、`update_scope=OWN`，租户管理员固定 ALL；删除默认 false。权限合并采用明确的“成员覆盖角色默认”规则，不能把多条允许策略简单相加。

### 5.7 `field_permissions`

唯一键 `(tenant_id, field_id, subject_role)`，`access` 为 `EDIT`、`READ_ONLY` 或 `HIDDEN`。管理员字段默认 EDIT；系统审计字段始终只读。

## 6. 业务记录

### 6.1 `records`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | 强制隔离键 |
| `object_id` | uuid | FK object_definitions，必须同租户 |
| `record_no` | bigint | 租户/对象内可读编号 |
| `owner_member_id` | uuid | 可空，必须同租户 |
| `status_key` | varchar(64) | 受字段/状态配置约束 |
| `title` | varchar(300) | 从主字段冗余，便于列表与关联展示 |
| `data` | jsonb | 动态字段值 |
| `source` | enum | `MANUAL` / `IMPORT` / `FEISHU` / `PHONE_BOT` / `API` |
| `created_by_member_id` | uuid | 人类成员时填写 |
| `created_by_integration_id` | uuid | 集成身份时填写 |
| `version` | integer | 乐观锁 |
| `created_at` / `updated_at` | timestamptz | 必填 |
| `deleted_at` | timestamptz | 软删除 |

约束：两种 `created_by` 至少一个存在且不能同时存在；`data` 只能含活动字段键，写入前服务端完成类型和字段权限校验。

示例：

```json
{
  "customer_name": "张先生",
  "phone": "13800000000",
  "requirement": "需要期刊推广服务",
  "stage": "QUOTED",
  "next_followup_at": "2026-08-23T01:00:00Z",
  "expected_amount": "50000.00"
}
```

### 6.2 `record_activities`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `tenant_id` / `record_id` | uuid | 主键与边界 |
| `activity_type` | enum | `CALL` / `MESSAGE` / `MEETING` / `NOTE` / `STATUS_CHANGE` / `SYSTEM` |
| `content` | text | 活动内容 |
| `result_key` | varchar(64) | 可空 |
| `next_action_at` | timestamptz | 可空 |
| `actor_member_id` | uuid | 可空 |
| `actor_integration_id` | uuid | 可空 |
| `metadata` | jsonb | 通话 ID、附件等受控数据 |
| `created_at` | timestamptz | 追加时间 |

业务活动默认不可编辑；如需纠正，追加“更正活动”并关联原活动。

### 6.3 `record_relations`

保存记录之间的可追溯关系，字段为 `from_record_id`、`to_record_id`、`relation_type` 和 `created_at`。MVP 关系类型受系统控制：`CONVERTED_TO`、`SOURCE_OF`、`DUPLICATE_OF`。

### 6.4 `record_conversions`

记录受控转换：来源记录、目标记录、转换类型、字段映射快照、操作者和幂等键。唯一约束 `(tenant_id, conversion_type, source_record_id)` 防止同一线索/跟单重复转换。

## 7. Dashboard 与集成

### 7.1 `dashboard_configs`

保存租户、适用角色、布局和组件配置。每个组件必须存储指标代码、对象、时间字段、过滤条件和展示方式；不接受任意 SQL。

### 7.2 `integrations`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `tenant_id` | uuid | 范围 |
| `provider` | enum | `FEISHU` / `PHONE_BOT` / `WEBHOOK` |
| `name` | varchar | 实例名称 |
| `status` | enum | `DRAFT` / `ACTIVE` / `ERROR` / `DISABLED` |
| `credentials_ref` | text | 密钥管理器引用，不存明文密钥 |
| `settings` | jsonb | 非秘密配置 |
| `last_success_at` / `last_error_at` | timestamptz | 健康状态 |

### 7.3 `external_identities`

把外部用户映射到 `tenant_member_id`，唯一键 `(integration_id, external_user_id)`。机器人权限判断必须先解析该映射，再复用普通授权服务。

### 7.4 `integration_events`

保存外部事件 ID、事件类型、接收时间、处理状态、重试次数和载荷摘要。外部事件 ID 在集成实例内唯一，用于幂等；原始敏感载荷按最短必要期限保存。

## 8. 文件、任务与审计

### 8.1 `files`

保存对象存储键、原始文件名、MIME、大小、哈希、上传者、病毒扫描状态和租户。业务 `data` 只引用 file id。

### 8.2 `import_jobs` / `export_jobs`

保存对象、文件、字段映射、过滤条件、状态、总数、成功数、失败数、错误文件和发起人。导入流程状态：`UPLOADED → VALIDATED → RUNNING → COMPLETED/PARTIAL/FAILED`。

### 8.3 `audit_logs`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | PK |
| `tenant_id` | uuid | 平台级动作可空 |
| `actor_type` / `actor_id` | enum + uuid | USER / MEMBER / INTEGRATION / SYSTEM |
| `action` | varchar | 稳定动作代码 |
| `resource_type` / `resource_id` | varchar + uuid | 目标资源 |
| `before` / `after` | jsonb | 敏感字段脱敏后的差异 |
| `reason` | text | 代管、权限等场景必填 |
| `request_id` / `ip` | varchar | 追踪信息 |
| `created_at` | timestamptz | 不可更新 |

## 9. 索引策略

必须索引：

- 所有租户表 `(tenant_id, id)`。
- `tenant_members (tenant_id, user_id)` 唯一。
- `tenant_invitations (tenant_id, target_phone)` 对 `status=PENDING` 建部分唯一索引。
- `verification_challenges (phone, purpose, created_at desc)`，并定期清理过期记录。
- `records (tenant_id, object_id, deleted_at, updated_at desc)`。
- `records (tenant_id, object_id, owner_member_id, deleted_at, updated_at desc)`。
- `records (tenant_id, object_id, status_key, deleted_at)`。
- `record_activities (tenant_id, record_id, created_at desc)`。
- `audit_logs (tenant_id, created_at desc)` 和 `(resource_type, resource_id)`。
- `records.data` 可建立通用 GIN 索引；高频 Dashboard 字段按配置建立受控表达式索引。

不允许平台管理员在页面输入任意索引表达式。索引变更通过受审查的迁移或后台任务执行。

## 10. 租户隔离与 RLS

服务端每个数据库事务设置不可由请求体覆盖的租户上下文。所有租户业务表启用并强制 RLS：

```sql
tenant_id = current_setting('app.tenant_id', true)::uuid
```

应用数据库角色不得是表所有者、超级用户或拥有 `BYPASSRLS`。平台跨租户统计使用单独、只读、审计严格的运维路径。

测试至少覆盖：

- 缺失租户上下文时默认拒绝。
- 使用其他租户记录 ID 查询、更新、删除和关联。
- 批量接口、导入、导出、Dashboard 和集成入口。
- 同一用户属于多个租户时上下文切换。

## 11. 数据生命周期

- 租户 `SUSPENDED`：禁止业务写入，管理员可按政策导出。
- 租户 `CLOSED`：进入保留期，之后由明确审批的清理任务删除。
- 成员停用：撤销会话，保留其历史身份和审计引用。
- 字段停用：不再显示或写入，历史 JSONB 值保留到迁移完成。
- 记录删除：进入回收状态；管理员可在保留期内恢复。
- 审计日志和转换关系采用更长保留策略，不跟随普通记录立即删除。
