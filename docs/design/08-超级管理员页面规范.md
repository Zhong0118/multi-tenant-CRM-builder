# CRM 平台超级管理员页面规范

> 角色：平台超级管理员  
> 核心职责：管理公司、模板、权限、集成、平台运行状态。  
> 原则：超级管理员不是企业日常业务员，因此默认不直接进入公司的获客、跟单、客户等业务数据。

---

# 1. 超级管理员信息架构

Sidebar 建议固定为：

```text
总览

公司管理

模板与表单

权限配置

Dashboard 配置

飞书集成

日志中心

系统设置
```

底部：

```text
收起菜单
退出登录
```

不建议加入：

- 客户管理
- 跟单管理
- 获客管理

这些属于公司工作空间。

如确实需要平台代管企业数据，应通过：

```text
公司详情 → 进入代管模式
```

并显示明显的代管状态。

# 3. 平台总览

## 3.1 目的

让超级管理员 30 秒内回答：

```text
平台有多少公司？
哪些公司正常？
今天有没有异常？
有没有待处理事项？
最近平台发生了什么？
```

不是企业销售 Dashboard。

---

## 3.2 页面结构

```text
平台总览                                [日期范围] [刷新]
多公司 CRM 平台运营情况与核心数据

公司总数   启用公司   活跃用户   今日新增记录

┌─────────────────────────────┐ ┌───────────────────┐
│ 公司概览                    │ │ 待处理事项        │
│ Table                       │ │                  │
└─────────────────────────────┘ └───────────────────┘

┌─────────────────────────────┐ ┌───────────────────┐
│ 平台数据趋势                │ │ 近期活动          │
│ Line                        │ │                  │
└─────────────────────────────┘ └───────────────────┘
```

---

## 3.3 KPI

只保留平台级指标：

1. 公司总数
2. 启用公司
3. 活跃用户
4. 今日新增业务记录

可选：

5. 今日 API 调用
6. 异常告警

第一版建议只显示前 4 个。

---

## 3.4 公司概览

只显示 5–8 家：

| 公司 | 管理员 | 员工数 | 启用模块 | 状态 | 最近更新 |
|---|---|---:|---|---|---|

右上：

```text
查看全部
```

---

## 3.5 待处理事项

包含：

```text
待审核公司
模块开通申请
权限申请
异常告警
```

每项：

```text
名称
说明
数量
>
```

---

## 3.6 近期活动

示例：

```text
ABC贸易 已通过开通审核
XYZ装修 开通了项目管理
DEF教育 更新管理员
GHI科技 数据同步异常
```

展示：

- Object
- Action
- Operator
- Relative time

# 15. 超级管理员页面统一视觉规则

1. 页面背景统一 `#F8FAFC`
2. 内容容器白色 + 1px Border
3. 不使用大面积 Shadow
4. Active Menu 使用浅蓝背景
5. 一个页面一个 Primary Button
6. 普通 Icon 保持单色
7. Status 才使用状态色
8. Table 优先于 Card Grid
9. 配置页面优先 Form / List
10. 详情优先 Drawer，复杂配置使用全页
11. 不使用 AI 卡通 Avatar
12. Dashboard 图表数量控制在 2–4 个
13. 平台总览不展示企业具体销售业绩
14. 超级管理员不直接拥有企业业务 Sidebar
15. 所有危险动作都放 More Menu 或 Detail 页面

# 16. 前端实现顺序

建议：

```text
1 AppShell
2 Sidebar
3 Header / UserMenu
4 PageHeader
5 DataTable / FilterBar
6 Drawer / Modal
7 平台总览
8 公司管理
9 公司详情
10 模板与表单
11 表单 Builder
12 权限
13 日志
14 飞书
15 Dashboard Builder
16 系统设置
```

先稳定 Shell 和公共组件，再做页面。

不要每完成一个页面就重新写 Sidebar / Header / Table。
