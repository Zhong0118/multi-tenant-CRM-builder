# 界面风格对比 · 第 01 轮（2026-10-20）

对比页：`style-explorer.html`（单文件，离线可开）。三个方向各三屏，共 9 屏，同一份示例内容（`data.mjs`），结构与样式各自单写。

## 用户任务

公司员工提出要「美化」。对现有界面的不满：侧边栏、表格、表格上方的筛选、详情抽屉（简洁但乱）、配置页，另有卡片样式、字号与位置、图标位置、间距、配色。不要求换 antd。参考：Attio / Linear / Twenty 与 shadcn/ui。

## 现状与问题（对着 2026-10-07 截图，`docs/audits/2026-10-06/frontend-polish/after/`）

- 侧栏：深蓝底加青绿，分组标题 12px，条目靠色块区分，和白色主区反差过大。
- 表格：antd 默认；每行名称都是同样加粗的青色链接；固定操作列压住最后一列。
- 筛选：「我的筛选」「应用筛选」「管理筛选视图」、搜索、下拉、更多筛选、更多操作排成两层，层级不清。
- 抽屉：员工、记录摘要、下一步跟进、活动历史各自一块不同粗细的框。
- 配置：说明文字多，步骤卡套卡片，字段账本和发布面板分开。

画面来自它们的公开演示页，不是登录后的真实应用，结论只用来取形、不当作规范。

## 三个方向

| | A 安静的表 | B 分组清单 | C 内嵌数据表 |
| --- | --- | --- | --- |
| 北极星 | 表格是主角，其余安静退后 | 把客户排成可扫读的清单 | 黑白灰加一个黑色主操作，颜色只留给状态 |
| 骨架 | 浅灰侧栏｜页头、视图标签、筛选行、无框表格 | 浅紫灰侧栏｜单行页头、按等级分组的清单 | 灰底侧栏｜内嵌圆角白色主区：标题、工具行、框内数据表、分页脚 |
| 字体 | DM Sans + 苹方；14/13px | Inter + 苹方；14/13px | Geist + 苹方；14/13px |
| 色彩 | 青绿 `#0E7C6B`（沿用品牌）、冷灰 | 靛蓝 `#5456D6` | 锌灰 + 黑 `#18181B`，状态才用红/琥珀 |
| 图标 | Phosphor Regular | Tabler 1.5px 描边 | Lucide 1.75px 描边 |
| 控件语法 | 8px 圆角、1px 描边、主按钮实心青绿 | 7–9px 圆角、分段控件、主按钮实心靛蓝 | 8px 圆角、虚线分面按钮、开关、黑色主按钮 |
| 等级的画法 | 彩色小标签 | 1–3 根柱 | 实心/半/空心圆加文字 |
| 详情 | 560px 右侧面板，无遮罩；标签页、属性清单 | 800px 两栏：正文与活动，右侧属性栏，含上/下一条 | 500px 侧滑面板带遮罩；标签页、两列字段、跟进卡片 |
| 配置 | 横幅提示待发布；字段账本含类型、必填、员工访问下拉、状态 | 左字段清单，右字段编辑面板（对应现有字段账本与字段抽屉） | 左子导航，右字段表：必填开关、员工访问下拉、状态徽标 |
| 放弃什么 | 彩色侧栏、装饰卡片、固定操作列 | 表头与竖线、彩色等级标签 | 彩色强调色、卡片阴影、渐变 |

## 差异检验

- 骨架：A 为「侧栏 + 页头 + 无框表」，B 为「侧栏 + 单行页头 + 分组清单」，C 为「内嵌圆角主区 + 框内数据表」；眯眼缩略图（`shots/compare-*/stitch.png`）里 B 没有表格网格，C 有明显的白色圆角外框和灰色背景。
- 字体、色彩、图标、等级画法三者各不相同。
- 说明：用户已点名四个参考，三个方向都留在这个范围内，不放保底的折中方案。

## 可读性与默认做法检查

- 正文 14px，辅助 13px，无小于 13px 的文字；行高 1.5，中文表格行 40–60px。
- 截图工具的「默认做法提示」九屏均无；C 的灰字对比度（原 4.40:1）已加深到 ≥ 4.5:1。
- 未做独立视觉评审（方向探索轮按规则交给用户先选）。

## 没做 / 假设

- 只有 1440×900 的静态主状态，无交互、无动效、无响应式；手机宽度、选中行批量操作条、空状态、错误状态都没做。
- 页面内容是示例：客户、电话、负责人是虚构的；字段、按钮和流程名称来自现有产品。
- B 的分组清单只能显示固定几列；现有产品的列是管理员可配置的（列设置），选 B 需要先决定「清单里放哪些字段」。
- 图标：Phosphor（MIT）、Tabler（MIT）、Lucide（ISC），来自 Iconify。字体：DM Sans、Inter、Geist（SIL OFL），来自 Fontsource。

## 第 02 轮（2026-10-20）：用户选择

反馈：喜欢 A 的色彩搭配和整体架构；导航栏和标签栏喜欢 C 的设计。

- 决定：以 A 为底（青绿 `#0E7C6B`、细线表格、右侧属性面板、横幅式配置页），侧边栏与标签栏取 C。
- 对「导航栏」的理解是左侧边栏；若指顶部面包屑栏，另行补。
- 取自 C：侧栏工作区块（名称加子域名，上下箭头）、32px 条目、选中仅浅灰底、数字徽标不用胶囊、底部账号块带角色；分段标签（灰色底槽加白色浮起的选中项）。
- 保持 A：配色、表格、筛选行、属性面板、横幅。
- 因导航取自 C，图标统一换成 Lucide（1.75px 描边），不在一个产品里混两套图标。
- 去掉了 A 里的侧栏搜索框：现有产品没有全局搜索，不画不存在的功能。
- 侧栏与主区之间保留 A 的 1px 分隔线：C 没有这条线，是因为它的主区是内嵌圆角面板，而不是整页铺满。
- 对比页：`style-explorer-r02.html`（D 三屏在前，A 原版三屏在后）；源文件 `d.mjs`、`d.css`。
- 检查：三屏的默认做法提示均无，无控制台错误。仍是 1440×900 静态主状态。

## 第 04 轮：批次 1 补充、批次 2（抽屉）、业务表图标（2026-10-21）

用户反馈：「我的筛选」收成「保存为视图」；操作列用方案 A；继续批次 2；白色圆角主区取自 shadcn；业务表图标要能改或提供选择。

### 已改

| 部分 | 改动 |
| --- | --- |
| 白色圆角主区 | 桌面端页面区是嵌在灰色外壳里的白色圆角面板（8px 边距、12px 圆角、1px 发丝边框、极轻阴影），侧栏与外壳同一灰色、不再有分隔线。窄屏仍整页铺满。按窗口高度计算的版面（记录列表、AI 助手）用 `--shell-inset-y` 扣除面板边距。**注意：第 02 轮的 D 稿没有画这个，是用户后来明确要求的。** |
| 操作列 | 去掉固定的宽操作列，改成每行一个「⋯」菜单：查看、编辑、领取、分配负责人、释放到公共池、删除。删除和释放仍先确认。无权限的项保留并写明原因（如「编辑（领取后可编辑）」）。手机卡片保留行内按钮。归属逻辑抽成 `useRecordOwnership`，行内按钮和菜单共用。 |

### 与第 02 轮 D 稿不一致的地方

- 抽屉没有用分段标签页。现有测试明确把「下一步跟进」「活动历史」放在摘要之下同屏可见（「安排跟进」是最常用的操作），塞进标签页会多一次点击。若仍想要标签页，只需把现有区块分组放进去，不影响数据。
- 图标：设计稿用的是 Lucide，真实产品仍用 antd 图标（业务表图标选择器也是 antd 图标），没有换整套图标库。
