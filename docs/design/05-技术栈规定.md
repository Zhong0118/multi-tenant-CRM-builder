# 技术栈规定

## 1. 架构结论

首期采用模块化单体（Modular Monolith）和单体仓库。Web、API、后台任务可以分别运行，但共享领域约定和一次发布版本；不拆微服务。

```text
pnpm monorepo
├── apps/web        Next.js Web 应用
├── apps/api        NestJS REST API
├── apps/worker     后台任务进程（可与 API 同代码包）
├── packages/contracts   OpenAPI 生成客户端/共享契约
├── packages/ui          平台主题与复合组件
├── packages/config      lint、tsconfig、测试配置
└── infrastructure       Compose、反向代理、迁移说明
```

## 2. 运行时与包管理

| 项目 | 规定 |
|---|---|
| 语言 | TypeScript，开启 `strict` |
| Node.js | 使用开发启动时仍受上游支持的 LTS；最低 20 |
| 包管理器 | pnpm，仓库锁定 `packageManager` |
| Monorepo | pnpm workspaces；只有需要任务缓存时再引入 Turborepo |
| 版本策略 | 初始化时锁定 major/minor 和 lockfile；升级单独提交并运行全套测试 |

不使用 `latest` 作为生产部署依赖。设计阶段只锁技术方向，实际创建项目时记录精确版本。

## 3. 前端

| 能力 | 选择 | 规定 |
|---|---|---|
| 框架 | Next.js 16 App Router | Web 页面、布局、路由与部署；不在 Next Route Handler 重复实现业务 API |
| UI | React 19 + Ant Design 6 | 使用 ConfigProvider 主题令牌和内部复合组件 |
| 数据表格 | Ant Design Table | 统一封装为 `RecordTable`；服务端分页、筛选和排序 |
| 数据请求 | TanStack Query | API 缓存、失效、重试和乐观更新；授权结果不做跨租户复用 |
| 表单 | React Hook Form + Zod | 静态表单；动态表单由字段定义生成 Zod/自有校验描述 |
| URL 状态 | Next Router/search params | 搜索、筛选、排序、分页和视图 |
| 图表 | Ant Design Charts 或 AntV G2Plot | 只实现文档定义的图表类型 |
| 日期 | Day.js | 显式时区转换，不在业务代码散落格式字符串 |

Next.js 官方当前推荐 App Router，且支持 Node/Docker 部署；Ant Design 面向企业级 Web 应用并提供 TypeScript 组件，符合高密度表格、表单、抽屉和选择器场景。参考：[Next.js App Router](https://nextjs.org/docs/app)、[Next.js 部署](https://nextjs.org/docs/app/getting-started/deploying)、[Ant Design React](https://ant.design/docs/react/introduce-cn/)。

### 3.1 前端边界

- Server Components 用于外壳和非交互初始内容；高交互 CRM 工作区使用明确的 Client Component 边界。
- 所有业务数据通过 NestJS API；Server Actions 仅可用于 Web 自身低风险操作，不形成第二套领域入口。
- 前端权限只控制体验，不作为安全边界。
- 不引入全局状态库保存可从 URL、Query cache 或组件状态推导的数据。
- 所有 API 类型从 OpenAPI 生成；禁止手写一份近似的重复接口类型。

### 3.2 为什么选择 Next.js + React

Next.js 是 React 的应用框架，不是与 React 并列的另一套前端。当前项目选择它的原因是：

- CRM 页面、API 契约和后端都使用 TypeScript，动态字段与权限类型更容易保持一致。
- App Router 提供布局、路由拆分和客户端导航；高交互表格仍可在清晰的 Client Component 范围内实现。
- React 生态同时覆盖 Ant Design、TanStack Query、表单、图表和数据表格。
- 团队已有 Vue/FastAPI 经验时，主要学习成本是 React 状态模型、Hook 和 NestJS 模块结构，而不是语言本身。

备选的 Vue 3 + FastAPI 仍是成熟方案：FastAPI 适合 Python 数据处理和 AI 服务较重的后端，Vue 对熟悉模板语法的团队上手更快。但本项目的主要复杂度在前后端共享契约、权限和元数据表单，首期统一 TypeScript 的维护收益更高。参考：[FastAPI Features](https://fastapi.tiangolo.com/features/)、[Vue TypeScript](https://vuejs.org/guide/typescript/composition-api)。

除非开发团队明确以 Python/Vue 为主，或 Python 领域任务成为核心工作负载，否则不在 Next.js/NestJS 与 Vue/FastAPI 之间混搭。

### 3.3 表格与样式策略

- 首期使用 Ant Design 作为唯一组件与样式体系，主题通过 Design Token 和少量 CSS Modules 实现。
- 不同时引入 MUI、Element Plus、shadcn/ui 或另一套全量组件库。
- Ant Design Table 只作为 `RecordTable` 模块的内部实现；业务页面不得直接散落列权限、分页和筛选逻辑。
- `RecordTable` 的接口接收字段定义、视图定义、权限结果和服务端查询状态，内部处理动态列、固定列、选择、空状态和详情抽屉。
- 首期不追求 Excel 区域复制、透视和多级分组。若这些需求成为付费核心能力，再评估 AG Grid；业务调用方不应因替换表格实现而修改。
- TanStack Table 属于无样式表格逻辑库，自由度高但需要自行实现大量交互，不作为首期默认方案。

## 4. 后端

| 能力 | 选择 | 规定 |
|---|---|---|
| 框架 | NestJS | 按业务模块拆分 Controller、Application Service、Domain、Repository |
| API | REST + OpenAPI | `/api/v1` 版本前缀；资源和显式业务动作并存 |
| 校验 | DTO + class-validator，动态字段使用统一 Field Engine | 服务端是最终校验者 |
| ORM | Prisma 7 + PostgreSQL adapter | 普通 CRUD 和迁移；RLS/复杂 JSONB 查询允许受控 raw SQL |
| 认证 | 手机验证码注册 + 密码登录 + 服务端会话 | Cookie 使用 HttpOnly/Secure/SameSite；集成使用独立凭据和作用域 |
| 后台任务 | BullMQ + Redis | 导入、导出、集成重试、通知；不在请求内处理大文件 |
| 日志 | Pino 结构化日志 | 自动加入 request_id、tenant_id、actor_id，敏感值脱敏 |

NestJS 官方要求 Node.js 20 或更高，并提供 Prisma 的 REST API 集成指南。参考：[NestJS First steps](https://docs.nestjs.com/first-steps)、[NestJS Prisma recipe](https://docs.nestjs.com/recipes/prisma)。

### 4.1 模块边界

```text
Auth
OnboardingInvitations
Tenancy
Members
Configuration
Authorization
Records
Activities
Conversions
Dashboards
ImportsExports
Integrations
Audit
FirstCompanyTemplate
```

- Controller 只处理协议转换、DTO 和响应，不写权限或 SQL。
- Application Service 编排事务和用例。
- Domain/Policy 定义权限、状态转换和指标口径。
- Repository 必须接收 `TenantContext`，禁止提供无租户的通用 `findById`。
- 首家公司模块只实现显式转换和指标，不复制通用记录 CRUD。

## 5. 数据与存储

| 能力 | 选择 | 规定 |
|---|---|---|
| 主数据库 | PostgreSQL 18 | 共享数据库、`tenant_id`、RLS、JSONB、事务 |
| 缓存/队列 | Redis | Session 辅助、BullMQ、短期幂等；不作为主数据源 |
| 对象存储 | S3 Compatible | 附件、导入源文件、错误文件、导出文件 |
| 迁移 | Prisma Migrate + 审核 SQL | RLS、索引和扩展使用显式 SQL 迁移 |

PostgreSQL 对 JSON/JSONB 提供原生查询能力，RLS 可以在正常查询和修改前按策略限制行；应用层过滤与 RLS 必须同时存在。参考：[PostgreSQL JSON](https://www.postgresql.org/docs/current/functions-json.html)、[PostgreSQL Row Security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。

### 5.1 数据库硬规则

- 应用连接角色不得拥有 `BYPASSRLS`，也不得作为业务表所有者运行。
- 每个业务事务在连接内设置 `SET LOCAL app.tenant_id`，事务结束自动清除。
- Repository 层统一处理软删除、租户范围和乐观锁。
- JSONB 写入必须经过字段定义校验；禁止原样保存任意请求对象。
- Dashboard 不执行用户提供的 SQL。
- 生产迁移先备份、再迁移、再验证；破坏性变更使用扩展-迁移-收缩流程。

## 6. API 规定

### 6.1 账号与邀请接口

```text
POST /api/v1/auth/verification-challenges
POST /api/v1/auth/register
POST /api/v1/auth/login
GET  /api/v1/me/invitations
POST /api/v1/invitations/:id/accept
POST /api/v1/invitations/:id/decline
```

验证码发送接口始终返回中性结果；接受邀请从当前登录 User 读取已验证手机号，不接受请求体传入另一个手机号代替。

### 6.2 资源接口

```text
GET    /api/v1/objects/:objectCode/records
POST   /api/v1/objects/:objectCode/records
GET    /api/v1/objects/:objectCode/records/:id
PATCH  /api/v1/objects/:objectCode/records/:id
POST   /api/v1/objects/:objectCode/records/:id/activities
```

### 6.3 领域动作

```text
POST /api/v1/leads/:id/review
POST /api/v1/leads/:id/convert-to-opportunity
POST /api/v1/opportunities/:id/convert-to-customer
POST /api/v1/records/bulk-assign
```

- 转换和集成写入支持 `Idempotency-Key`。
- 分页使用稳定游标或受控 offset；MVP UI 可显示页码，API 不返回无限全量。
- 错误遵循统一结构：`code`、`message`、`fieldErrors`、`requestId`。
- PATCH 请求携带版本号或 `If-Match`；冲突返回 409。
- API 从认证上下文取租户，忽略或拒绝普通客户端提供的 `tenant_id`。

## 7. 认证、授权与安全

- 注册使用手机号验证码；验证通过并设置密码后才创建可登录 User，注册本身不创建租户。
- 没有活动 TenantMember 的用户只获得 onboarding 作用域，不能建立租户数据库上下文。
- 租户管理员通过邀请模块添加员工；接受邀请时必须以当前 User 的已验证手机号匹配邀请目标。
- 短信发送通过 `VerificationSender` 接口接入实际供应商，业务模块只依赖发送结果，不依赖供应商 SDK。
- Web 使用短时会话与可撤销刷新机制，Cookie 设置 HttpOnly、Secure、SameSite。
- 所有状态变更防 CSRF；登录和重置密码防暴力尝试及账号枚举。
- 密码使用 Argon2id 或平台安全库的当前推荐参数。
- 验证码和邀请码只保存哈希，具有过期时间、尝试次数、一次性消费和发送限流。
- 集成密钥存入密钥管理器或部署环境 Secret，不进入数据库 JSON、日志或 Git。
- 飞书/电话 Bot 回调必须验签、校验时间窗、去重并限制载荷大小。
- 导出文件使用一次性/短时签名 URL，并记录下载审计。
- 输入富文本如后续启用，必须服务端清洗；MVP 默认纯文本。
- 安全响应头、CSP、依赖漏洞扫描和 Secret 扫描纳入 CI。

## 8. 测试规定

| 层级 | 工具 | 必测内容 |
|---|---|---|
| 前端单元/组件 | Vitest + Testing Library | 动态字段、权限表现、筛选 URL、错误和空状态 |
| 后端单元 | Jest | Policy、Field Engine、状态机、指标和字段映射 |
| 数据集成 | Jest + 临时 PostgreSQL | RLS、事务、JSONB、迁移、幂等与乐观锁 |
| 端到端 | Playwright | 三角色核心流程、跨租户攻击、转换与导入 |
| 契约 | OpenAPI schema check | 前后端生成类型及错误结构 |
| 视觉 | Playwright screenshots | 关键视口、抽屉、表格、设计器与权限状态 |

禁止使用 SQLite 替代 PostgreSQL 运行租户隔离与 JSONB 集成测试。

## 9. 代码质量与 CI

- ESLint + Prettier；TypeScript `strict`；禁止未说明的 `any`。
- 提交必须通过：格式、lint、类型、单元、集成、构建和数据库迁移检查。
- PR 中自动生成/比较 OpenAPI，破坏性接口变更必须显式说明。
- 数据库 Schema、RLS Policy 和权限矩阵都要有测试覆盖。
- 主分支镜像使用不可变 commit SHA 标签，保留回滚版本。

## 10. 部署拓扑

### 10.1 首期

```text
Internet
   │
Caddy/Nginx（TLS、限流、反向代理）
   ├── web: Next.js
   └── api: NestJS
          ├── worker
          ├── PostgreSQL
          ├── Redis
          └── S3 Compatible Storage
```

单机 Docker Compose 可用于试点和低风险首期，但数据库与附件必须做异机/异地备份。Web/API/Worker 使用独立容器和健康检查。

### 10.2 扩展触发条件

- API 或 Worker 资源争用：先拆进程和水平扩容，不先拆业务微服务。
- 数据库成为瓶颈：先优化索引、查询、连接池和只读报表，再考虑读副本。
- 单租户出现合规物理隔离要求：增加专属数据库部署模式，不改变上层租户契约。

## 11. 环境与配置

- 环境：local、test、staging、production。
- 配置通过环境变量/Secret 注入，启动时验证必填项和格式。
- staging 使用脱敏或合成数据，不复制生产客户数据。
- 每个环境使用独立数据库、Redis、对象存储桶和集成凭据。
- Feature Flag 只用于渐进发布，不替代长期产品配置。

## 12. 明确禁止

- 业务 Controller 直接调用 Prisma 或拼 raw SQL。
- 依赖前端传入租户 ID 或角色判断授权。
- 用“管理员接口”跳过字段校验和审计。
- 将飞书表格作为主数据库并双向无冲突同步。
- 在 JSONB 内保存密码、访问令牌或附件二进制。
- 将首家公司名称/ID写入通用模块条件分支。
- 为了首期而引入 Kubernetes、Kafka、GraphQL 或服务网格。
