# CRM 平台页面设计规范 V3（Final）

> **状态：唯一有效版本 / Canonical Page Design Specification**  
> **适用范围：平台超级管理员、公司管理员、公司员工、登录/注册/邀请/工作空间等公共页面。**  
> **依赖规范：`04-交互与样式约束-v3-final.md`。若本文件与交互/样式规范在尺寸、颜色、组件行为上冲突，以 04 文档为准。**  
> 本文件定义“页面如何组织、有哪些页面类型、不同角色如何进入页面、各类页面的结构模式与代表性页面”。  
> 具体某个角色的完整页面清单和每页业务字段，放在对应角色页面规范中维护。

- 哪些页面必须使用 Drawer，哪些必须使用全页；

# 1. 页面设计总原则

## 1.1 三层架构

所有页面统一拆成三层：

```text
A. Global Shell
   ├── Sidebar
   ├── Top Header
   ├── Global Search
   ├── Notification
   └── User Menu

B. Page Pattern
   ├── Dashboard
   ├── List
   ├── Detail
   ├── Config
   ├── Builder
   ├── Audit
   └── Wizard

C. Business Content
   ├── 公司
   ├── 获客
   ├── 跟单
   ├── 客户
   ├── 期刊
   ├── 员工
   ├── 统计
   └── 集成
```

开发原则：

```text
Global Shell 只实现一次
Page Pattern 抽成公共页面骨架
业务页面只注入数据、权限和配置
```

禁止：

```text
每开发一个页面
重新写 Sidebar
重新写 Header
重新写 Table
重新写 Drawer
```



```text

```

```text

```

而内部实现仍可称：


# 3. 用户角色与页面边界

## 3.1 平台超级管理员

核心职责：

- 管理所有公司；
- 新增/停用公司；
- 管理公司管理员；
- 配置公司启用模块；
- 管理模板与表单；
- 管理平台级权限规则；
- 配置 Dashboard 模板；
- 管理飞书集成；
- 查看全平台日志；
- 配置平台设置。

默认不直接进入：

```text
获客
跟单
客户
期刊
```

等企业日常业务。

如需协助客户处理问题，通过：

```text
公司详情
↓
进入代管模式
```

进入公司工作空间。

---

## 3.2 公司管理员

核心职责：

- 查看本公司全部业务数据；
- 管理员工；
- 查看 Dashboard；
- 查看/导出统计；
- 使用平台允许开放给公司的配置能力；
- 管理本公司飞书/业务配置（若授权）。

数据范围默认：

```text
ALL（仅本公司）
```

---

## 3.3 公司员工

核心职责：

- 完成自己的工作；
- 查看自己负责的数据；
- 新增业务记录；
- 修改授权字段；
- 新增跟进/活动。

数据范围默认：

```text
OWN
```

员工页面名称优先：

```text
我的获客
我的跟单
我的客户
```

而不是伪装成“全部数据”。

# 7. Page Pattern：Dashboard

适用于：

- 平台总览；
- 公司管理员首页；
- 数据统计页。

标准：

```text
Page Header
Date / Scope Filter
────────────────────────────────────
KPI        KPI        KPI        KPI
────────────────────────────────────
Primary Chart                Tasks
────────────────────────────────────
Secondary Chart              Activity
────────────────────────────────────
Detail / Ranking Table
```

规则：

- KPI 第一屏最多 6 个，推荐 4 个；
- 每个 KPI 可下钻；
- 有口径说明；
- 有最近更新时间；
- Dashboard 首要作用是发现问题并继续处理；
- 不做卡片墙；
- 不堆装饰图表。

---

# 8. Page Pattern：List

适用于：

- 公司管理；
- 员工管理；
- 获客；
- 跟单；
- 客户；
- 期刊；
- 日志；
- 模板列表。

标准：

```text
Page Header                              Primary Action
Description / Update Time
────────────────────────────────────────────────────────
Search   Filter   Filter   More Filter             Reset
────────────────────────────────────────────────────────
Optional Summary / View Tabs
────────────────────────────────────────────────────────
Table
────────────────────────────────────────────────────────
Batch Action                              Pagination
```

规则：

1. CRUD 业务优先 List；
2. 单击 Row 打开 Drawer；
3. Row 中 Link / Checkbox / Button 阻止 Row Click；
4. 除非复杂配置，否则不切独立编辑页；
5. 搜索、筛选、排序、页码进入 URL；
6. 浏览器返回后恢复上下文。

---

# 9. Page Pattern：Detail

## 9.1 轻量业务详情

优先：

```text
List + Right Drawer
```

适用：

- 跟单；
- 客户；
- 获客；
- 员工；
- 日志事件。

---

## 9.2 Full Detail Page

适用：

- 公司详情；
- 模板详情；
- 复杂用户配置；
- 系统级对象。

结构：

```text
Page Header
Object Summary + Actions
Tabs
──────────────────────────────────────
Main Information / Form
Side Activity / System Tips
```

# 11. Page Pattern：Builder

适用于：

- 表单设计器；
- Dashboard Builder。

标准：

```text
Page Header                     Preview  Save  Publish
─────────────────────────────────────────────────────────
Library / Tree     Canvas / Main Workspace     Properties
```

推荐布局：

```text
240px | minmax(560px, 1fr) | 320px
```

Builder 与普通业务 List 页面不共用布局。

---

# 12. Page Pattern：Audit

适用于：

- 平台日志；
- 公司审计；
- 飞书事件；
- 安全日志。

标准：

```text
Page Header
Filter Bar
Summary
Tabs
────────────────────────────────────────────────────────
Log Table                           Event Detail / Drawer
```

Detail 可以：

- 固定右栏；
- 或点击 Row 打开 Drawer。

---

# 13. Page Pattern：Wizard

V1 的“创建租户 / 导入向导”保留，并统一成 Wizard Pattern。

适用于：

- 新增公司；
- Excel 导入；
- 初始模板安装；
- 复杂集成初始化。

标准：

```text
Step 1 ── Step 2 ── Step 3 ── Step 4

Title
Description

Step Content

Back                              Continue
```

规则：

- 每一步可返回；
- 返回不丢输入；
- 最终一步展示 Summary；
- 提交后有 Progress / Result；
- 失败保留草稿；
- 可重试失败步骤。

# 41. Canonical Rule

从本版本开始：

```text
06-页面设计-v3-final.md
```

是页面架构与 Page Pattern 的唯一有效版本。

旧版本：

```text
页面设计-v1.md
页面设计-v2.md
```

进入：

```text
archive/
```

若未来调整：

```text
V3.1
V3.2
V4
```

禁止同时维护多个互相冲突的“当前版本”。

所有开发 Prompt 建议附加：

> 页面结构以 `06-页面设计-v3-final.md` 为唯一依据；UI Token、尺寸、颜色和组件交互以 `04-交互与样式约束-v3-final.md` 为最高优先级。
