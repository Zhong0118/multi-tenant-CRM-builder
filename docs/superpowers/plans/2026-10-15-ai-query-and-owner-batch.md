# AI 查询与批量负责人修复计划

需求依据：用户确认本地修复查询参数、错误反馈、最终答案、对话样式、成功失败状态、耗时、重试，并把批量分配负责人上限提高至 1000。允许当前 AI 服务只读验证刘洋的问题，不同步服务器。

## 全局约束

- 保留现有成员字段权限与分页改动，保留未跟踪的 docs/user-guide；不提交、推送或部署。
- 不改变业务记录、权限与 AI 写操作确认机制。复用现有 SDK、样式与图标。
- 负责人批量操作 1000；普通字段批量编辑仍为 100。翻页清空选择保持不变。
- 根因证据：docs/audits/2026-10-15/ai-query-diagnosis.md；.local/ai-query-qa/trace.json。
- 当前分支 codex/member-field-access，上一轮尚未提交；本轮继续同一工作区以保留本地可测集成状态。

### Task 1: AI 后端查询与最终答案

范围 apps/api/src/modules/ai、packages/contracts/src/ai/stream.ts（必要的兼容可选字段）；不改生成的 OpenAPI。

- 先补回归测试：真实模型曾生成 filters.stage="lost"，后端要求 ["lost"]；错误不能统一伪装为数据服务故障。选择最小的通用修复，保证任意表和可见字段都受原有权限、筛选校验约束。
- 给模型明确过滤格式及纠正提示，安全区分参数错误、访问限制、预算与服务不可用，禁止泄露异常堆栈和不可见字段。
- 预留有界的无工具最终总结步骤，禁止工具调用耗尽后直接把过程文本当完成；模型最终回答必须使用实际值、单位/字段口径，不能只给链接，也不能用少量搜索结果冒充完整合计。
- 工具摘要增加 startedAt?: string、durationMs?: number、errorCode?: string；detail 为可安全显示的错误或查询结果描述。旧历史兼容。耗时包含失败和被预算拒绝的调用。
- 总轮耗时前端可用消息 createdAt/completedAt；必要时为 terminal SSE 添加可选 durationMs，说明接口。
- 保留取消、超时、工具预算、提案确认和幂等行为。测试 provider、wrapper、工具与 orchestrator 相关路径，typecheck。
- 不调用真实 provider（由主 agent 最后统一一次联调）；报告准确改动/测试/限制。

### Task 2: AI 对话可观察性和重试

范围 apps/web/src/features/ai。先读取 Task 1 报告中的最终接口。

- 工具进行中/成功/失败明确显示图标及文字，混合结果分别计数；不再把全失败称为已完成的查询。
- 显示工具耗时和整轮耗时；新流式消息持续计时，完成/失败/取消停止，历史兼容。
- 局部失败给出安全具体原因与重试入口，失败重试复用现有流程；不能隐式执行写提案或在进行中重复提交。
- 优化对话卡片、过程折叠、来源与最终内容层级，白黑蓝和现有开源图标，适度过渡与 reduced-motion，不引入新 UI 库。
- 覆盖混合/全失败、重试、耗时停止、历史与流式结果等测试；保持现有断流恢复和提案交互。

### Task 3: 批量负责人 1000

范围负责人相关 DTO/service、records UI及测试；不改其他成员权限实现。

- 现有负责人批量操作为前端逐条调用 ownership 接口，无独立批量 DTO；将前端允许量统一到 1000并在 Drawer 验证；普通字段编辑仍最多100，不新增批量后端接口。
- 选择20行就是20条，1000为最大操作量，与每页容量不强制绑定。
- 测试1000可处理、1001拒绝与普通编辑100限制不变；保留逐条权限、版本校验与失败项重试，不重放已成功项。
