# 通用公海本地使用说明

本次仅在本地开发和验收，没有同步 GitHub 或服务器。

## 开启与配置

1. 公司管理员进入需要使用公海的业务表，打开「公共池设置」。
2. 开启公共池及「分阶段流转」。每张表独立设置，不影响其他业务表。
3. 联系期限默认 24 小时，跟进期限默认 720 小时（30 天），管理员可以修改。名称也可以改成客户、渠道等实际业务用语。
4. 如果需要成交保护，选择实际的来源业务表和其已发布流程中的正式状态，例如订单的「已确认」或协议的「已签约」。具体记录还必须通过现有「关联记录」建立关系。普通文本列写“已成交”不会触发保护。
5. 保存即生效，不需要再次发布业务表。改变期限只影响后续事件，不修改原有截止时间。

设置窗口显示旧未指定、旧公共池、旧已分配和已到期数量，以及当前员工权限。启用功能不会自动改变原有权限或归类旧记录。

## 五个阶段

| 阶段 | 负责人 | 下一步 |
| --- | --- | --- |
| 初始公共池 | 无 | 员工领取，或管理员分配 |
| 已联系公共池 | 无 | 再次领取，重新确认联系 |
| 待联系 | 当前成员 | 24 小时内确认建立联系；超时回原池 |
| 跟进私域 | 当前成员 | 新增有效跟进，重新获得 30 天；超时进入已联系公共池 |
| 保护私域 | 当前成员 | 正式业务依据触发保护，不自动回收 |

这些只是同一张表内的视图，不会复制记录，也不会增加四张业务表。员工私域视图默认展示本人记录；「全部记录」仍按已有读取权限显示。管理员可以查看全部并按负责人筛选。

## 旧数据和导入

- 旧记录保持原来的负责人和公海状态，新阶段为空。在「未归类旧记录」或全部记录中处理。
- 旧的未指定记录不会因此向员工公开。管理员明确选择归入哪个公共池，或者分配负责人后，才进入新流程。
- 启用新流程后，新导入可以确认进入初始公共池，或指定负责人进入待联系；两者不能同时选择。
- 「未指定负责人」筛选只查询负责人为空的记录，包括旧未指定和公共池记录，不会变更数据。

## 日常操作

- **领取**：从公共池领取，开始联系倒计时；两人同时领取只会有一人成功。
- **确认联系**：当前负责人或管理员确认已经建立联系，进入跟进阶段。
- **写跟进**：新增有内容的备注、通话、会面或消息活动可续期。修改普通字段、只建未来待办不会续期；过期后补写不能绕过回收。
- **释放**：填写原因，可标记丢单、空号或重复。公共池中的质量标记可供管理员筛选、清理。
- **分配/转交**：管理员指定有权限的活动成员。未成交记录开始新的联系期；已受保护记录保留保护。
- **成交保护**：关联来源记录达到已配置的正式状态后自动生效。若目标没有负责人，应先分配；若目标已经过期，应先重新处理归属。
- **依据作废**：还有其他有效依据时继续保护；最后依据失效时显示待复核，保留保护，由管理员决定是否解除并释放。

关闭公共池暂停领取、释放和自动回收，但记录与截止时间保留。重新开启会处理积压的到期记录，保存前应查看数量。已有新流程记录时不能降回旧模式，可直接关闭公共池。

## 推荐试用顺序

在专门的本地测试业务表中开启新流程，导入两三条测试数据，分别验证领取、确认联系、写跟进、释放、管理员转交。配置真实发布状态并关联一条测试订单，验证保护及撤销后的待复核提示。自动到期的时间边界、并发和权限场景由隔离数据库回归测试覆盖，不需要修改真实数据的时间来试验。
