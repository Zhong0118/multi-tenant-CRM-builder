# 组长对组员记录的独立列权限

**Goal:** 公司管理员逐表给组长设置组员记录的可编辑、只读、隐藏列；本人记录保持原权限。

**User-approved rule:** 只有明确设置为可编辑的组员列才新增修改能力，表级 canUpdate 为 false 时全部禁止修改。已有账号、业务记录、发布配置不自动修改。只在本地实现和验证，本轮不部署。

**Architecture:** 复用成员级业务表权限，新增可空的 groupFieldAccess 配置。权限在服务端根据当前组长身份、当前组成员和记录负责人解析，不能靠浏览器隐藏。配置缺省保持旧行为；一旦启用独立组员列配置，未指定的列按原可见性只读或隐藏，不自动新增可编辑列。普通字段编辑的新增授权不用于负责人变更、删除、工作流迁移、成交保护、附件或跟进管理。

**Tech Stack:** NestJS / Prisma / PostgreSQL / Next.js / React / Ant Design；不新增依赖。

## 对外契约

- MemberObjectAccessDto 追加可选 `groupFieldAccess?: Record<string, 'EDIT' | 'READ_ONLY' | 'HIDDEN'> | null`。以已发布 fieldKey 为键；对象整体替换，null 恢复原有列规则；省略时保留现有设置，避免旧客户端清空。仅公司管理员可设置，仅当前在职组长的 GROUP 查看范围可启用。未知、停用或未发布字段不接受，系统字段不可 EDIT。
- MemberObjectPolicyResponseDto 返回相同配置；MemberFieldAccessResponseDto 追加可选 `groupEffective`，用于展示组员记录的实际列权限。不设置独立配置时显示当前旧规则在组员记录上的实际结果。
- RuntimeObjectSchema 追加可选 `groupFieldAccess`（当前生效的组员字段规则）和 `queryFieldKeys`（混合范围下允许搜索/筛选/排序/聚合的字段）。`fields` 含至少一个记录范围可见的字段元数据，`access` 仍表示本人/普通范围；两边隐藏的字段不返回。
- RecordResponseDto 追加可选 `fieldAccess`（当前记录实际列权限）和 `canEditFields`（仅普通字段值修改能力）。旧客户端/旧响应均兼容；没有新增规则的对象不强制返回额外属性。
- 标题字段隐藏沿用既有“无法读取记录”语义：组员标题字段隐藏时不返回组员记录，而非暴露 title 字符串；本人记录不受影响。前端在该字段控件旁明确提示。

## 后端边界

1. 新增可空配置列，不回填业务或权限。成员权限变更与审计在现有事务和 roster 锁内执行。管理端需复核本人是否仍为管理员、目标是否仍为在职组长。
2. 尽量集中实现按记录负责人的字段权限选择。本人/公共池/未分配记录沿用原权限，只有同组其他成员名下记录才使用 groupFieldAccess；跨组、跨租户不受该配置授权。
3. 列表、详情、导出、编辑/批量编辑使用实际行权限；隐藏字段不出现在响应或 CSV 内容中。查询筛选、搜索、排序、聚合、仪表盘必须使用所查询记录范围共同可见的字段，避免通过数量或排序推断隐藏内容。不要把 UI 的列显示设置当成安全边界。
4. 字段编辑专用通道可在原 updateScope=OWN 时修改明确授予 EDIT 的组员列，但原 read/canRead/canUpdate 总开关仍生效。普通 UPDATE_RECORD 命令校验字段集合，混合允许/禁止字段应整条失败，不得部分写入。版本冲突保留。
5. 非字段操作仍用原修改范围，不能通过“有一个可编辑列”开放转移、删除、工作流确认、附件写入或跟进操作。自动化的来源字段映射、预览、历史与 AI 查询/操作缓存按当前记录权限裁剪；既有显式工作流/自动化角色授权不放宽。
6. 撤销组长、更换组员、成员停用、表停用、字段停用和权限收回后，后续请求按实时数据执行。所有响应需防止标题、关联、历史或缓存泄漏隐藏值。SQL 保护函数与 TS 边界一致。

## UI

- 保留员工默认；在组长 GROUP 表权限下，把“当前生效”明确为“本人记录”，增加“本组其他成员记录”一列。
- 增加“设置组员列权限”编辑入口，逐列选择可编辑/只读/隐藏，支持取消及保存反馈。保存后立即生效，无需发布；错误保留草稿。
- “可以修改记录”关闭时说明实际只读；标题隐藏和系统字段限制有明确说明。原“修改范围”标注为原记录操作范围，避免显示仅本人负责但暗示组员字段全部禁止。
- 组长查看/编辑记录时只渲染该行允许的字段；本人可写、组员只读/隐藏应在同一张列表和详情中正确区分。创建表单仍只使用本人权限。
- 使用现有 Ant Design、设计 token、过渡和 reduced-motion 约定；不新增设计系统。
