# 从 Excel / CSV 创建业务表草稿

用户已明确要求实现：上传文件，识别表头和字段类型，人工确认修改后创建，减少逐字段操作。使用 writing-plans / executing-plans 的检查与实施流程；后端独立接口任务可按 subagent-driven-development 委派。

## 设计与边界
- 新建业务表页面保留手工空表流程，增加“从 Excel / CSV 生成字段”。复用已交付的文件解析器、编码切换、工作表选择和限制，无新解析依赖/AI服务。
- 前端分析所选工作表整列非空值，生成列名、类型、样例、判断依据。手机号、编号、长数字、前导零数据保留文本；明确数字/日期/日期时间/是或否/邮箱可建议对应类型；混合/空列退回文本。
- 单选/多选依赖业务含义，符合状态/分类/标签等列名且有限枚举值时提供可采纳建议；默认文本，不强行设为枚举。手动选择单/多选时提取选项，可逐行编辑，最多100项、每项100字符，不能悄悄截断。
- 用户可修改列名、类型、必填、选项、包含/跳过列；系统生成稳定 col_1 等键；重复表头初始显示唯一名称并提示，后续原文件数据导入需核对映射。
- 标题字段由用户选择，只能是现有支持的文本/电话/邮箱/单选类型且必填。若没有适合字段，提示先把一列改为文本。其他字段不根据样例推断业务必填。
- 创建只写表结构草稿，不自动发布/导入数据。默认列表包含所选字段，员工权限关闭，创建后进入原设计器确认权限、发布，再用既有导入入口导入原文件。
- 创建 API 新增 initialFields（1–40个）与 titleFieldKey；一次事务保存业务表/字段/默认列表/默认关闭权限。复用现有字段配置校验，禁止成员/附件自动绑定，不新增迁移。无 initialFields 的原创建行为不变。
- 不修改服务器，不覆盖无关 docs/user-guide/。
