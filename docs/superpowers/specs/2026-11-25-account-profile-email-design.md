# 个人中心与邮件通知 · 第一期设计

审阅稿 · 2026-11-25 · 起点 `origin/main@e8fc2a5` · 分支 `codex/account-profile-email`

员工从侧栏头像进入个人中心。姓名、头像、邮箱和通知偏好跟账号走，职位跟公司走。手机号加密码仍是登录方式。邮箱用于验证、找回密码和收通知。

## 1　分两次交付

| PR | 员工可以做什么 | 平台与运维 |
| --- | --- | --- |
| 1 · 资料、邮箱、安全提醒 | 编辑资料和职位，管理头像、邮箱和登录设备，用已验证邮箱找回密码。账号安全页先提供新设备提醒开关 | SMTP、本地收信、发信队列、90 天清理、就绪状态、测试邮件、7 天统计。0063 发信基础、0064 邮箱验证和设备、0065 资料和头像 |
| 2 · 通知设置、每日摘要 | 在通知设置中选择接收哪些提醒。按公司当地时间收摘要，一键退订 | 在 API 的分钟任务里发现到期公司，复用 PR 1 发信。预计迁移 0066，开工前核对 |

## 2　个人中心长什么样

沿用 AccountShell 的顶栏、720px 内容区和设置页分区样式。平台管理员保留「管理中心」入口。全站用户菜单依次为个人资料、账号与安全、通知设置、切换工作空间（有多个时）、退出登录。PR 1 只挂载已交付的页面。PR 2 将新设备偏好放进通知设置，安全页给出直达链接，两处读写同一个值。

| PR 2 账号偏好 | users 增 digest_enabled（false）、digest_kinds（已知类别数组）、digest_subscription_version | 偏好只可本人修改。关闭、重新开通、邮箱更换均使旧退订令牌失效；取消订阅只改摘要。无须为每家公司复制一份偏好 |

**迁移前只取计数。** 有权限的运维在目标库运行下列查询。规格阶段未查询生产；PR 1 说明记录库环境、日期、非空数、空白数、冲突组数，部署前再核对。不导出任何地址。

~~~sql
SELECT count(*) FILTER (WHERE email IS NOT NULL) AS nonnull,
       count(*) FILTER (WHERE email IS NOT NULL AND trim(email) = '') AS blank
FROM users;

SELECT count(*) AS duplicate_groups FROM (
  SELECT lower(trim(email)) FROM users
  WHERE nullif(trim(email),'') IS NOT NULL
  GROUP BY lower(trim(email)) HAVING count(*) > 1
) duplicates;
~~~

空白转 NULL，其他历史地址保留且验证时间为空。有归一化重名时停止该次迁移，由运维核实归属，禁止自动合并账号。无冲突时规范化并建立数据库唯一性（规范化 CHECK 与唯一索引），并发绑定以数据库结果为准。上线后不推断历史地址已验证，绝不据此发通知或找回密码。

账号级数据通过已认证 userId 读写，匿名仅有受限找回与退订操作。成员资料单独返回公司内原始显示名，避免把仓储计算出的回退姓名误标成「管理员设置」。挑战、队列不开放业务表 CRUD；API 业务角色采用专用受限仓储/数据库授权。调度器跨公司只取得到期标识和任务，不获得全租户业务读取权；真正的摘要读取重建本人 TenantContext，走正常 RLS。平台统计接口仅聚合类别与结果，不能查询收件人、公司资料或正文。

## 4　账号接口与头像

以下均是拟增或扩充的接口，沿用现有 API 前缀、会话、同源写请求保护、错误格式和 OpenAPI 检查。

| 接口 | 规则 |
| --- | --- |

| PUT、DELETE /me/avatar；GET /users/:userId/avatar/:version | 上传/删除写账号审计。收到读取请求时鉴权，匿名 401，无共同有效公司 403，本人或平台管理员可读；已授权但版本不存在 404 |
| POST /me/email/challenges、POST /me/email/verify、DELETE /me/email | 登录态绑定/重新验证/换绑；挑战与用户、用途和目标绑定。换绑签发和最终提交均校验当前密码，解绑提交校验密码 |
| POST /auth/email/forgot-password、POST /auth/email/reset-password | 输入邮箱；完成时提交验证码、新密码和挑战标识。沿用已有密码策略、撤销会话逻辑。登录请求仍只接受手机号 |
| GET、PATCH /me/notification-settings | 账号级。PR 1 只支持新设备位；PR 2 增加摘要和类别。固定安全事件没有可写开关 |
| /platform/runtime-status、POST /platform/mail/test、GET /platform/mail/statistics | 平台管理员专用，测试接口无收件人参数，只发本人已验证且可投递邮箱。请求限频并记审计，统计按最近 7 天的发送结果、类别统计 |
| /mail/unsubscribe | PR 2，公开的随机令牌退订入口，见第 8 节 |

头像浏览器先限制原图 ≤2 MB，提供可键盘调整的方形裁剪与预览，压缩后 ≤300 KB。API 限制 multipart 大小、只取一个文件；按魔数加实际解码校验 JPEG、PNG、WebP，同时限制解码像素（例如 1600 万）、拒绝动画/多帧、损坏或伪装内容。用 sharp 将方向校正、裁成 256×256、重新编码为静态 WebP；不保留 EXIF、GPS 或其他元数据。API 将 sharp 声明为直接依赖，验证生产镜像能加载对应二进制。[sharp 输出文档](https://sharp.pixelplumbing.com/api-output/)

目录 `AVATARS_STORAGE_DIR/<userId>/<随机版本>.webp`，默认独立挂载 `/var/lib/crm/avatars`，权限限 API 账号，路径完全由服务端生成。先写同文件系统临时文件并原子改名，再事务更新版本及审计。图片服务只按数据库当前版本读取，客户端不可指定文件路径。按账号串行更新，提交后清理旧版本，失败清理新文件；重启清理超过宽限期且无 DB 引用的文件。多实例必须共享同一头像卷；数据库与头像卷配套备份。删除先清引用；服务器停止提供旧版本。响应使用 image/webp、nosniff 和 Cache-Control: private, max-age=3600。浏览器私有缓存一小时内可复用；离职后已缓存的副本最多再显示一小时。禁止共享缓存、代理缓存及 Next 图片优化。共同公司要求双方账号、双方成员及同一公司均有效。

## 5　验证码、找回与安全事件

1. 使用密码学随机数生成 6 位十进制码，保留前导零，有效 10 分钟。每次签发都用服务端独立生成的随机 UUID v4 挑战 ID 作盐，保存 `SHA-256(挑战 ID + ":" + 六位码)`，校验时常量时间比较。邮箱经 trim 和小写规范化后直接取 SHA-256，供挑战匹配和限流使用。手机号现有流程和存量挑战独立运行。
2. Redis 对规范化邮箱的摘要限 60 秒 1 次、滚动 1 小时 5 次，跨邮箱用途合计。账号跨所有目标 24 小时 10 次，来源 IP 1 小时 20 次，确认接口也按 IP/目标限频。并发不能突破额度。Redis 异常拒绝邮件验证码请求。认证失败次数与请求 IP 不同，换 IP 不重置 5 次机会。
3. 同一目标和用途的新挑战使旧码失效。重发时旧挑战与新挑战的替换须串行；较早发信的延迟响应不能重新激活被替代的码。先持久化挑战、同步 SMTP 发送；只有收到接受结果才激活，明确失败/结果未知即废弃，绝不入重试队列。事务内行锁检查当前邮箱版本、状态、有效期和次数，错误计数须提交，第 5 次锁死。成功消费、更新账号、审计和必要的通知入队在同一事务中完成。并发确认只允许一次成功。
4. 首次绑定/重验的验证邮件是唯一允许寄到待验证地址的业务邮件，其作用是证明收件权。换绑时旧地址保持有效直至新地址验证成功。提示地址不可使用即可，不给出占用账号。解绑清除绑定并关闭摘要；换绑使旧邮箱上下文和令牌失效。老地址通知只发给变更前已验证且未被标为无法投递的地址。
5. 邮箱找回只匹配启用账号当前已验证且可投递的地址。无匹配、账号停用、不可投递、单账号配额耗尽或 SMTP 拒绝，外部响应同一状态、结构和提示「如果这个邮箱已绑定账号，你会收到验证码」。返回同形随机挑战标识。地址/IP 的公开频率限制对已绑定、未知邮箱一致。匿名接口立即返回统一结果；账号匹配、存挑战、发信、收到 SMTP 接受后激活在进程内后台执行，验证码不会写入发送队列。期间进程重启会丢失这次申请，可重新申请。重置失败统一提示验证码无效或已过期。成功后撤销全部会话，密码修改保留当前会话；短信重置和邮箱重置都产生同类安全事件。
6. 新设备判断在成功登录事务里、插入新 Session 之前执行。串行化同账号的比较与记录。登录成功后写入不可预测的长期设备 Cookie（HttpOnly、Secure、SameSite=Lax、Path=/、有效期一年），服务器仅存随机值摘要与账号关联；它不能用于认证。带已知 Cookie 时直接视作已知设备，换 IP、切换 Wi-Fi 不触发。缺失或陌生 Cookie 时，用最近 90 天设备族（浏览器族＋系统族，忽略小版本）及可信代理来源的网段（IPv4 /24、IPv6 /64）兜底。首次建立基线；无可比较的设备数据不猜测。按账号维护 Cookie 到期时间及兜底指纹，退出不会删除基线。关闭提醒仍更新基线。
7. 账号姓名、头像、绑定/换绑/解绑、邮箱找回成功写 tenantId=NULL 的审计；职位事件写实际公司、操作者和目标成员。邮箱只记打码地址；密码、验证码、挑战摘要、退订串、原始邮件及附件内容均不进入审计。沿用现有密码路径审计，避免重复记一次操作。

## 6　发信配置与队列

发件身份固定为「百杰CRM <noreply@notice.baijiehub.com>」。线上绝对链接从配置的 WEB_ORIGIN 取 https://crm.baijiehub.com，忽略请求 Host 和用户提交的跳转地址。现有 WEB_ORIGIN 可以是列表，生产启动邮件模块时验证列表包含此源；开发用其中明确配置的本地源。模板全部保存在仓库，同一份安全转义的内容数据分别渲染 HTML 和纯文本。

| 环境变量 | 行为 |
| --- | --- |
| MAIL_PROVIDER | 空为关闭；生产启用 smtp。测试注入内存捕获器，开发用同一 SMTP 适配器接本机 Mailpit |

| MAIL_REPLY_TO | 可选，合法单地址；拒绝换行和额外头字段 |

头像路径由 AVATARS_STORAGE_DIR 控制，邮件链接复用现有 WEB_ORIGIN。

使用 Nodemailer SMTP；本地 Mailpit 捕获 MIME，自动化内存实现可模拟明确拒绝、连接中断及已接收。未配置/部分配置不会阻断应用或短信启动。运行状态返回就绪布尔值与缺失/无效的配置**名称**；业务端隐藏操作并显示未开通提示，直接请求邮件功能统一返回 503 MAIL_SERVICE_UNAVAILABLE。配置完整仅表示可尝试投递，测试邮件的 SMTP 结果另列。关闭期间不接收新邮件任务；账号密码和资料操作照常完成。恢复后过期摘要作废，先核对未过期待发项的资格。[SMTP 地址与端口](https://cloud.tencent.com/document/product/1288/65750) · [Nodemailer SMTP](https://nodemailer.com/smtp)

**队列不重复自动投递的边界。** 数据库能保证一个业务事件只入队一次。SMTP 接受邮件和数据库写回结果无法原子提交，Message-ID 相同也不能保证收件箱去重。选择优先防重复：若无法判断上次是否已被接收，标记「投递结果未知」，停止自动重发。代价是极少数邮件可能漏送。平台统计把未知单列，不算成功。[SMTP 对最终接收确认的说明](https://www.rfc-editor.org/rfc/rfc5321#section-4.5.3.2.6)

| 状态或节点 | 行为与重启处理 |
| --- | --- |
| 入队 pending | 密码、登录、邮箱变更用「类型＋不可变事件 ID」（登录用 sessionId）；摘要用 digest:<memberId>:<公司日期>。唯一键冲突忽略。保留去重行 90 天，任务不回放 90 天前事件 |
| claimed | API 每分钟用 FOR UPDATE SKIP LOCKED 领取一批到期项，写领取令牌和租约后提交，不跨 SMTP 持有数据库锁。此阶段只查资格、取资料、渲染。租约过期可重领 |
| sending | 真正调用 SMTP 前，持令牌以条件更新从 claimed 转为 sending 并提交。旧令牌不能发。给每次尝试设有界超时、稳定的 Message-ID；发送中的过期租约转 unknown，禁止另一实例接手重发 |
| sent | 收到 DATA 最终成功响应，凭令牌写 sent。不把收件方是否最终入箱计作可观测成功 |
| retry_wait | 明确未接收的临时错误（如提交前连接失败或明确 4xx）分别延迟 1、2、4、8、16 分钟；初次后最多重试 5 次。每次重建资格和正文，失败用允许列表错误码 |
| failed、unknown、skipped | 明确永久错误或重试耗尽记 failed；发送后掉线无法确定结果或 sending 时崩溃记 unknown；已退订、权限撤销、无内容、摘要已跨公司日期等记 skipped。三者都是终态 |
| 归档与统计 | 终态立即清除临时明文地址、领取数据等工作字段。发信记录保留去重与关联所需的最小标识、类别、打码地址、状态、错误码、时间及可用的服务商编号。每分钟任务分批清除超过 90 天记录；平台只读最近 7 天聚合（含验证码和测试信），重试不重复计成功或终态失败 |

SMTP 拒绝优先按原因分类。额度或频率限制无论 4xx 或 5xx 都按相同退避重试，耗尽记系统失败，不能写 email_undeliverable_at。只有明确指向收件箱不可投递的拒绝才能写 email_undeliverable_at，条件包含账号和目标邮箱版本；认证、发信域配置、模板或发件人错误只记系统失败。停止给该地址发通知及找回码，允许本人主动重新验证。旧地址快照仅保存在投递工作字段，所有终态原子清除，统计和审计只用打码地址；普通摘要与安全事件按版本从账号取地址，无须复制完整地址。任何操作日志只保留内部错误码及经过长度和字符白名单检查的厂商编号；关闭 SMTP 调试、信封/正文记录及 HTTP 敏感入参、查询串记录。安全、验证码及测试邮件都不附退订头。

## 7　每日摘要的权限和时间

1. 每分钟在 API 进程运行一次。按有效公司 timezone 将当前 UTC 时刻换算为当地日期和时间；本地 08:30（含）至 12:00（不含）发现当日尚无去重键的已开启成员，分页入队。多实例靠唯一键收敛。晚启动仅在上述时间窗补发，发送及每次重试均复核窗口，12:00 起作废当天待发摘要。日期采用公司日历而非固定 UTC 偏移；夏令时重复时刻仍只有一个键。两个公司的时区或名称相同也各发一封。
2. 任务只存 userId、tenantId、memberId、公司日期及地址版本。每次发前重新核对公司、账号、成员状态、邮箱验证与投递状态、订阅开关和类别。公司停用或关闭、成员离开、角色降级、换邮箱或退订，都按发送时的事实处理。
3. 沿用 NotificationsService 的 scopeParams、current_member_notifications、VISIBLE、READABLE、CAN_OPEN。将现有列表的共享筛选封装在通知模块内部，列表与摘要在普通成员事务中调用同一个入口。读取「还没处理」定义为视图内仍有效且 read_at IS NULL、resolved_at IS NULL 的提醒；生成摘要不修改已读状态。公司管理员的额度提醒由已有 QUOTA 条件筛出。
4. 当前列表的 toItem 给出提醒标题和记录号。邮件要显示业务记录标题时，仅对仍可打开的行走现有记录读取授权和字段投影，只取当前可见的主显示字段。隐藏标题只写允许显示的记录号或提醒类型；删除或已失去访问权的记录不贡献业务标题。对允许保留的公海收回通知沿用通用文案。非记录提醒用已有文案；不得用快照中的旧名称或直接读取 records.values 来补标题。
5. 对发送时实际可展示的提醒先过滤再算每类总数，按到期时间（空值在后）、创建时间、ID 稳定排列；每类最多 5 项。公司名称、标题、到期时间均转义，时间显示公司本地时间；无到期时间不伪造。超过五条显示「还有 N 条」，邮件标题的件数取过滤后总数。无事项记 skipped，次日重新判断。
6. HTML 和纯文本的工作台链接使用同一条授权路由。邮件不会提升权限。与业务事件写入同刻撤权的测试以最终发起 SMTP 前的一次已提交数据库快照为界；已经寄出的邮件不能撤回。

## 8　邮件与退订

统一模板宽度上限 600px，外表格宽 100%，CSS 内联；Outlook 给确定宽度，移动端留边。页头文字「百杰 CRM」，中文字体依次使用系统中文无衬线、微软雅黑、Arial、sans-serif。正文不依赖外部图片、脚本或字体。所有链接均为绝对地址。每封同时带 text/plain 和 text/html。

| 类别 | 标题样例 | 正文必须包含 |
| --- | --- | --- |
| 绑定、换绑、重新验证或找回验证码 | 百杰 CRM · 验证邮箱 / 找回密码 | 操作用途、正文中的 6 位码、10 分钟有效、非本人请求可忽略。主题、预览行和 URL 不含码 |
| 已登录修改密码 | 百杰 CRM · 账号密码已修改 | 时间、其他设备已退出、非本人操作请立即修改密码、账号安全入口 |
| SMS 或邮件重置密码 | 百杰 CRM · 账号密码已重置 | 时间、所有设备已退出、账号安全或找回入口 |
| 更换或解绑邮箱 | 百杰 CRM · 邮箱已更换 / 已解绑 | 发给原已验证邮箱、时间、操作类型、「如果不是你本人操作，请立即修改密码」。不暴露新地址 |
| 新设备登录 | 百杰 CRM · 新设备登录提醒 | 时间、简要设备类型、掩码网络信息、查看登录设备与撤销入口 |
| 每日摘要 | 云帆贸易 · 今天有 6 件事要处理 | 公司当地日期、按类别列事项与到期时间、溢出计数、「打开工作台」、「不再接收每日摘要」 |
| 平台测试 | 百杰 CRM · 测试邮件 | 测试时间、平台发信配置测试说明。无需附任何公司或员工数据 |

每封摘要用密码学随机数生成器取至少 32 字节，编码为 base64url 放进链接。数据库只存该令牌的 SHA-256，关联账号、邮箱版本、订阅版本和 30 天到期时间。重新开启订阅时切换订阅版本，后续邮件签发新令牌，旧版本的链接立即失效。处理 POST 时在同一事务内核对令牌摘要、到期时间和当前版本，再关闭订阅。访问日志省略令牌。邮件正文点击进入退订页，只显示「不再接收每日摘要」按钮，无需登录，员工点一次才 POST；GET/HEAD 或执行页面 JS 的安全扫描都不改变偏好。兼容邮件客户端的 List-Unsubscribe 使用同域 HTTPS 端点，另加 List-Unsubscribe-Post。合法 POST 只关闭该账号所有公司的每日摘要；重复点击得到已关闭提示。过期、篡改或重开订阅前的旧令牌不会关闭新订阅。[RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)
