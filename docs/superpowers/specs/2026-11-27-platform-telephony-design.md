# 平台电话外呼服务设计 · 统一线路、通话套餐、加量和收支

审阅稿，2026-11-27。基线为 PR #94（分支 `claude/telephony`，迁移 `0066_tenant_telephony` 尚未上线）。

现在的做法是每家公司自己填快马企业账号。改成和统一 AI 服务一样：平台买一个快马企业账号，所有公司共用这条线路；平台定通话套餐、给公司开通，按分钟加价转售。例如平台付给快马 100 元的通话，卖给公司 120 元。

已确认的决定：

- 计费方式：月度分钟套餐，另可加购分钟。
- 计费规则：每通按通话时长向上取整到分钟；未接通不计。
- 坐席：套餐里写明坐席数，超出不能再开。
- 建坐席：系统自动调用快马接口，公司管理员不填坐席号。
- 线路：只有平台线路，不保留公司自带账号。

## 1. 谁做什么

| 角色       | 能做的事                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 平台管理员 | 配置平台线路和进价；建、改、停用通话套餐；给公司分配套餐或设为「未开通」；给公司加当月分钟并记录收费；看每月收支             |
| 公司管理员 | 看本公司套餐、本月用量和坐席占用（不显示任何金额）；选择每张业务表里可拨打的字段；给成员填接听手机、打开外呼，系统自动建坐席 |
| 员工       | 在允许拨打的号码旁点电话图标拨号；看自己的通话记录                                                                           |

公司侧所有接口都不返回金额、进价和平台账号信息。

## 2. 数据

#94 的迁移 0066 还没上线，直接改写它，不另加迁移。金额一律以「元」存储：单价用 `numeric(10,4)`，套餐月费、加量收费用 `numeric(12,2)`。月份按公司时区取拨号时刻所在自然月的第一天，和 AI 用量一致。

| 表                                  | 字段和用途                                                                                                                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `telephony_platform_settings`（新） | 单例。线路模式 `MOCK` / `KUAIMA`；快马企业 ID；加密的企业密钥；加密的回调凭据；每分钟进价；每坐席每月进价；版本                                                |
| `telephony_plans`（新）             | 名称（唯一）、坐席数、每月分钟数、月售价、是否可分配、版本                                                                                                     |
| `tenant_telephony_configs`（新）    | `tenant_id` 主键，套餐（可空，空即「未开通」），版本。新公司默认未开通                                                                                         |
| `telephony_plan_history`（新）      | 只追加。公司、套餐（可空）、当时的套餐名、月售价、分钟数、坐席数、生效时间。分配套餐和修改套餐时写入，用来算每月收入                                           |
| `telephony_tenant_months`（新）     | (`tenant_id`, `month`) 主键。本月已用分钟、本月加量分钟、80% 和 100% 是否已通知                                                                                |
| `telephony_minute_additions`（新）  | 公司、月份、分钟数、收费金额、备注、幂等键、操作人、时间。同一个幂等键重复提交只加一次                                                                         |
| `telephony_settings`（改）          | 只保留可拨打字段 `phone_fields` 和版本。去掉公司级的开关、线路模式、企业账号、密钥和回调凭据                                                                   |
| `telephony_member_bindings`（改）   | 保留是否允许外呼、接听手机；`seat_id` 改由系统写入；新增快马坐席账号 `provider_username` 和建坐席时间 `seat_created_at`                                        |
| `telephony_calls`（改）             | 新增月份 `month`、计费分钟 `billed_minutes`（默认 0）、拨号时的每分钟进价 `cost_per_minute`。`provider_bind_id` 改为全局唯一：只有一个快马账号，话单号不会重复 |

平台表和公司表都开启并强制行级安全（RLS）：

- 平台表只有平台管理员可读写。判断平台管理员沿用 `ai_is_platform()`。
- 公司表按 `tenant_id` 隔离。公司成员可以读本公司的配置、月用量和已分配的套餐。
- 分配套餐、加分钟、记账、按话单号查公司，都走只做这一件事的 `SECURITY DEFINER` 函数，函数里先检查身份。
- 加量记录只有平台可读。公司只能从月用量里看到加了多少分钟。

## 3. 流程

### 3.1 平台配置线路

平台设置 → 电话线路：

- 选线路：「模拟」或「快马回拨」。正式环境不能选模拟。
- 填快马企业 ID 和企业密钥。密钥加密保存，保存后谁都看不到原文；留空表示不修改。
- 填每分钟进价和每坐席每月进价。
- 回调地址：点「生成」，显示一次 `POST {API_ORIGIN}/api/v1/telephony/hooks?token=…`，复制给快马客服配置；重新生成后旧地址立即失效。
- 页面显示线路状态和不可用的原因，例如「企业密钥未填」「服务器未开启真实外呼」，以及已建坐席总数。

服务器开关 `TELEPHONY_LIVE_ENABLED` 继续作为总闸，保留不变。密钥用 `AI_MODEL_KEYRING` 加密，附加数据为 `telephony` + `platform:字段名`。

### 3.2 套餐和开通

- 平台建套餐：名称、坐席数、每月分钟数、月售价。
- 修改套餐立即对所有使用它的公司生效，并给每家公司写一条套餐历史。
- 正在使用的套餐不能删除，只能设为「不可分配」。
- 坐席数不能改到低于任何一家使用它的公司当前已开的坐席数。保存时提示是哪几家公司超了。
- 平台在公司详情页给公司选套餐，或改为「未开通」。新套餐的坐席数少于这家公司已开坐席数时拒绝，提示先请公司管理员关掉几位成员。
- 开通后，公司设置页才出现「电话外呼」。

### 3.3 成员开外呼和自动建坐席

公司管理员给成员填接听手机、打开「允许外呼」后：

1. 检查坐席空位：本公司已开外呼的在职成员数，必须小于套餐坐席数。
2. 每位成员的快马坐席账号固定：`c` + 成员 ID 的 SHA-256 前 15 位十六进制，共 16 个字符。账号名的格式要求待快马确认。
3. 先用「获取坐席列表」按账号查：
   - 已经有了（上次建好但没保存成功），就直接用；
   - 没有，就调用「创建坐席」（昵称用成员姓名、手机用接听手机、密码随机生成且不保存），再查一次取回坐席号。
4. 已有坐席、只改了手机号：调用「更新坐席」。
5. 回到数据库重新检查坐席空位，然后保存。如果这时空位已被别人占了，坐席号照样存下，但外呼保持关闭，并提示坐席已满。
6. 快马返回失败时，原样显示快马给的原因，这位成员的外呼保持关闭。

关闭外呼不删除快马坐席，再打开时直接复用。快马能否删除或停用坐席、坐席是否收月租，待快马确认后再决定是否做「坐席回收」。

模拟线路下不调用快马，坐席号写 `MOCK-` 加坐席账号。平台从模拟切到快马后，这些模拟坐席按「未建」处理，成员要重新打开一次外呼才会建真实坐席。模拟线路只在非正式环境出现。

### 3.4 拨号

后端按下面的顺序检查，第一个不满足的就是返回给前端的原因：

| 检查                                 | 不满足时                                                    |
| ------------------------------------ | ----------------------------------------------------------- |
| 公司已开通（有套餐）                 | `NOT_ENABLED`：电话图标、拨号窗口、设置入口都不显示         |
| 平台线路就绪                         | `PLATFORM_NOT_READY`：「通话线路暂不可用，请联系管理员」    |
| 本月已用分钟 < 套餐分钟 + 本月加量   | `MINUTES_EXHAUSTED`：「本月通话分钟已用完，请联系管理员」   |
| 成员已开外呼并有坐席                 | `MEMBER_NOT_CONFIGURED`：「你还没有外呼坐席，请联系管理员」 |
| 号码在允许拨打的字段里、员工能看到它 | 沿用现有校验                                                |

原来的 `DISABLED`、`MOCK_FORBIDDEN`、`LIVE_DISABLED`、`PROVIDER_NOT_CONFIGURED`、`ENCRYPTION_UNAVAILABLE` 都并入 `PLATFORM_NOT_READY`。具体是哪一项没配好，只在平台的电话线路页显示。

都满足后，用平台的快马账号拨出，并在通话记录里写下当月月份和当时的每分钟进价。模拟线路直接记为已接通 30 秒，同样计 1 分钟，进价记 0，这样本地也能演练额度用满。不重复拨号、待核实、拨出 1 分钟后可以手动结束，这几项都和 #94 一样。

### 3.5 话单回来

回调地址只有一个：`POST /api/v1/telephony/hooks`，凭据放在 `?token=` 或 `Authorization: Bearer` 里。

1. 和平台回调凭据比对，不对返回 401。
2. 用话单号 `bind_id` 查出对应的公司。查不到返回 404，让快马按它的规则重推。
3. 按那家公司的身份处理：主叫、被叫、坐席号必须和拨号时一致，否则返回 403。之后的处理和 #94 相同。
4. 通话第一次变成「已接通」时，计费分钟 = 通话秒数除以 60 向上取整（61 秒计 2 分钟，0 秒计 0），同时加到这通电话所属月份的已用分钟上。「未接通」「已结束」「待核实」「线路拒绝」都计 0。
5. 结果确定后，同一条话单再推送、或之后再推录音，都不再改变计费。

用量要等话单回来才知道。如果最后剩 1 分钟时有几位成员同时在打，实际用量会超出额度。超出的部分照实记入，不另外扣费；平台在收支标签里能看到。每位成员同一时间只有一通电话，所以超出量最多是「同时在打的人数 × 每通时长」。

### 3.6 额度提醒

本月已用分钟达到额度的 80% 和 100% 时，给这家公司的所有管理员各发一次站内通知（新增通知类型 `TELEPHONY_MINUTES_80`、`TELEPHONY_MINUTES_100`）。做法和 AI 额度提醒一样：月用量行上的触发器判断，并标记已通知。每个月每一档只提醒一次，加了分钟以后再次越过也不重复提醒。

### 3.7 加分钟

在公司详情页填加多少分钟、收了多少钱、备注，只能加到当月。请求带幂等键，网络重发只加一次。写入审计日志 `telephony.minutes_added`。

### 3.8 收支

通话套餐页的「收支」标签，选月份，每家公司一行，最后一行合计：

| 列   | 怎么算                                                                        |
| ---- | ----------------------------------------------------------------------------- |
| 套餐 | 截至该月月底的最后一条套餐历史里的套餐名；未开通显示「—」                     |
| 分钟 | 该月计费分钟合计 / 额度                                                       |
| 收入 | 截至该月月底的最后一条套餐历史的月售价（未开通计 0）+ 该月加量收费合计        |
| 成本 | 每通的「计费分钟 × 拨号时的进价」之和 + 该月月底前已建坐席数 × 当前坐席月进价 |
| 毛利 | 收入 − 成本                                                                   |

坐席月进价没有按月保存，按当前值计算，页面上注明。模拟线路的通话进价记为 0。

## 4. 页面

### 平台

- 导航「AI 套餐」后面加「通话套餐」（`/platform/telephony-plans`）：套餐列表、新建、编辑、停用分配。布局和 AI 套餐页一致。
- 系统设置下加「电话线路」（`/platform/settings/telephony`）：见 3.1。
- 公司详情页（`/platform/tenants/[tenantId]`）加「通话服务」卡片：选套餐、本月用量（分钟、坐席）、加分钟、本公司加量记录。
- 收支放在通话套餐页的第二个标签「收支」，不单独占一个导航项。

### 公司管理员

设置 → 集成 → 电话外呼，改成三块：

1. **套餐和用量**：套餐名、本月已用 / 额度分钟、坐席已开 / 上限。只读，不显示金额。线路不可用时显示「平台线路未就绪」。
2. **可拨打的号码**：和现在一样。
3. **成员坐席**：只填接听手机和开关，不再填坐席号；显示坐席状态（未建、已建、建坐席失败及原因）。

原来的线路、企业账号、回调地址三项从公司页面去掉。

### 员工

- 拨号窗口、电话图标、记录页「通话」标签、「通话记录」页都不变。分钟用完时，电话图标变灰，提示原因。
- 公司被改回「未开通」后：电话图标和拨号入口隐藏，「通话记录」页和记录的「通话」标签只要有历史通话就继续显示，方便查看。

## 5. 接口

平台接口（要求平台管理员，沿用 `platform/*` 路由风格）：

| 方法和路径                                        | 用途                               |
| ------------------------------------------------- | ---------------------------------- |
| `GET` / `PATCH platform/telephony-settings`       | 读取和修改平台线路，不返回密钥原文 |
| `POST platform/telephony-settings/callback-token` | 生成回调地址，只返回这一次         |
| `GET` / `POST platform/telephony-plans`           | 列出和新建套餐                     |
| `PATCH` / `DELETE platform/telephony-plans/:id`   | 修改和删除套餐                     |
| `GET` / `PATCH platform/tenants/:id/telephony`    | 读取公司通话服务，分配套餐         |
| `POST platform/tenants/:id/telephony/minutes`     | 加分钟                             |
| `GET platform/telephony-report?month=YYYY-MM`     | 当月收支                           |

公司接口：沿用 #94 的 `workspaces/:tenantCode/telephony/*`。设置接口改为返回套餐和用量、只接受可拨打字段；成员接口负责建坐席；`runtime` 的不可用原因改成 3.4 里的四种。

回调：`POST telephony/hooks`。#94 的 `telephony/hooks/:tenantId` 从未上线，直接去掉。

## 6. 出错时

| 情况                           | 处理                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| 快马建坐席、改坐席失败         | 原样显示快马的原因，这位成员的外呼保持关闭                              |
| 快马拒绝拨号                   | 和 #94 一样，显示「线路拒绝」和快马给的原因，计 0 分钟                  |
| 平台没配好快马账号             | 公司页显示「平台线路未就绪」，员工无法拨号；平台线路页写明缺什么        |
| 话单一直没回来                 | 通话停在「待核实」或「已结束」，计 0 分钟。和快马账单的差额每月人工核对 |
| 平台改套餐与成员开外呼同时发生 | 两边都锁公司配置行，后完成的一方按新坐席数重新检查                      |
| 同一时刻两人抢最后一个坐席     | 第 3.3 节第 5 步的复查只放行一个，另一个提示坐席已满                    |

## 7. 测试和验证

后端端到端测试（真实 PostgreSQL，受限数据库角色）：

- 没开通的公司：拨号、成员建坐席接口都被拒绝，电话入口不显示。
- 坐席数等于套餐上限后，再开一位成员被拒绝；两个请求同时抢最后一个坐席，只成功一个。
- 改小套餐坐席数、给公司换小套餐：低于已开坐席数时被拒绝。
- 本月分钟用满后拨号返回 `MINUTES_EXHAUSTED`；加分钟后恢复。加分钟用同一幂等键提交两次，只加一次。
- 计费：61 秒计 2 分钟，60 秒计 1 分钟，未接通计 0；同一条话单推送两次只计一次；先推录音、后推话单，结果相同。
- 两家公司的话单都打到同一个回调地址，各自只记到自己头上；把 A 公司的话单号配上 B 公司的号码推送，返回 403。
- 达到 80% 和 100% 时各通知一次管理员，重复推送不重复通知。
- 收支：套餐月售价、加量收费、分钟成本、坐席成本按第 3.8 节算出的数与手算一致；月中换套餐按最后一个套餐计收入。
- 公司接口的返回里没有任何金额和平台账号字段；公司成员直接查平台表查不到数据。
- 快马的建坐席、查坐席、改坐席接口用测试替身，覆盖成功、失败、建好但没保存后重试这三种情况。

网页单元测试：平台套餐页、线路页、公司详情的通话服务卡片、收支标签；公司设置页的三块；四种不可用原因的提示文案。

本地演练：在本地假快马里加上建坐席、查坐席、改坐席接口，用独立数据库 `crm_telephony_review` 走一遍：

1. 平台配置线路、建套餐、开通星云科技；
2. 公司管理员给孙悦开外呼，自动建坐席；
3. 孙悦拨号，话单回来后计费；
4. 加分钟；
5. 查看收支。

## 8. 要补问快马客服的问题

补进 `docs/integrations/kuaima-vendor-questions.md`：

1. 发给我们的 appkey 和 appSecret，是否就是接口文档里的 `company_id` 和 `app_secret`？`company_id` 应该是数字。
