# 三角色核心闭环 UI 重构设计

> 日期：2026-08-30  
> 状态：待最终审阅  
> 适用范围：平台超级管理员、公司管理员、普通员工的核心业务闭环  
> 优先级：本设计与旧页面/样式规范冲突时，以本设计为准；旧文档仅作历史参考。

## 1. 背景

当前系统已经具备账号、邀请、公司工作空间、动态业务对象、字段、权限、发布快照、动态记录以及平台业务模板等核心能力，但页面实现存在以下问题：

- 新旧配色和视觉语言并存；
- 各业务模块重复编写页面容器、卡片、表格和状态样式；
- 平台端、公司管理端、员工端的页面层级和操作密度不一致；
- 部分导航仍指向占位页面；
- 表格、Drawer、Modal、空状态、错误状态和响应式行为缺少统一规则；
- 对象设计器能够工作，但字段、权限、预览和发布之间缺少清晰流程；
- 视觉层级偏“页面拼装”，尚未达到可以长期使用的业务工作台标准。

本次重构不重新设计后端模型，而是在现有权限、草稿、发布快照和模板应用机制上，建立一套真正可实施的 UI 架构。

## 2. 角色边界

### 2.1 平台超级管理员

负责：

- 管理公司生命周期；
- 创建和发布可复用业务模板；
- 使用模板为新公司批量初始化业务表草稿；
- 查看平台级运行状态。

平台超级管理员不负责企业日常数据录入。若以后增加代管配置，应通过独立的代管模式并保留审计记录。

### 2.2 公司管理员

负责：

- 创建公司专属业务表；
- 调整模板初始化出的表、字段和默认视图；
- 配置员工动作权限和数据范围；
- 检查变更并发布；
- 管理公司成员。

### 2.3 普通员工

负责：

- 使用已发布且已授权的业务表；
- 查看、新建和修改权限允许的记录；
- 只访问属于自己的工作入口和数据范围。

## 3. 目标与非目标

### 3.1 目标

1. 建立统一且可复用的设计令牌和页面骨架。
2. 打通并清晰表达三角色闭环：
   `公司初始化 → 公司管理员配置发布 → 员工使用业务表`。
3. 让高频数据操作保持紧凑，让说明和决策区域保持舒适。
4. 统一桌面、窄屏和移动端的布局降级方式。
5. 修复重构页面中发现的滚动、遮挡、溢出、错误反馈和状态同步问题。
6. 不使用假数据填满页面；没有真实数据时提供可执行的空状态。

### 3.2 非目标

- 不改变租户隔离、RLS、权限模型和发布快照机制；
- 不把百杰专属业务逻辑写入通用对象核心；
- 不在本轮实现日志中心、飞书集成、Dashboard 配置等占位功能；
- 不为了视觉效果增加无业务意义的图表、动画或大型指标卡；
- 不修改受保护的 `apps/web/src/app/(auth)/register/page.tsx`；
- 不进行全仓库测试扩张，本轮只做与改动对应的定向验证。

## 4. 视觉方向：B × C 混合工作台

核心原则是：**舒适地阅读，准确地操作。**

- 阅读与决策区域采用适量留白和柔和圆角；
- 按钮、输入框和导航保持适度亲和；
- 表格、字段设计器和分栏工具区使用直角或微圆角；
- 深色侧栏固定角色上下文，浅色内容区承载长时间工作；
- 主色用于可继续的动作，警示色仅用于等待、风险和发布确认。

### 4.1 颜色令牌

| 名称 | 值 | 用途 |
|---|---|---|
| Ink | `#17232D` | 深色侧栏 |
| Ink Hover | `#22313D` | 侧栏 Hover / Active 背景 |
| Page | `#F3F6F8` | 工作区背景 |
| Surface | `#FFFFFF` | 表格、表单、阅读面 |
| Border | `#D8E0E5` | 默认分隔线 |
| Border Strong | `#C8D2D9` | 强边界和输入框 |
| Text | `#17232D` | 主文本 |
| Text Secondary | `#687681` | 次级说明 |
| Work Teal | `#167568` | 主操作、完成、当前状态 |
| Teal Soft | `#E7F3F0` | 轻选中和成功背景 |
| Action Amber | `#C66C18` | 待处理、发布提醒 |
| Amber Soft | `#FFF3E5` | 风险说明背景 |
| Danger | `#B42318` | 删除、阻断和失败 |

不使用渐变、彩色阴影、玻璃拟态和无语义装饰色。

### 4.2 圆角层级

| 层级 | 圆角 | 组件 |
|---|---:|---|
| 阅读区域 | `10px` | 流程概览、任务说明、预览表单、引导面板 |
| 操作控件 | `6px` | Button、Input、Select、导航选中态 |
| 状态标签 | `4px` | 状态、权限、草稿标签 |
| 数据工具 | `0–2px` | Table、字段设计器、分栏工作区、批量工具栏 |

圆角不是装饰，而是帮助用户区分“需要理解的内容”和“需要连续操作的工具”。

### 4.3 字体与密度

- 中文正文优先使用系统中文无衬线字体；
- 英文和数字沿用 IBM Plex Sans；
- 编号、技术代码可使用 IBM Plex Mono；
- 页面标题 22–28px；
- 分区标题 15–17px；
- 正文 13–14px；
- 表格与辅助标签 11–13px；
- 常规表格行高 44–48px；
- 间距采用 `4 / 8 / 12 / 16 / 20 / 24 / 32` 级数。

## 5. 全局页面架构

### 5.1 AppShell

- 桌面展开侧栏宽度：224px；
- 桌面收起侧栏宽度：64px；
- 顶栏高度：56px；
- 整体高度：`100dvh`；
- Sidebar、Sidebar 导航区和右侧 Main 各自拥有清晰的滚动责任；
- 页面不得通过左右区域互相撑高；
- 顶栏固定，主内容独立滚动；
- 侧栏只显示当前角色真正可访问的页面。

平台端、公司管理端和员工端共享同一个 AppShell，只传入品牌、角色、导航分组和业务对象导航。

### 5.2 页面宽度

- 表格、设计器和数据工作区：使用全部可用宽度；
- 普通详情和表单：内容宽度不超过 960px；
- Dashboard 和混合布局：建议最大宽度 1280–1360px；
- 页面外边距在桌面为 24px，窄屏为 16px，移动端为 12px。

### 5.3 公共页面模式

实现并复用以下页面模式，而不是在每个业务模块重新拼装：

- `PageHeader`：标题、说明、状态和主要操作；
- `ProcessRail`：显示跨角色流程和当前步骤；
- `FilterBar`：搜索、筛选、视图和批量操作；
- `DataPanel`：表格和工具区的直角容器；
- `ReadingPanel`：说明、任务和预览的圆角容器；
- `StatusTag`：统一状态语言；
- `DetailDrawer`：桌面端记录详情；
- `EmptyState`：说明当前状态和下一步动作；
- `ErrorState`：说明发生位置、原因和恢复动作；
- `PublicationReview`：发布前变更摘要、阻断项和确认。

## 6. 三角色核心页面

### 6.1 平台超级管理员

核心页面：

1. 平台总览；
2. 公司列表；
3. 新增公司；
4. 公司详情；
5. 业务模板列表；
6. 模板设计器。

公司详情使用 `ProcessRail` 表达：

1. 公司已创建；
2. 初始化业务表；
3. 公司管理员完成配置并发布。

页面必须显示真实状态：管理员邀请、应用模板、创建的业务表草稿、公司是否具备激活条件。模板应用仍遵循现有后端约束，不在 UI 中伪造可追加或部分应用能力。

### 6.2 公司管理员

核心页面：

1. 管理工作台；
2. 成员列表与成员权限；
3. 业务表列表；
4. 对象设计器；
5. 发布检查。

对象设计器采用三栏工作区：

```text
业务表列表 | 字段 / 视图 / 权限配置 | 员工端实时预览
```

- 左栏负责切换和新增业务表；
- 中栏负责字段顺序、字段属性、默认视图和员工权限；
- 右栏展示员工实际可见表单或列表预览；
- 窄屏时右栏收进“预览”Drawer；
- 保存草稿和发布必须是两个不同动作；
- 有未保存变更时显示稳定提示；
- 发布前展示差异、阻断项和影响范围。

### 6.3 普通员工

核心页面：

1. 我的工作台；
2. 已授权业务表列表；
3. 记录列表；
4. 新建记录；
5. 记录详情和编辑。

记录工作区采用：

```text
筛选工具栏
记录表格 | 当前记录详情
```

- 桌面端点击行在右侧打开详情；
- 移动端点击行进入全屏详情；
- 员工只看到已发布且已授权的对象和字段；
- OWN 范围使用“我的数据”等用户语言，不暴露技术术语；
- 只读字段明确显示，只隐藏的字段不渲染也不下发；
- 新建和编辑动作由发布快照权限决定。

## 7. 交互规则

### 7.1 导航与滚动

- Sidebar 固定视口高度；
- 导航区域内部滚动；
- Sidebar 底部角色信息和退出操作固定；
- Main 独立滚动；
- 禁止页面同时出现无意义的多层纵向滚动条；
- Table 只在必要时横向滚动，主要列保持可见。

### 7.2 列表和详情

- 搜索与筛选集中在一个 FilterBar；
- 常用筛选直接展示，低频筛选进入“更多筛选”；
- 行点击打开详情，行内独立操作不得误触行点击；
- 批量操作只有选中数据后才出现；
- 筛选条件和分页在返回列表时保留。

### 7.3 草稿和发布

- 本地未保存、服务端草稿已保存、线上已发布是三个明确状态；
- 保存时只锁定相关按钮，不冻结整个页面；
- 离开含未保存变更的页面前提示；
- 发布必须先分析，再展示确认面板；
- 阻断项必须说明字段和修复方式；
- 发布成功后统一刷新线上状态和导航。

### 7.4 反馈

- 成功使用短 Toast，文案与动作一致；
- 表单错误显示在字段附近，摘要放在表单顶部；
- 模块加载失败在模块内恢复，不替换整页；
- 用户输入在失败后保留；
- 删除、归档、停用等高风险动作要求确认并解释影响。

## 8. 页面状态

每个核心页面至少覆盖：

- 首次加载；
- 有数据；
- 无数据；
- 局部请求失败；
- 权限不足；
- 提交中；
- 提交成功；
- 版本冲突；
- 窄屏布局。

加载使用局部 Skeleton。空状态必须说明为什么为空以及下一步动作。错误不得只显示“发生错误”。版本冲突应提示重新加载最新草稿，不自动覆盖他人修改。

## 9. 响应式与可访问性

- 桌面端优先，完整三栏设计器建议宽度不低于 1180px；
- 900–1180px：压缩侧栏并将预览放入 Drawer；
- 小于 768px：侧栏变为临时导航，详情使用全屏 Drawer；
- 表格移动端优先保留主字段、状态和下一步时间；
- 所有交互元素有可见键盘焦点；
- 图标按钮必须提供可访问名称；
- 色彩不是唯一状态信号；
- 支持 `prefers-reduced-motion`；
- 动画只用于 Drawer、状态切换和轻微反馈，时长控制在 120–180ms。

## 10. 工程落地

### 10.1 设计系统

- 在全局 CSS 中集中定义视觉令牌；
- Ant Design ConfigProvider 与 CSS 变量保持同源；
- 清理功能模块内的旧硬编码色值；
- 公共页面模式放入共享组件目录；
- 功能模块只负责业务内容和数据，不重新定义页面外壳。

### 10.2 数据流

- 服务端页面继续负责身份和工作空间上下文；
- 客户端查询与 mutation 沿用现有 API 和 TanStack Query；
- 任何指标、状态和表格内容必须来自真实接口或明确的本地草稿；
- 发布成功后刷新对象列表、运行时导航和当前对象状态；
- 权限仍由服务端裁决，前端隐藏入口只用于改善体验。

### 10.3 实施阶段

1. 统一令牌、AppShell 和公共页面模式；
2. 重构平台端公司与模板核心流程；
3. 重构公司管理员工作台、成员和对象设计器；
4. 重构员工工作台和记录工作区；
5. 统一状态、响应式和可访问性；
6. 使用 Playwright 检查三角色闭环并修复页面 Bug。

每个阶段必须可以独立运行，不允许长期保留一半新样式、一半旧样式的核心页面。

## 11. 验证策略

遵循“足够证明可用，不扩张测试”的原则：

- Web TypeScript 检查一次；
- 只运行受影响组件和页面的定向测试；
- 使用 Playwright 检查三条关键路径：
  1. 平台管理员查看公司并初始化业务表；
  2. 公司管理员修改对象并进入发布检查；
  3. 员工打开授权业务表并进入记录详情；
- 检查桌面 1280px、窄屏 900px 和移动端 390px；
- 检查侧栏和内容区独立滚动；
- 不默认运行全仓库测试或大规模 smoke。

## 12. 验收标准

1. 三种角色登录后能立刻理解自己能做什么；
2. 超级管理员能看清公司初始化进度和下一步；
3. 公司管理员能在一个工作区完成表、字段、权限、预览和发布；
4. 员工只看到被授权的业务对象和动作；
5. 核心页面使用同一套颜色、间距、状态和操作语言；
6. 表格与设计器保持工具密度，说明区域有足够留白；
7. 桌面和移动端不存在遮挡、双重滚动和关键操作不可达；
8. 空状态、加载、失败和版本冲突都有明确恢复路径；
9. 不通过假数据或未实现入口制造“看起来完成”；
10. 定向测试、Web 类型检查和三角色 Playwright 核心检查通过。
