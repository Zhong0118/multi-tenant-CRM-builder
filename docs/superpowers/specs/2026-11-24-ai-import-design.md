# AI 导入设计 · 第一轮审阅已采纳

销售打开现有「导入 Excel / CSV」抽屉。系统先用规则对列，销售只需处理剩余差异。销售能看到文件原值、将要写入的值、哪些行可导入，以及失败原因。在点「导入」之前，业务表中不会出现新记录。

**分支起点**　2026-11-24 fetch 后，origin/main 为 6ae8bef；阶段 A 的功能目录在 #89，阶段 B 最后一个迁移为 0061。按提前开始的约定，codex/ai-import 从包含二者代码的 codex/ai-sales-daily @ c827ec0 建立。实施时沿用 A 的目录和计量入口；B 合并后变基到最新 main，再核对迁移编号。拆为两个 PR。PR 1 只有规则、抽屉和按行归属，所有套餐都可使用，无数据库迁移；PR 2 接入 AI 和评测。第一批实现基于 #90 的最新提交，待 B 合并再变基。

## 1　从读文件到导入

1. 浏览器用现有 SheetJS 和 CSV 解码器读单张工作表。保留 10 MB、40 列、1 万数据行、公式错误、乱码和编码检查。保留原工作表行号、绝对列位置、空行和列间空洞的位置信息；CSV 保留解析器的原始行号语义，带换行的引号单元格仍是一条记录。用位置 C1…C40 标识列，同名表头也能分别修改。
2. 先在前十行按唯一匹配的字段数择优，再判断候选行是否有多个短文本单元格且下方呈数据形状；规则明确时自动选择并提示「已识别第 N 行为表头」。无法确定时保持默认并允许选源文件前 10 行中非空的一行。先保留最多十行前导区，再对表体校验列数和行数；标题行只有一格、首行为空亦可预览。超限明确报错，不能因解析器提前截取而当成完整工作表。原文件行号随选表头、切分批次和指定负责人保持稳定。
3. 自动做唯一匹配。保留未识别项，按列统计 N 个待处理列、M 个未对上的不同取值（按列累加）。有歧义的表头行、日期格式也可手动发起求助。纯规则完成时模型调用数为零。
4. 用户点击「AI 帮我对列」才生成一次建议。表头仍有歧义时，单次请求提供候选表头及其绑定的列位置与安全摘要，模型在同一个响应里给出表头行和该行的完整列方案。点击「改用第 N 行」同时应用对应方案；文件或草稿版本冲突则提示重新检查，不自动扣第二次额度。取消、超时和额度不足均保留手动映射。
5. 用户核对方案、负责人及查重字段，点击「检查数据」。界面汇总 READY、失败、重复和主动跳过的行。只有最近一次完整检查对应的计划可执行；文件、表头、映射、取值、格式、查重项或负责人变化使检查失效。关闭抽屉清除方案。并发返回以本次文件、工作表、请求序号和草稿版本核对，迟到的结果不能覆盖手工操作。

## 2　隐私、最小输入与权限

**接口**　POST /api/v1/workspaces/:tenantCode/objects/:objectCode/import-assist。独立只读预览服务，复用 filter-preview 的治理入口。先按当前身份检查 import_assist、已发布对象和 canImport。缺套餐或缺导入权返回 403；对象不可见沿用现有统一错误语义。重新从服务端计算 EDIT / CREATE_ONLY、可导入类型、有效选项；排除系统、隐藏、只读、成员字段。模型返回后再解析当前权限和发布版本，权限撤销拒绝返回，版本过期要求刷新。正式导入仍由 importRows 重新鉴权。

**管理员的手动对照范围。** 已发布的员工字段权限显式为 HIDDEN 或 READ_ONLY 时，该字段只参与人工导入。管理员打开 AI 导入抽屉仍可选它，选项标注「仅手动对照」。AI 模式的规则识别表头与自动对列时跳过这些字段。服务端用已发布的员工权限与操作者实际字段权限取交集，先剔除目标字段及选项，再按所有候选表头和手动映射剔除整条来源列。其名称、样例、取值和次数均不发往厂商。普通导入按已有业务权限检查并写入。

**表头投影。** 对规则已确定或员工选定的当前表头，保留业务文字，先遮盖个人标识再截到 40 个 Unicode 码点。其他候选行仅展示短标签，姓名、长句和数据单元格退为形状或空。负责人、受限字段和人工排除列按所有候选行的物理位置整列排除，此规则优先于表头投影。

**浏览器到服务端。** 单一工作表摘要，包括工作表名、当前表头行、前十行的有界投影、未解列的位置/表头、至多 5 个样例；低基数列（原始不同值 ≤50）携带未解值及其频数。规则已解、人工锁定、负责人、不可导入列只传位置/占位信息用于布局或占用检查，不传其样例；已定字段但仍有取值未解时，只求该字段的值对照。频数和唯一值在浏览器扫完整列，不能用前五行推断。高基数只送样例，不发送全量明细。各值以 Unicode 码点裁至 40 字；先打码再截短，避免截断使识别失效。前端先做同类清洗与预算裁剪，HTTP 请求体目标 ≤80 KiB；伪造超出协议硬上限的请求按现有输入错误处理。

**服务端到厂商。** 服务端重做规范化、分类、打码和预算裁剪，不信任浏览器的「安全」「已匹配」声明。最终只发白名单 JSON；字段只含本次短引用、显示名、类型、必填标记和有效选项的短引用/名称。原始字段键、成员名单、成员 ID、手机号对照表和业务记录均不进入模型。字段与选项短引用在本请求内回译。所有字符串入口（含工作表名、任一候选表头和选项名称）经过相同隐私处理。

| 输入风险 | 发往厂商的表示 |
| --- | --- |
| 手机、座机、邮箱、身份证、银行卡 | 先识别完整片段（含区号、常用分隔符、身份证末位 X、国际前缀），遮住中间部分。示例 138****5678、010-****5678、z***@qq.com。长数字同时命中多个类型取遮盖更多的一种；无法分类的长编号保留类型或掩码。相同掩码的原始值不能通过显示文字回填，按不透明的值 ID 区分。 |
| 负责人、跟进人、销售、业务员、归属，或手工标的负责人列 | 本地规则先标记，服务端从候选表头再次排除整列，连前十行投影、取值计数与样例也一起排除。可疑别名先请人指定。负责人不会成为 AI 可建议的目标。 |
| 与隐藏、只读、系统字段同名/同键的源列 | 服务端在租户权限边界内建立阻止外发清单。检查候选表头行时取被阻止列位置的并集，整列值和列名均不出站；碰撞时按受限处理。错误与丢弃说明不回显隐藏字段。 |
| 表头未确定、未知的自由文本、可能夹带姓名的说明行 | 前十行先传位置、空/非空、是否像文本/数字/日期等形状。只投影识别为表头的安全标签；其余正文、长备注、疑似人名列和无从判定归属的高敏内容退为类型或空占位。禁止把第一行整段标题或前十行原矩阵发出。必要时先人工选表头/排除敏感列，再请求建议。 |
| 短枚举、结构清楚的日期/数值、可识别的安全列 | 可传掩码后的值示例及未解枚举；过长/有明显敏感片段的自由文本仅给形状。完整原件、失败行 CSV 和字典回填留在浏览器。 |

隐藏字段的防线是隔离来源列，不能靠删除 JSON 中的目标字段列表实现。任意别名、粘进普通单元格的秘密无法仅靠正则识别；无法安全区分时隐藏该值，只做表头或手动对照。界面在点击前说明会发送哪些摘要；发送范围只列列名与样例数，按整列切换「不发送这一列」。开发与留出都在 provider 收包处校验哨兵，覆盖表头第 3 行、标题/备注夹杂敏感内容、隐列、负责人、不同取值列表和混合格式号码。

**总预算**　厂商输入含指令/字段字典以 UTF-8 JSON 字节计，目标 ≤48 KiB。先去重复样例，逐轮减少每列样例、压缩前十行到形状，再按整列减少枚举字典或目标候选；缺完整字典的列明确标为「仅部分建议，余项手动」。保留合法引用所需字典，绝不截半个 JSON 值。必要时只解决可容纳的一组，其余留待手动；没有安全且可求解的项直接返回规则结果、零调用。业务体积大不会令整个预览失败。使用现有 ModelMeter、额度预占、取消/超时结算和每人限流；用量、审计、错误、追踪都只记录功能、计数、耗时、状态，不记录文件内容和方案。

## 3　方案协议与应用

下列是预览契约的设计类型。field/option/value 均指本次请求提供的有限集合；返回浏览器时，服务端把合法引用翻译为当前可见的字段键、选项键和文件值 ID。前端用值 ID 在本地绑定原文。一个结果只属于当前工作表快照。

```ts
type Confidence = 'high' | 'review'
type Target = { mode: 'field' | 'append'; field: string } | { mode: 'skip' }
type ColumnAdvice = {
  col: string
  target: Target
  confidence: Confidence
  reason: string                 // 最多 20 个码点
  dateOrder?: 'DMY' | 'MDY'
  bareAmountUnit?: 'yuan' | 'wan'
  values?: { value: string; option: string | null; confidence: Confidence }[]
}
type ImportPlanV1 = {
  version: 1
  headerRow: number              // 1-based
  columns: ColumnAdvice[]
  matchFields: string[]          // 最多 3 个
}
```

响应另含服务端生成的 generatedAt、草稿版本、逐项提示；模型不输出业务行、负责人、写入指令或转换程序。系统消息明确所有标签、样例、频数和单元格中的指令均是数据。调用使用结构化输出和枚举引用。外壳损坏/调用失败时保留已有草稿，逐元素解析防止一个非法项拖垮合法列；实现验收要包含一个数组元素坏、其余仍能采用的模拟厂商回包。

- 表头行必须实际存在、非空且在 1–10；非法则保持当前表头，不采纳依赖非法表头的列建议。新表头未经确认不更换。旧规则、手动已占字段不可被 AI 抢占。
- 未发送的列/值、跨字段的选项、停用选项、不可导入字段和类型不适用的格式分别丢弃。重复占用同一直接目标且无法唯一判断时剔除相冲突的建议，不取列表第一项；多个追加只允许同一可导入 TEXTAREA，并允许一列正常映射该字段。冲突或被裁剪的项保留待手动处理，绝不回显未授权引用。
- high 可填入**预览草稿**。review 显示理由和「采用」；低把握值/格式也要单独确认。理由按短纯文本显示，限制长度、过滤个人信息及不可见字段，失败用通用说明。建议查重字段必须已有效映射、可查询、非成员非多选且满足现有 importRows 条件；依赖的列未采用则暂不勾选。
- 选项 null 表示职员确认「不对应」，不同于尚未决定。未决定的项提示人工选择或保留现有逐行检查错误。标为不对应时该格留空，必填在检查时报错；多选混有已知和不对应项时明确预览整格留空，避免静默丢一半。规范化后出现多个候选时不可自动选。手动操作优先。点「恢复到 AI 之前」恢复点击前的表头、映射、格式、取值及查重快照；将覆盖之后的人工修改时先说明影响。

## 4　确定性转换，所有套餐均可用

| 对象 | 规则与回归例 |
| --- | --- |
| 表头 | NFKC、忽略空白、大小写和末尾常用标点，匹配字段显示名/键。唯一才自动对上；不同原列归一到同一字段时显示冲突。客户名称：→客户名称；客户编号不因数字形状而映射到电话。 |
| 日期 | 保留当前支持的明确写法和旧两位年扩展；新增 2024年3月5日、20240305，均接受有边界的时分/秒后缀。严格验日历、闰年和时间。年在末尾的 3/5/2024 整列推断：某行前段 >12 表示 DMY，后段 >12 表示 MDY；两者都出现、两段都 >12 或非法日期是输入错误。全列均 ≤12 时保持待选，显示例如 3 月 5 日 / 5 月 3 日；推断只用原始数据行。 |
| 日期时间 | 显式 Z/偏移的输入保留原瞬间；无偏移的 ISO T、空格和中文写法按公司已验证的 IANA 时区转换。日期单独导入 DATETIME 按当地 00:00，DATE 仍是日历日期。复用 dashboard-timezone 的墙钟候选计算，保留秒数；夏令时跳空、重复时刻无唯一解时提示改为带偏移输入；公司时区取不到时停止该类行转换。上海 2026-08-21 10:30 → 02:30Z，详情仍显示 10:30；换浏览器时区结果相同。旧记录不回写。 |
| 数值、金额 | 严格检查千分位、符号与小数，支持 12万→120000、1.2万→12000、3亿→300000000、¥1,200元→1200、1200元→1200。用十进制移位后沿用现有 NUMBER/MONEY 表示与限制，超范围、非法分隔和非有限值报行级错误。单位建议仅作用于无单位值，显式「元/万/亿」优先，不能重复乘万。编号和电话不做数值转换。 |
| 是否 | 原有 是/否、true/false、1/0、yes/no，新增 有/无、Y/N、√/×；未知值报错，空格保持空。 |
| 单选/多选 | NFKC、去空白，对选项名/键作唯一比对。多选沿用现有分隔符逐值处理，去重并保留顺序。规则已解决的枚举不求助模型。不能仅因相似就把「重点客户」当成「A级」。 |
| 跳过/追加 | 默认跳过未对上的列并显示数量。追加按原列从左到右生成「原列名：原值」，非空每列一行，接在正常映射的长文本之后；原格有换行时在追加行内合为空格，原文件保留。目标超长走原检查，不截断存库。这里的“原有内容”指本次创建行已映射到该字段的内容。 |

CSV 和 Excel 覆盖同一套转换；涵盖格式化的前导零、Excel 日期序列、带引号的 CSV、多行、空表头和重名列。所有映射调整后重新计算预览，不修改源文件。

## 5　分负责人、查重与重试

管理员在本地选择负责人列。用当前公司在职成员的显示名精确且唯一匹配；两人同名、停用、空值、一名未匹配都进入人工处理。管理员可手工定列，所以即使负责人表头为陌生缩写也可在点击 AI 前排除。确认框按「名字、行数、归属」展示，允许指定某位在职成员、放入已启用初始公共池、或跳过这些行。公共池不可用时禁选并告知原因。员工能看见源列提示「仅公司管理员可按行指定负责人」，不会取得管理员的成员对照清单，不发送归属参数。普通成员字段不准映射或追加为负责人。

**复用现状。** record-import-file.ts 用文件原始字节与工作表名算 importBatchId；records.service.ts 用对象、batchId、原始 rowNumber 查已处理行。正式导入持有现有批次锁和查重锁。后端的 seen 仅在一次请求有效，前端 record-import-batches.ts 的 seen 仅在一次 runImportBatches 有效。只共用 batchId 可以抵御同一行的重试，不能替代文件内业务键查重。

**执行顺序**

1. 建立按源行号排序的不可变计划，包含转换后值、负责人/公共池/主动跳过和统一 matchFields。全体使用原 batchId，ownerMemberId、表头选哪行、编码和批号均不参与重新编号或派生新批次键。
2. 对所有待导行按归属分组并串行 dryRun，沿用每批最多 100 行、现有字节边界（单行限 80 KiB，批次包体约 90 KiB）。一个请求只指定 ownerMemberId 或 importToPool。空查重键、成员停用、公共池变化、权限撤销由现有服务端判定。
3. 收齐各批检查结果后按**原行号**做一次全表归并，使用服务端标准化后返回的 READY.matchKey（无 matchFields 时不判业务重复）。同一键按原行号最早的可导行获胜。示例：第 2 行归李四，第 80 行归张三，查重键同为客户编号 X，即使先检查张三组，最终仍是第 2 行 READY、第 80 行 SKIPPED。组内按原序检查，保留后端已识别的已有记录和组内重复；整组检查中断不能启用确认按钮。
4. 仅提交本次检查 READY 的行，其他行沿用检查结果。导入阶段仍按归属分组、使用同一原行号、保留服务端数据库查重与唯一行凭据。所有结果归并到 rowNumber→最终状态，按原文件排序显示。请求未完成的行保持「待重查」，不猜成功或失败。服务端已提交但响应丢失时重试命中「该行已导入」；不会创建第二条或改派先前已导入记录。并发新记录可令 READY 在正式导入时变为 SKIPPED，页面显示实际结果。
5. 记录在原权限可见范围内查重，不要求扩大查重范围。文件内判重仅针对本次文件。修改源文件字节会改变 batchId，重试必须使用原文件；重新提交另一份文件要靠选定的业务查重字段。部分写入后改映射/责任人需重新检查剩余行，成功行按原凭据保留。下载失败 CSV 按原始行号回取本机原值。

集成测试覆盖不同负责人、同组跨 100 行、跨组键相同、第一行校验失败、员工伪造负责人、跨租户成员 ID、停用成员、未启用公共池、响应丢失、并发重试、已有行再次导入。检查结果、最终归属、创建数、现有审计记录和可见范围均要断言。

## 6　导入抽屉线框

沿用列表页触发器、现有抽屉、AntD Select / Tag / Collapse 和表单反馈。1440 宽时抽屉约 920 px；1280 宽约 820 px。40 个文件列显示为最多 40 个纵向行，不横铺 40 个表头。文件样例过长可展开，长标签可换行，操作按钮保持可达。


## 7　交付门槛和证据

**目录与计量。** 在治理目录新增 import_assist / AI 导入 / 数据处理 / text / 已上线，无依赖，暂定输出 4,000 token，迁移暂排 0062；以评测中宽表合法输出长度、截断率和 p95 确认额度。复用目录同步、套餐数据库校验和既有平台配置；迁移不更新任一套餐 features。同步接口调用前检查权益和额度；无需模型的转换、日期修复和按行分负责人均可独立使用。登记 api-schema 与生成类型，架构测试继续禁止绕过治理层。

**评测设计。** 用同一批真实格式的合成 CSV、XLS、XLSX，开发 30、留出 10；先提交文件、文件哈希与正确方案，再调提示词。标注包含表头物理行、直接目标/允许的追加/应跳过、选项、日期顺序、金额单位、负责人预期和可导入行。覆盖中文近义、英文、相似但错误字段、标题/空行、歧义日期、万元、近似枚举、成员、隐藏哨兵、注入、40 列宽表。

| 指标 | 判定与分母 |
| --- | --- |
| 错配 | 错目标（包括该跳过却映射、向错误长文本追加）列数 ÷ 全部源列数 ≤2%。高把握错配列数 ÷ 全部高把握建议列数 ≤1%。两组分别过门槛；无高把握样本记「无法评估」。低把握候选也纳入建议正确性统计，另报实际预选错配率。 |
| 覆盖和质量 | 应对照的列中正确对上的比例、正确的不同值映射数/带标注的值数、表头正确文件数/文件数。并排报告纯规则和规则加 AI；低把握未采用的候选不算已对上。 |
| 隐私与注入 | 模型实际输入中完整电话、邮箱、证件、银行卡、成员列及隐藏字段哨兵为零；模型/最终方案中隐藏字段匹配为零。注入样本在加入干扰前后比较目标与选项，不能触发指令中的配置或写入。任何一次越权或外泄阻止交付。 |
| 业务结果 | 同一测试租户、权限、初始记录与原始行集上，逐文件分别转换并调用真实 dryRun。主指标为 READY / 全部原始数据行；失败、重复和主动跳过分别列数，不通过移除难行提高比例。两种模式用相同人工决策基线，另报人工采用低把握项后的结果。dryRun 前后断言记录数、行凭据及写入审计不变。 |
| 费用与等待 | 按实际调用统计 p50/p95 耗时、输入/输出 token 均值与 p95；记录未调用文件、取消、故障和截断。假 provider 负责权限和流程回归，真实模型单独报开发/留出，Key 从环境注入。 |

**实现顺序与验收。** PR 1 交付规则/时区、表头识别与选择、负责人分组、长文本追加及普通导入抽屉，完成后先交试用并列出隐私与分组规则的测试对照。PR 2 才实现套餐、模型接口、AI 交互与评测。每批先写对应失败用例，再跑类型、相关单测；API/数据库改动加 E2E 与 PostgreSQL 集成；现有 AI 模拟评测与基线逐项比。实际浏览器用刘洋验成员分组和断网重试，用赵晨和孙悦验员工权限、不同可见字段、未开通套餐及绕过 UI 的请求。对应提示词 1–15 逐条留证；人工核对真实同义列映射、低把握采用/恢复、物理第 3 行、必填不对应和两列追加。1440/1280 两种宽度截图按状态归档至 docs/audits/<日期>/ai-import/，注明真实与模拟、通过与未验证。PR 写清目录迁移、管理员需手动把功能加入套餐、旧无偏移时间可能差 8 小时且历史数据不会自动回填。

**扩展边界。** 保存方案/周期导入以后可从版本化映射协议接入；批量更新、多表拆分与关联、跟进/沟通导入各自需要明确的实体和写入权限。缺字段引导管理员去既有「AI 补充字段」后重新解析。省市拼接、拆列、其他成员字段、后台大文件和 OCR 留给单独版本。当前仍是单表、新建记录、人工确认。

**PR 2 验收。** 在同一实现指纹上比较 DeepSeek Responses 的默认推理和关闭推理。分别运行开发集、已查阅的 h01–h10 参考组，以及独立冻结的 h11–h20。开发集和新留出集分别判定以下门槛。

- 错配率 ≤2%，高把握错配率 ≤1%，隐私哨兵与注入命中为零。
- 包括待复核建议在内，正确对列覆盖率 ≥80%。员工采用实际提出的正确建议后，真实检查达到完整方案可导入行数的 80%，每份宽表至少一行可导入。
- 对实际 READY 且有标准答案的行分别统计缺值和错值。相对纯规则新增的非空错值逐文件、原始行和字段列出。
- 汇总全部实呼的 p50、p95，含超时和截断，p95 目标 ≤20 秒。另列每份宽表的耗时、成功情况和各文件调用次数。质量和延迟均达标后才选更快模式。
- 每次请求最多调用一次，25 秒超时后取消。员工手动选择再次尝试时可再次发起。当前对照在超时后保留。
