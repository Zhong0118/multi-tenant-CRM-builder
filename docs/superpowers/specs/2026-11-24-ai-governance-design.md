# AI 治理设计 · 套餐、额度、用量和操作记录

审阅稿，2026-11-24。基线为合入 AI 建表的 `bf1fff2`。产品验收的单位是一家公司：平台给它开通什么，管理员如何分配，员工下一次调用能否成功，以及三方分别能看到什么。

## 1. 谁决定什么

平台管理员定义套餐，给公司分配一个套餐或「未开通」，可追加当月额度。停止分配只影响以后的选择；正在用的公司继续使用，系统默认指向该套餐时须同时改选默认值。在用套餐不可删除。编辑套餐按引用立即生效。提交前由服务端返回实际影响的公司数、移除的功能和版本，写入时重新核对，过期的确认重新展示。

公司管理员只能改「全员共用 / 按人均分」。成员身份、表权限、记录可见性、字段权限和写入确认仍在原业务入口执行。套餐检查也覆盖助手侧面板、完整页、工具、卡片重试、单项和批量确认，以及直接请求 API 的路径。用量查询由服务端从会话解析租户、成员和角色。

| 功能 | 模型调用及归类 | 无额度时仍可执行 |
| --- | --- | --- |
| 对话助手 | 所有助手模型步骤一律归入助手，包括问答、简报及产生提议的步骤 | 查看本人历史 |
| AI 写入提议 | 必须同时开通助手。此开关独立控制生成与确认。用量页仅统计提议项数、确认项数，各按唯一操作 ID 去重，不分摊 token | 确认已生成的项仍重验套餐、权限和记录版本；拒绝或撤销待确认状态沿用已有能力 |
| 整理沟通 | 独立入口和助手内的实际草稿生成调用都归此项 | 按原草稿路径确认，要求整理沟通仍开通 |
| 一句话筛选 | 独立和助手内的筛选模型调用都归此项 | 已获准预览的应用仍通过记录查询校验 |
| AI 建表 | 初次生成、自然语言调整、补字段均归此项，另外要求租户管理员身份 | 已生成方案的确认重验套餐及管理员身份 |

助手转调整理沟通或一句话筛选时，外层决策步骤和内层生成是两次实际调用，各按自身功能计。确认时按服务端持久化的来源区分对话提议与沟通草稿，两者共用底层写入命令；客户端不能改来源。独立销售工具可以单独出售。助手仅注册已开通工具，执行工具及发布卡片前再验一次。额度耗尽可确认，功能被移除则禁止相应确认；紧急关闭期间暂停生成及 AI 确认，仍可查看历史、拒绝旧提议、手动操作 CRM。已经提交的业务事务按原语义完成。

## 2. 存储、迁移与读写边界

以下是拟新增的逻辑表，计数均使用非负 bigint。月份键取调用开始时公司当地自然月的第一天，时间戳存 UTC；跨月完成仍结算到原月，下月零点按 IANA 时区计算。月度设置不靠定时清零。

| 数据 | 必要字段、键与用途 |
| --- | --- |
| 平台 AI 套餐 | id、唯一名称、说明、五个允许的功能键、每月总 token、可分配状态、版本。服务端及数据库约束写入提议依赖助手 |
| 平台 AI 设置 | 单例，默认套餐可空、紧急关闭标志、原因、版本。provider 和模型名从运行时读取，只回传是否配置 |
| 公司 AI 配置 | tenant_id 主键、可空套餐外键、分配方式、版本。新建公司和配置同行事务落库 |
| 公司月额度 | (tenant_id, month) 主键，当月加量、已结算输入/输出、预占。额度取当前套餐值加本月加量；换套餐保留当月消费与加量，未开通时禁止调用。加量请求带幂等键，重发一次只加一次 |
| 成员月用量 | (tenant_id, month, member_id) 主键，已结算输入/输出、预占。共用模式也累计，切模式无需重建 |
| 模型调用明细 | tenant_id、member_id、月份、功能、provider、模型、request_id、唯一物理调用 ID、起止时间/耗时、结果、结算 token 和估算标志、预占及截止时间。一个 HTTP 请求允许多条。结果含成功、失败、取消、超时；内部另有待结算态 |
| 公司日功能用量 | (tenant_id, local_date, feature) 主键，结算时累加次数、输入和输出。写入提议按生成日和首次有效确认日分别累加提议项数和确认项数，只计来自对话的提议。平台六个月走势及功能分布只读这一级与公司月额度 |
| 公司 AI 操作记录 | 见第 5 节。业务内容和计量明细分开存放 |

迁移接在 0053 之后。一次事务建表、约束、索引和策略，建立全功能套餐「默认 AI 套餐」，所有存量公司赋此套餐并设全员共用。**每家公司试用月额度为 1000 万 token**，试用满一个月后按各功能实测用量复核。新公司默认也指向此套餐，平台可改成「未开通」。旧消息保留；计量从启用时开始，启用月标注起算日，不能从缺少用量的历史请求补算。部署顺序为数据库迁移、计量 API 和入口更新；混合版本期间不得对外宣称额度已强制执行。

所有租户表有 tenant_id、复合外键和 ENABLE / FORCE RLS；普通应用角色不可绕过。公司配置的分配套餐和加量采用仅平台身份可执行的窄写入口，与租户管理员的分配方式更新分开授权。沿用 platform-operations 的 withUser 和平台身份检查，仅向平台提供套餐归属、公司数和聚合指标；平台身份本身不获成员账、调用明细、操作原文或会话的读权。平台审计只存设置变更白名单字段，既有通用日志 API 也不能透出 AI 原文。测试使用实际受限数据库角色，覆盖直接跨租户 select/update、员工查他人用量以及平台角色查业务内容。0052 展示了强制 RLS；0053 只修改已有表的约束和索引。

## 3. 每次模型调用怎么检查和记账

### 3.1 谁可以发起调用

1. **规则**　业务服务先校验身份和业务权限。只有计量层能构造原始 provider；四个消费者和助手转调都传入服务端解析的租户、成员、功能与请求 ID。
   - **理由**　同一功能可能有独立页面和助手两个入口。
   - **对应测试**　架构测试限制原始工厂、令牌及 SDK 导入位置；用同一员工从两处调用，验证隔离和记账一致。
2. **规则**　每次发送前依次检查紧急关闭、套餐、公司余额、个人份额、限流。拦截返回原治理错误码，记录原因。
   - **理由**　紧急关闭要对新请求立即生效；查看历史和拒绝待确认项不消耗额度。
   - **对应测试**　同时触发两种拒绝时验证优先级。被拦截的请求，供应商调用数和消费增量均为零。分别测 REST、流式返回和工具转调。紧急关闭后确认旧提议也应失败。
3. **规则**　每次实际发给供应商的模型请求只记一次。助手逐步记账，三个结构化方法各自取得 output 和 usage。关闭隐式重试；显式重试重新准入。
   - **理由**　一次助手回合可能多次调用模型，结束事件也可能包含整轮合计。
   - **对应测试**　助手两步加一次筛选生成应有三笔，合计等于三次实报。一次写入提议被确认两次只计一个有效确认；确认本身不增加 token。

### 3.2 预占多少，什么时候拒绝

4. **规则**　输入预占 I = 实际待发送请求体的 UTF-8 字节数 + 16 × 消息条数，单位为 token。16 是本版的封装余量，含系统消息在内的每条消息计一次。计数覆盖工具定义、工具结果和输出 schema；请求头和凭据不参与，计数后不保存请求体。
   - **理由**　这给 DeepSeek 兼容接口提供一套可复算的保守估算，无需本地分词器。供应商可能另加封装，估算允许低于实报。
   - **对应测试**　固定中英文、表情、多步工具及长 schema 请求，核对实际序列化字节数。部署验收另与供应商回报逐条比对（第 7 节）。
5. **规则**　输出预占 O 固定取该功能完整的请求上限：每步对话 4096、沟通 4000、筛选 3500、建表 16000 token。需要预占 R = I + O。
   - **理由**　余额不足时压缩输出会截断回答，或使建表、筛选和沟通的 JSON 无法解析。
   - **对应测试**　公司和个人可用余额均至少为 R 时发送，断言传给供应商的输出上限等于 O。余额差 1 token 时整次拒绝，原输入保留。例：建表预估输入 4000 token，提示「剩余额度不足以完成这次请求，预计需要约 2 万 token」。
6. **规则**　可用余额 = 有效额度 − 已结算 − 在途预占。按配置、公司月行、成员月行的固定顺序加锁，锁内重验余额、写调用行并预占。两级预算都通过才提交事务，事务结束后才发送。
   - **理由**　同一笔余额只能被一个请求预占，网络等待不应占用数据库锁。
   - **对应测试**　真实 PostgreSQL 同时提交多个请求，只允许余额足够的调用到达 provider。限流拒绝释放尚未发送的预占。套餐变更与发起请求并发时，后续步骤按新设置检查。

### 3.3 如何结算，以及超额风险

7. **规则**　正常按供应商实际输入和输出结算。某一侧用量缺失时，以该侧预占值估算并标记。取消、失败、超时同样处理；确定未发送则释放全部。
   - **理由**　用户取消后，供应商可能已经处理了输入。估算标记让管理员知道哪些数值仍有误差。
   - **对应测试**　模拟取消且仅返回输入、超时且完全没有 usage、结构化结果解析失败但有 usage，逐笔核对扣除的 token 数与状态。
8. **规则**　调用按唯一 ID 在同一事务释放预占并更新调用明细、日汇总与两级月汇总。过期在途在下一次准入或查看用量时估算结算；晚到实报只按差额更正一次。
   - **理由**　进程退出或回执重发都可能发生。
   - **对应测试**　跨月重放同一回执两次，校验次数不变、差额只更新原月，日/月合计与明细相等。
9. **规则**　实报高于预占时记足实数，并按调用 ID 留一条估算偏低异常。平台系统设置仅展示模型、次数及差额汇总；模型继续可用。
   - **理由**　额度固定时，越过额度的部分最多为当时已准入、实数尚未入账的调用各自正误差之和，即 Σ max(实报 − 预占, 0)。包含可能迟到的回执。每人限频和长调用名额限制暴露面；没有全公司统一的固定 token 超额值。人工降额造成的历史超额单独解释。
   - **对应测试**　公司余 10000 token，两名成员各发一次筛选，分别预占 5000 token（输入预估 1500、完整输出上限 3500），分别实报 5110、5230，最终超 340 token；后续准入被公司余额拦下。追加额度后同模型可继续。重复回执不增加异常次数。
10. **规则**　每成员每分钟最多 12 次用户发起的生成或续答。一次续答内部的模型步骤逐次计量，共用这次限频许可。整理沟通和建表合计每人同时最多 1 个长调用。
    - **理由**　避免重复点击创建昂贵任务，同时保留正常多步问答。
    - **对应测试**　Redis 固定窗口第 13 次拒绝。独立入口和助手转调争抢同一个带所有者及 TTL 的长调用租约。断连时拒绝发送并恢复预占。历史和业务确认均不占生成名额。

| 拒绝原因 | HTTP / 错误码 | 用户看到的内容 |
| --- | --- | --- |
| 平台关闭 | 503 AI_PLATFORM_DISABLED | AI 功能暂不可用 |
| 套餐不含 | 403 AI_FEATURE_NOT_INCLUDED | 当前套餐不包含此功能；管理员可联系平台 |
| 公司已用尽 | 429 AI_TENANT_QUOTA_EXHAUSTED | 公司当地的恢复日期；员工联系管理员，管理员联系平台 |
| 个人已用尽 | 429 AI_MEMBER_QUOTA_EXHAUSTED | 个人份额的恢复日期 |
| 尚有余额，但放不下 R | 409 AI_REQUEST_BUDGET_INSUFFICIENT | 剩余额度不足以完成这次请求，并显示该功能本次预计需要的 token 数 |
| 仅因在途预占不足 | 409 AI_BUDGET_RESERVED | 同样显示预计需要的 token 数，提示待当前请求结束后再试 |
| 限频或长调用占用 | 429 RATE_LIMITED | 请稍后再试，附等待秒数 |
| 业务权限不足 | 沿用原业务错误 | 保留现有资源隐藏行为 |

## 4. 月份、均分和通知

1. **规则**　按公司当地自然月记账，当月加量在下月失效。调用按开始月份结算。
   - **理由**　跨月回执应归入原请求的预算周期。
   - **对应测试**　固定公司时区，在月末最后一分钟开始调用，次月收到实报，核对两个自然月及页面恢复日。
2. **规则**　全员共用只检查公司额度。按人均分时，每人份额取「本月总额度 ÷ 在职人数」向下取整，含管理员。零名成员时显示「暂无在职成员」。
   - **理由**　管理员和员工共同消费公司的额度。
   - **对应测试**　验证不能整除的余数、零名成员，以及个人达到份额而同事仍有余额。
3. **规则**　准入、切换预览和份额展示均使用当前人数和额度。停用及再启用保留个人的当月消费。已超新份额的成员等待份额提高或次月恢复。
   - **理由**　中途调整分配方式或成员状态仍应保留整月账目。
   - **对应测试**　月中入职、停用、再启用、追加额度、共用与均分互切；检查确认框、个人占比与实际准入一致。
4. **规则**　按已结算用量判断 80% 与 100% 两条线。每个公司自然月首次触达时，分别向当时在职的公司管理员发一次通知。结算和额度变更触发判断。
   - **理由**　反复预占、释放或加量会造成比例波动，预占不应触发通知。
   - **对应测试**　一次跨两线各发一条；回执重复、加量后再跨线均不重发。扩充 MemberNotification 的 kind 约束，沿用收件人、kind、eventKey 唯一键，月行阈值标记与通知同事务提交。零额度或未开通不计算百分比。
5. **规则**　全员共用且达到 80% 时，助手输入框上方显示「公司本月 AI 额度已用 83%」这样的实际占比。达到 100% 时改为耗尽提示和恢复日。按人均分时显示本人占比、剩余 token。
   - **理由**　共用额度也需要提前告知员工。
   - **对应测试**　79.9%、80%、100% 和加量回落分别验证。阈值用未舍入的比例判断；员工接口只返回所需用量提示，不带成员排行。

## 5. 操作记录与接口

AiOperation 已有 requestText、displayChangesJson、目标、发起人与确认人；AiRecordDraft 有原文且受本人策略保护。公司页采用**最小操作投影**：在提议创建、确认、失败或拒绝时随原事务更新操作记录，以操作 ID 唯一；沟通草稿按草稿 ID 显示一次，确认后的各项可展开。只复制导致该次写入的提问、准许展示的改动及目标引用，绝不复制聊天历史、系统提示或模型推理。AI 建表以 ObjectDraftBatchService 成功事务的对象与审计 ID 为源，标明 AI 确认来源，普通手动建表排除。未调用模型的拦截写原因、成员、功能和时间即可。供应商失败从用量明细按请求关联，安全错误只展示分类。对拒绝产生的操作记录须在返回业务错误前独立提交，避免一起回滚。

上线时为已有写入提议从 AiOperation 可验证字段回填，草稿与建表仅关联可可靠识别的来源。读操作记录重新校验当前目标、字段和角色；无权目标收起正文、差异与跳转，已删除的目标只显示状态。公司审计页可链接此处。平台的公共 AuditLog 仅写操作者和设置前后值，操作原文仅限公司侧。查看员工整段对话会暴露与一次操作无关的内容，后续若有此需求需先约定告知、查看权限、留存期与查看审计。

操作记录按 (tenant_id, created_at DESC, id) 游标分页，成员筛选加 (tenant_id, member_id, created_at DESC, id)，类型/状态在租户与时间范围内过滤。用量按 (tenant_id, month, member_id) 和公司日功能主键读取；公司列表先在数据库连接月汇总并按比例排序再分页，零额度排末尾。平台趋势不扫描 AI 消息或按成员取数。

| 入口（拟议，接入现有 REST / OpenAPI） | 读取与修改 |
| --- | --- |
| 平台 ai-plans、ai-settings | 套餐列表、详情、创建、编辑和停配，默认套餐和紧急关闭；所有修改校验平台身份、版本、审计 |
| 平台 tenants/:id/ai | 只读公司聚合；换套餐、按月追加额度。所有写操作和含修改前后值的审计同事务 |
| 工作区 ai/settings、ai/usage、ai/operations | 仅租户管理员；只允许修改分配方式。对新加入、停用、套餐变动重新计算确认摘要 |

1. 先测试原始 provider 边界、三个结构化调用、流式多步、工具嵌套、无 usage、取消、超时、结算幂等、过期预占。用事件顺序断言拦截发生在供应商调用之前。

### 真实用量与试用成本的验收口径

- 用 DeepSeek 运行中、英文样本，覆盖助手多步工具、长 schema 和三个结构化生成入口。逐调用报告 UTF-8 字节数、消息数、输入预估和供应商实报输入 token，列出所有低估及最大差额。报告说明本组样本是否逐条覆盖实报；发现低估时验证全额入账、平台提示及下一次可正常调用。
- 对四种实际调用分别报告样本数、每次调用的输入/输出/合计 token 的均值和 p95（从小到大第 ceil(0.95 × n) 个）。统计有完整实报的调用，另列缺失、估算、失败及取消数量。助手另按回合汇总，以便对照历史。第五个功能「AI 写入提议」报告提议与确认项数，token 栏标「计入对话助手」。目前没有本版实测结果。
- 审阅人提供的历史样本为 14 个 DeepSeek 助手回合，平均输入 9641、输出 818 token，合计约 1.05 万 token，回合 p95 约 1.64 万 token。按均值折算，1000 万 token 约 956 个同类回合。试用满一个月，用真实的功能构成、成员人数、估算偏差和被额度拦截的次数复核配额。
- 预算示例（2026-11-24）：按项目上轮实测使用的 deepseek-flash、上述输入输出比例，假设用满 1000 万 token。输入全部缓存未命中时，全在空闲时段约 12.35 元，全在高峰约 24.69 元；命中缓存还会降低输入费用。估算取百万输入未命中/输出的空闲价 1/4 元、高峰价 2/8 元。历史样本缺少缓存拆分和计费时段，无法还原实际账单。这项换算只用于试用预算。[DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

扩展点：保留输入/输出原数，后续计权或成本换算可独立汇总；自助购买、发票和超额付费可围绕套餐分配增加订单。个别成员份额、角色开关、席位计量及表数限制需单独定义授权和资源单位。模型路由与租户密钥以后接入同一计量边界；导出复用现有只读权限。以上均不纳入本次实现。
