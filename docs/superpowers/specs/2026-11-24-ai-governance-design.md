# AI 治理设计 · 套餐、额度、用量和操作记录

审阅稿，2026-11-24。基线为合入 AI 建表的 `bf1fff2`。产品验收的单位是一家公司：平台给它开通什么，管理员如何分配，员工下一次调用能否成功，以及三方分别能看到什么。

## 1. 谁决定什么

平台管理员定义套餐，给公司分配一个套餐或「未开通」，可追加当月额度。停止分配只影响以后的选择；正在用的公司继续使用，系统默认指向该套餐时须同时改选默认值。在用套餐不可删除。编辑套餐按引用立即生效。提交前由服务端返回实际影响的公司数、移除的功能和版本，写入时重新核对，过期的确认重新展示。

公司管理员只能改「全员共用 / 按人均分」。成员身份、表权限、记录可见性、字段权限和写入确认仍在原业务入口执行。套餐检查也覆盖助手侧面板、完整页、工具、卡片重试、单项和批量确认，以及直接请求 API 的路径。用量查询由服务端从会话解析租户、成员和角色。

| 功能 | 模型调用及归类 | 无额度时仍可执行 |
| --- | --- | --- |
| 对话助手 | 每次模型步骤起初归到助手。问答、只读工具和简报属于该项 | 查看本人历史 |
| AI 写入提议 | 必须同时开通助手。实际产生有效写入提议的模型步骤归到写入提议，同一步只计一次。被拦下或无有效提议的普通回答算助手 | 确认已生成的项仍重验套餐、权限和记录版本；拒绝或撤销待确认状态沿用已有能力 |
| 整理沟通 | 独立入口和助手内的实际草稿生成调用都归此项 | 按原草稿路径确认，要求整理沟通仍开通 |
| 一句话筛选 | 独立和助手内的筛选模型调用都归此项 | 已获准预览的应用仍通过记录查询校验 |
| AI 建表 | 初次生成、自然语言调整、补字段均归此项，另外要求租户管理员身份 | 已生成方案的确认重验套餐及管理员身份 |

助手调用后两类业务工具时，外层决策步骤和内层生成是两次实际调用，各按自身功能计。确认时按服务端持久化的来源区分对话提议与沟通草稿，两者共用底层写入命令；客户端不能改来源。独立销售工具可以单独出售。助手仅注册已开通工具，执行工具及发布卡片前再验一次。额度耗尽可确认，功能被移除则禁止相应确认；紧急关闭期间暂停生成及 AI 确认，仍可查看历史、拒绝旧提议、手动操作 CRM。已经提交的业务事务按原语义完成。

## 2. 存储、迁移与读写边界

以下是拟新增的逻辑表，计数均使用非负 bigint。月份键取调用开始时公司当地自然月的第一天，时间戳存 UTC；跨月完成仍结算到原月，下月零点按 IANA 时区计算。月度设置不靠定时清零。

| 数据 | 必要字段、键与用途 |
| --- | --- |
| 平台 AI 套餐 | id、唯一名称、说明、五个允许的功能键、每月总 token、可分配状态、版本。服务端及数据库约束写入提议依赖助手 |
| 平台 AI 设置 | 单例，默认套餐可空、紧急关闭标志、原因、版本。provider 和模型名从运行时读取，只回传是否配置 |
| 公司 AI 配置 | tenant_id 主键、可空套餐外键、分配方式、版本。新建公司和配置同行事务落库 |
| 公司月额度 | (tenant_id, month) 主键，当月加量、已结算输入/输出、预占。额度取当前套餐值加本月加量；换套餐保留当月消费与加量，未开通时禁止调用。加量请求带幂等键，重发一次只加一次 |
| 成员月用量 | (tenant_id, month, member_id) 主键，已结算输入/输出、预占。共用模式也累计，切模式无需重建 |
| 模型调用明细 | tenant_id、member_id、月份、功能、provider、模型、request_id、唯一物理调用 ID、起止时间/耗时、结果、结算 token 和估算标志、预占及截止时间。一个 HTTP 请求允许多条。结果含成功、失败、取消、超时；内部另有待结算态 |
| 公司日功能用量 | (tenant_id, local_date, feature) 主键，结算时累加次数、输入和输出。平台六个月走势及功能分布只读这一级与公司月额度 |
| 公司 AI 操作记录 | 见第 5 节。业务内容和计量明细分开存放 |

迁移接在 0053 之后。一次事务建表、约束、索引和策略，建立全功能套餐「默认 AI 套餐」，所有存量公司赋此套餐并设全员共用。**建议初始月额度 1000 万 token/公司**，这是待审阅的试用值，现有系统没有可直接继承的 AI 商业额度。新公司默认也指向此套餐，平台可改成「未开通」。旧消息保留；计量从启用时开始，启用月标注起算日，不能从缺少用量的历史请求补算。部署顺序为数据库迁移、计量 API 和入口更新；混合版本期间不得对外宣称额度已强制执行。

所有租户表有 tenant_id、复合外键和 ENABLE / FORCE RLS；普通应用角色不可绕过。公司配置的分配套餐和加量采用仅平台身份可执行的窄写入口，与租户管理员的分配方式更新分开授权。沿用 platform-operations 的 withUser 和平台身份检查，仅向平台提供套餐归属、公司数和聚合指标；平台身份本身不获成员账、调用明细、操作原文或会话的读权。平台审计只存设置变更白名单字段，既有通用日志 API 也不能透出 AI 原文。测试使用实际受限数据库角色，覆盖直接跨租户 select/update、员工查他人用量以及平台角色查业务内容。0052 展示了强制 RLS；0053 只修改已有表的约束和索引。

## 3. 每次模型调用怎么检查和记账

1. 业务服务先解析身份和业务权限，向计量入口传可信的 tenantId、memberId、feature、requestId。原始 provider 只在计量模块内构造。架构测试限制生产代码导入原始工厂、provider 令牌和底层模型 SDK 的位置；四个消费者和助手内调用均走公开的计量接口。
2. 准入依次检查紧急关闭、套餐功能、公司可用余额、个人可用余额、Redis 限流。前三类设置从数据库读，重新登录不是生效条件。生成失败的原有 catch/流式错误事件须保留治理错误码，不能统一翻译成「模型不可用」。被拒绝时只写治理事件，provider 调用数、已结算 token 均不增加。
3. 计量边界是每次实际发送给供应商的请求。当前 streamText 可连续执行工具步骤，finish 还会返回整轮 totalUsage。采用模型适配器的单步骤调用边界做预占和结算；保留现有流式工具编排和历史消息字段。关闭 SDK 的隐式重试；显式重试须重新准入。整轮 totalUsage 仅作显示或核对，不能再记一笔。三个 generateText 方法同时取得 output 和 usage，解析失败也经过结算。Fake 按同一边界给固定用量。
4. 预占采用严格预算。在请求发送前计算本次输入 token 的可信上界 I，包含完整消息、系统提示、工具描述、结构化 schema、消息封装与供应商计入的输入开销。模型适配器须有经验证的计数约定或供应商给出的硬上界；不能用中文字数除常数充当保证。允许使用已验证模型的请求输入上限作为较粗的兜底；无法确定上界的模型在平台状态中标明不可计量并拒绝发送。
5. 以较小可用余额扣除 I 后给本步分配输出上限 O，取该余额和功能上限的较小值；涵盖供应商计入输出的推理 token。沿用建表 16000、沟通 4000、筛选 3500 的输出上限，对话建议每步 4096。连输入与最小输出 1 都放不下时，提示「本次请求超过剩余额度」，有余额时可缩短输入。预算足够时不调整请求内容和提示词。
6. 固定顺序锁定配置版本、公司月行、成员月行，锁内重新计算余额，检查成功后原子增加两处预占 I+O 并建唯一调用行；不跨网络持数据库锁。并发请求看到的可用数 = 额度 − 已用 − 预占。Redis 限流成功才发送，未发送的限流拒绝释放预占，不计消费。设置变更与准入有明确先后顺序，已发出的单步允许结算，之后每步重新准入。
7. 回包时在一个事务内按调用 ID 从待结算改成终态、释放预占、写入成员/月/日统计。正常按供应商实际输入+输出记账。缺失哪一侧就以该侧预占上界估算，标记「估算」；取消、超时和供应商失败同样适用。比如预占输入 800、输出 400，取消后只收到输入实数 530，则记 530+400。明确在发送前失败释放全部；可能已发出的崩溃请求按估算结算。记录最晚完成时刻，在下一次准入或读取用量时清算过期待结算行；晚到的真实回执按同一 ID 一次性更正差额，不能重复计次。Redis 长调用槽也有到期时间。
8. 在验证过 I、O 上界的适配器上，任意数量并发导致的额度超用上限为 **0 token**。人工调低套餐/重算份额可使已用加在途量超过新额度，这部分完整展示，此后停止准入。若供应商实报突破适配器硬界，保留真实账、记录数值异常并停用该适配器，不能截断账目；上线前必须验证真实供应商的计数约定，模拟测试仅验证本地并发不变量。

| 拦截原因 | 拟用错误与展示 |
| --- | --- |
| 平台紧急关闭 | 503 AI_PLATFORM_DISABLED，「AI 功能暂不可用」 |
| 未开通或套餐不含 | 403 AI_FEATURE_NOT_INCLUDED，「当前套餐不包含此功能」；管理员附联系平台说明 |
| 公司用尽 / 个人用尽 | 429 AI_TENANT_QUOTA_EXHAUSTED / AI_MEMBER_QUOTA_EXHAUSTED，含公司当地恢复日期；公司用尽时员工联系管理员、管理员联系平台 |
| 输入超过剩余预算 / 余额已被在途请求占用 | 409 AI_REQUEST_BUDGET_INSUFFICIENT / AI_BUDGET_RESERVED，分别提示缩短输入、等待当前请求 |
| 频率或长调用并发达到上限 | 429 RATE_LIMITED，含 retryAfterSeconds，提示多久后再试 |
| 原业务权限不足 | 沿用原错误码与隐藏资源行为；历史读取沿用原授权 |

建议每成员每分钟 12 次用户发起的生成或续答，共享 tenant+member 键；同一外部请求内部的工具步骤不重复占用分钟次数，但仍逐次计量。整理沟通、AI 建表共用每成员 1 个长调用槽，包括助手转调。该值允许日常交互并限制重复点击引发的长调用。复用现有 Redis 固定窗口；长槽使用唯一租约、按持有者释放、TTL 大于实际服务端硬超时；故障时拒绝新调用并释放预占。只读历史、查看用量和确认均不占生成限流。

## 4. 月份、均分和通知

- 全员共用只检查公司余额。均分时份额 = floor((套餐额度 + 当月加量) / 当前在职成员数)，含管理员。使用公司和成员两道预算，余数留在公司。每次准入、设置预览和显示份额都按当前人数重算。零名在职成员时份额显示「暂无在职成员」，不做除法。
- 停用成员的本月消费继续占公司总额；重新启用同一成员也保留其用量。任何调整导致成员超份额，显示真实占比且暂缓准入，直到份额再增加或次月恢复。切回共用立即取消个人限制。临时加量只属于指定自然月。月份结算与显示都不能用 UTC 月初替代本地月初。
- 月内已结算用量首次达到有效额度的 80%、100% 时，向当前在职公司管理员写 MemberNotification。单笔跨过两线各一条，企业月与阈值去重，同一阈值下调、加量再耗尽也不重发。复用 recipient/kind/eventKey 唯一键，扩充 kind 检查约束；公司月行保留已触达阈值。按结算、额度变动重新判断，预占不触发。零额度/未开通显示配置状态，不触发比例除零。通知与结算或变更同事务提交。

## 5. 操作记录与接口

AiOperation 已有 requestText、displayChangesJson、目标、发起人与确认人；AiRecordDraft 有原文且受本人策略保护。公司页采用**最小操作投影**：在提议创建、确认、失败或拒绝时随原事务更新操作记录，以操作 ID 唯一；沟通草稿按草稿 ID 显示一次，确认后的各项可展开。只复制导致该次写入的提问、准许展示的改动及目标引用，绝不复制聊天历史、系统提示或模型推理。AI 建表以 ObjectDraftBatchService 成功事务的对象与审计 ID 为源，标明 AI 确认来源，普通手动建表排除。未调用模型的拦截写原因、成员、功能和时间即可。供应商失败从用量明细按请求关联，安全错误只展示分类。对拒绝产生的操作记录须在返回业务错误前独立提交，避免一起回滚。

上线时为已有写入提议从 AiOperation 可验证字段回填，草稿与建表仅关联可可靠识别的来源。读操作记录重新校验当前目标、字段和角色；无权目标收起正文、差异与跳转，已删除的目标只显示状态。公司审计页可链接此处。平台的公共 AuditLog 仅写操作者和设置前后值，操作原文仅限公司侧。查看员工整段对话会暴露与一次操作无关的内容，后续若有此需求需先约定告知、查看权限、留存期与查看审计。

操作记录按 (tenant_id, created_at DESC, id) 游标分页，成员筛选加 (tenant_id, member_id, created_at DESC, id)，类型/状态在租户与时间范围内过滤。用量按 (tenant_id, month, member_id) 和公司日功能主键读取；公司列表先在数据库连接月汇总并按比例排序再分页，零额度排末尾。平台趋势不扫描 AI 消息或按成员取数。

| 入口（拟议，接入现有 REST / OpenAPI） | 读取与修改 |
| --- | --- |
| 平台 ai-plans、ai-settings | 套餐列表、详情、创建、编辑和停配，默认套餐和紧急关闭；所有修改校验平台身份、版本、审计 |
| 平台 tenants/:id/ai | 只读公司聚合；换套餐、按月追加额度。所有写操作和含修改前后值的审计同事务 |
| 工作区 ai/settings、ai/usage、ai/operations | 仅租户管理员；只允许修改分配方式。对新加入、停用、套餐变动重新计算确认摘要 |
| 工作区 ai/capabilities | 在职成员读取本人入口、公司恢复日和本人的已用比例。不给员工同事明细；前端回到页面、保存设置或收到拒绝时刷新 |
| 既有会话、草稿、筛选和建表接口 | 服务端复查功能及业务权限；客户端隐藏入口不能替代接口拦截 |

## 6. 页面文字线框

沿用项目设计 04、06、08 以及平台和设置页的两份 UX 审计。AntD Form、Select、Checkbox.Group、Radio、Modal 配合项目 DataTable、feedback、MemberIdentity 及已有 @ant-design/charts。表单就地报错，保存成功 toast。统计统一「已用 12.3 万 / 50 万（24.6%）」；颜色按精确比例计算，零为中性、80% 起警示、100% 起危险。进度条最多画满，文字可超过 100%。
