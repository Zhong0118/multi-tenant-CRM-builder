# 平台 AI 模型配置、套餐功能目录与销售日常 AI

2026-11-24 · 供产品审阅 · 两个交付阶段

平台管理员配置一次模型，各公司沿用自己的套餐和额度。销售打开工作台先看到规则生成的清单，有需要才生成建议。建议、文案和日报都交给本人决定是否采用。此次审阅决定页面布局、数据范围和生效规则。真实厂商兼容性、性能和模型质量由后续验收给出。

## 1. 交付顺序与复用点

| 阶段 | 用户能做什么 | 复用入口 |
| --- | --- | --- |
| A · `codex/ai-model-settings` | 平台管理员管理连接、测试模型、切换用途；编辑按组展示的套餐 | 系统设置、套餐编辑、公司 AI 设置、治理工厂、ModelMeter、0054 的预占/结算/拒绝逻辑 |
| B · `codex/ai-sales-daily` | 全员查看个人清单；有相应套餐的成员生成建议、文案、日报草稿 | PersonalFollowUpWorkbench、记录详情助手、选记录卡、沟通与跟进表单、我的工作日报 |

A 从合入 ai-closeout 后的最新 origin/main 开始。B 开始前 fetch，A 已合并则从最新 main 建树；若并行则从 A 的最新提交建独立树，记录依赖，A 合并后 rebase 到 origin/main。各开一个 PR，推送和开 PR 前确认。新功能上线与给现有套餐开通分两步。

## 2. 平台模型配置

### 2.1 存储、角色和接口

以下为拟新增的逻辑表及键。模型 ID 是厂商 API 接受的字符串，平台内部另有稳定 ID。同一供应商可同时提供 Chat 与 Embeddings，界面分别选择「对话格式」和「支持向量接口」，共享基址和凭据。需要不同地址或凭据时创建另一连接。

| 数据 | 关键列和约束 |
| --- | --- |
| 供应商 | 稳定 id、显示名、预设、启停状态、生效与待测修订。修订保存规范化 baseURL、对话格式、是否有 embeddings 接口、凭据版本。对外列表只返回掩码。 |
| 凭据 | 独立表，id、供应商 id、密钥版本、主密钥 id、随机 nonce、密文、认证标签、末四位。连接修订通过外键引用。普通公司角色及平台通用查询角色无凭据表读取权限。 |
| 模型 | 连接修订下唯一的厂商模型名、能力集合、上下文长度、生成模型的最大输出、向量维度（实测）、可选输入和输出单价及币种；金额用 decimal，每百万 token。 |
| 用途分配 | `scope=platform`、可空 planId、purpose=text/vision/embedding、连接修订、模型、单调递增版本。平台范围每个用途唯一，用数据库约束处理空 planId；本版约束只接收平台范围。将来按套餐选择时扩展 scope 和唯一约束。 |
| 测试记录 | 供应商修订、凭据版本、模型、用途、测试套件版本、状态、操作者、起止时间、各步骤耗时、安全错误码、向量维度、平台测试 token 数。保存固定夹具的判定结果。 |
| 租户调用账本 | ai_model_calls 保留原 provider/model，追加 purpose、供应商稳定 ID、分配版本、配置来源、该次价格快照。历史行标识历史来源，未知成本留空。环境变量来源使用明确的来源标记与部署配置标识，排除秘密值。 |

平台管理 API 校验当前平台管理员身份。公司只读功能目录、模型就绪布尔值和自己的用量；价格、供应商详情及连接测试只在平台可见。治理运行身份通过窄接口解析当前激活配置；常规租户 SQL 查询不能读取供应商凭据。平台表沿用项目数据库角色和强制 RLS 约定，用真实角色做正反测试。平台测试没有 tenantId，不能伪装成免费租户调用。

拟在平台 AI 管理路由下提供供应商列表、保存待测修订、单独录入/更换 Key、发现模型、按用途测试、激活修订、分配用途、停用和删除；所有修改走版本校验。环境转换是独立 POST，只有确认与测试触发生效。测试失败保留可编辑草稿；删除和停用需事务内重查用途引用，历史调用的模型名称和价格仍可追溯。审计记录操作人、时间和可公开的改前/改后值；凭据事件只记录「已更换」。

### 2.2 Key、地址与测试

- 新环境变量 `AI_MODEL_KEYRING` 由部署工具注入，含 activeKeyId 和按 id 编码的 32 字节随机 AES 主密钥。平台配置写入采用 AES-256-GCM，每次加密生成新的 96 位 nonce，认证附加数据绑定供应商和凭据 ID。主密钥独立于数据库和数据库备份保管。仅用旧环境变量时无需设置它；缺少相应主密钥时禁止创建或激活不可解密的配置。
- 轮换主密钥先将新旧密钥并存分发到所有实例，确认都能解密两者，再切换写入 keyId。逐行用版本条件重加密并验证，允许断点续跑；核对旧 keyId 活动引用数为零，保留备份恢复所需的旧密钥在离线密钥库，再从在线配置撤下。轮换数据库密文不改变厂商 Key。更换厂商 Key 则走新修订与测试。
- 手动输入的 Key 仅随专用 TLS 写入请求发出，输入组件不回填，不进浏览器持久存储；环境转换只传命令，Key 全程不过浏览器。上游错误只映射错误类型、HTTP 状态和可公开建议，过滤请求头、URL 查询串及上游正文；关闭该路径的原始请求/响应追踪。假 Key 覆盖返回值、日志、审计、DB 明文列、导出和截图。
- 所有出站请求共用同一个受控传输，包括发现、测试、日常调用和环境迁入。生产只接收 HTTPS，限制无凭据、无查询串或片段的基址；在每次新建连接时校验全部 DNS 地址为公网地址，连接绑定到已校验地址并正常校验证书，拒绝重定向。连接超时建议 5 秒，发现 10 秒，单项测试及业务生成各有总时限（建表保留 90 秒）；用户取消贯穿 SDK 和 fetch。已有可信部署环境的兼容性在切换前用原生产格式回归。
- 连接参数和模型声明作为不可变修订；测试必须覆盖正在使用或准备分配的每个用途与模型。平台显示最近一次测试结果；只有当前修订、当前 Key 版本、相同模型与用途、相同测试套件的**最近一次完成测试成功**才准启用。采用单调测试序号和事务内比对防止旧测试覆盖新失败。未绑定的新供应商需至少一个用途通过才成为可用，未测模型保持待测。更换用途自动测，确认时若修订或测试已过期则提示重测。
- 文字测试通过治理工厂发三类固定请求：普通文本能解析；必须出现指定工具和合法参数（本地无副作用）；使用生产整理沟通同一 schema 和同一 SDK 调用路径，校验草稿和结束状态。厂商只支持部分结构化能力时，按真实生产调用结果判定。视觉使用内置小图，图片中的文字不进提示词，核对识别结果。向量使用两条固定文本，核对返回顺序、恰好两组、非空、有限数值、维度一致，记录实测维度；新维度与旧值不同须确认「已有资料需要重新建立索引」。
- 延迟使用单调时钟，从发出到完整读回并验证逐项显示毫秒，整套另计总耗时。发现模型仅提供可选 ID，发现成功不能当作一次测试通过。测试和发现走平台身份限流及治理工厂，测试费用只进入平台记录。架构测试覆盖原始生成、图像输入、embedding SDK 和直接调用厂商 HTTP 的位置。

### 2.3 热切换和现有部署

1. 环境变量 AI_PROVIDER、AI_MODEL、AI_API_KEY、AI_BASE_URL 作为一组可选旧配置。有效且平台尚无文字分配时，沿用旧 adapter/地址及 Responses 行为。全空时 API 正常启动，页面显示「未配置」。部分缺失时只报告缺项名称。已添加视觉供应商也不影响文字 fallback。
2. 「转为平台配置」根据旧端点和模型复制为加密待测修订，初始协议沿用旧配置。测试成功后原子激活并分配文字用途；失败仍沿用原配置。重复点击复用同一转换，失败可修改格式重测。已生效平台配置发生运行故障时显式报错，避免悄然换回旧模型。
3. 业务模型请求先通过原功能门禁，再向治理工厂取一次当前用途快照。建议每次实际请求读一次小型分配行（主库），按不可变修订缓存 SDK 客户端，减少跨实例缓存失效的复杂度。预占、请求和结算绑定同一快照；新请求在事务提交后读到新版本，在途流和重试归属原版本。多实例并发验收界限为 60 秒。
4. 每个用途激活之前确认能力和配置版本；文字模型最大输出须覆盖目录中全部文字生成项中的最大值，目前为 16000 token。列出所有超出模型能力的功能及其需求。调用时还检查上下文余量；严禁为了额度不足截短结构化输出。
5. 继续复用 ModelMeter 包装真实 fetch，包括 SDK 重试。平台测试、模型发现与租户调用分开归属。公司详情汇总按调用时单价与输入/输出分别计算，混合币种分行，部分缺价格标明覆盖范围。套餐满额成本有历史输入输出比例时用该比例预估并展示；无历史时按全输入至全输出的价格区间。未填单价显示「未设置单价」。

### 2.4 协议与厂商预设

项目当前固定 ai 7.0.100、@ai-sdk/openai 4.0.66。优先复用现有包的显式方法：createOpenAI({baseURL,apiKey,fetch}).responses(id)、.chat(id)、.embeddingModel(id)，分别对应 Responses、Chat Completions、Embeddings；视觉是对话中的图像输入，向量用 ai.embedMany。若兼容厂商的 SSE、计量或结构化协议需要兼容适配，在同一工厂中选匹配已锁 SDK 主版本的 @ai-sdk/openai-compatible，使用 createOpenAICompatible(...).chatModel(id)。该包不是引入三套计量的理由。各格式分别做网络契约测试（路径、模型、流式 usage、取消、schema、工具）。[SDK 文档](https://ai-sdk.dev/providers/ai-sdk-providers/openai) · [兼容适配器](https://ai-sdk.dev/providers/openai-compatible-providers)

## 3. 套餐与功能目录

采用一份版本化目录清单作为编辑源，每条含 key、中文名称、组、排序、依赖、所需用途、是否已上线（released）、是否可计量、单次输出上限。迁移由该清单生成或固化为快照；已发布迁移不可引用将来会变化的文件。运行时以数据库目录供 API、页面和 SQL 查询。CI 比较清单和应用全部迁移后的实际行。增加一种套餐能力，只须加目录条目和迁移；实现其业务行为仍在对应模块。

| 组 | key 与显示名 | 门禁与计量 | 输出上限（token） |
| --- | --- | --- | ---: |
| 基础 | assistant 对话助手 | 自身计量 | 4096 |
| 基础 | write_proposal AI 写入提议 | 依赖 assistant，沿用提议/确认计数 | 随 assistant 计量 |
| 数据处理 | communication 整理沟通 | 自身计量 | 4000 |
| 数据处理 | filter 一句话筛选 | 自身计量 | 3500 |
| 管理员 | table_builder AI 建表 | 公司管理员且获套餐授权 | 16000 |
| 销售日常 | daily_brief 今日建议 | 自身计量 | 2000，暂定 |
| 销售日常 | writing 帮我写 | 自身计量 | 1500，暂定 |
| 销售日常 | daily_report AI 写日报 | 自身计量 | 2500，暂定 |

八项均使用文字用途。预留 import_assist、vision、knowledge、channel、automation_builder 仅用于后续命名。平台套餐和公司设置从同一目录接口取排序和分组，服务端按 key、依赖和当前身份重新校验，删除 max(5)。套餐可以包含平台尚未配置模型的功能，保存前明确提示；A 发布到 B 上线期间，新三项显示「即将上线」且禁止选择，API 和数据库均拒绝授权。B 部署完成后以目录迁移开启，再由平台手动分配。

**数据库迁移策略。** 保留既有 ai_plans.features 数组，避免滚动期间旧 API 写入另一份授权数据。以针对写入的 trigger 查询目录替代数组枚举 CHECK，验证非空元素、合法 key、无重复、依赖闭包；目录迁移角色才可编辑目录。保留既有套餐行及顺序，用双向集合差核对迁移前后授权。ai_model_calls.feature 加目录外键，数据库预占按目录行的可计量标志与精确输出上限判定；保留 ai_feature_gate 的套餐和建表权限检查。更新聚合、拒绝记录和前后端展示，去掉第二份 feature 列表、硬编码 CASE 和固定数组长度。预占 SQL 测试覆盖未知 key、未计量项、错误上限和旧客户端。新增调用列先兼容旧插入，旧日志保留原名。迁移不改变新公司默认套餐。新功能只由平台管理员明确加入套餐。回滚旧 API 前撤销对新增项的编辑入口并保留配置，避免旧界面重存截断新增项。

## 4. 个人简报与「今天要处理」

### 4.1 清单与查询

清单接口不调用模型，不检查 AI 套餐。管理员和员工都按当前成员身份取数。以租户时区把本地日期的起点和下一天起点换算为 UTC，范围左闭右开；天数按本地日历日相减。逾期沿用现有工作台 due_at < now。当天已过点的任务在逾期组出现一次。默认计入本租户有负责人的已发布业务表，公司设置可缩小范围。

| 优先级 | 入组条件（查询前已应用租户、有效成员、可读记录、未删除、所选表） | 稳定顺序 |
| --- | --- | --- |
| 1 逾期跟进 | 本人是 OPEN 跟进负责人，due_at < now，按记录取最早到期。本人的跟进挂在同事负责的可读记录上也可入组。终态业务记录不进入四组。 | 最早到期、记录 id |
| 2 快被收回 | 本人负责、尚未进公海、pool_stage=FOLLOWING，存在回收期限，期限早于「当地今天 + 提前天数 + 1 天」零点。已到点而尚未收回者仍提醒，实际收回即移出。 | 回收到期、记录 id |
| 3 进展停滞 | 本人负责、非公海、已发布工作流且当前状态可识别且非终态。以最近进入当前状态的历史时间为起点，无历史用记录创建时间。停留天数 ≥ 阈值。 | 进入时间、记录 id |
| 4 很久没联系 | 本人负责、非公海、非终态（无工作流可入）。取最后一条 CALL/MESSAGE/MEETING/NOTE 的 created_at 与最后一次已完成跟进的 completed_at 中较晚者，均无则用创建时间。沟通人不限。间隔天数 ≥ 阈值。 | 最后联系、记录 id |

SQL 先在当前授权的记录集内分别选本人负责记录和本人到期跟进关联记录。按 tenant_id、record_id 关联活动、跟进和流转历史；从发布的工作流元数据取终态。UNION ALL 各组后用 row_number 按记录、优先级取第一项，再分组计算总数与前五。不先 LIMIT 再去重。「查看全部」沿用同一查询，按组内时间与 ID 游标分页。已有任务仍按任务展示；原有今日/近期跟进、待联系保留入口和业务含义，汇总记录卡片按 ID 去重，PENDING_CONTACT 继续在待联系展示。清单数量均基于可读数据。优先级 1 参与去重和 AI 候选，仅在原「跟进」列展示；「需要关注」只展示其余三组。

第一版按需查询，先沿用 records 的租户/表/负责人索引、活动的 tenant/record/created_at 和跟进负责人到期索引。用 EXPLAIN (ANALYZE, BUFFERS) 检查，按查询计划补齐 completed_at 的完成跟进部分索引、tenant/record/to_state_key/created_at、FOLLOWING 负责人回收期限索引。压测使用固定种子 5 万记录，含成员数据倾斜、跨表权限、历史活动和完成跟进；报告数据库规模、机器、统计信息、并发 10、预热后至少 200 次、清单首屏和最重分组抽屉 p95，另列冷启动结果。目标为本地 API 端到端 p95 <300ms。若仍不达标，再引入 last_contact_at 单一汇总列：分批回填，活动和跟进增改删、撤回完成时在同事务按记录重算，核对汇总与底表 SQL 后切读。pool_last_follow_up_at 的业务含义不同。本规格阶段没有性能测量值。

### 4.2 今日建议与私人缓存

- 本人主动生成。按上表顺序在去重结果中取前 30 条；每条带安全标题、表显示名、最多 6 个可见且已发布的标量业务字段。优先当前视图可见列，余位用发布顺序补齐；长值截断。补最近 3 条获准沟通正文（每条 200 字）、可见未完成跟进（按 dueAt 排序，输入受上下文预算约束，省略标注数量）。不传整行 JSON 或活动 metadata。提示词将业务文本标为资料，不接受其中的操作指令。
- 输出形状为 items[{recordRef, reasonFactRefs[], action:call|message|visit|advance_stage|add_followup, explanation, suggestedTitle?, suggestedDue?}]。输入分配临时事实编号。服务端剔除未知记录、无依据原因、重复项和不合法日期。原因可由事实模板生成；建议用将来语气。候选不少于三条时目标 3–5 条；仅一两条就按实际展示，验证后不足不补造。没有候选时零调用。
- 卡片可打开记录；有 writing 权益才出现「帮我写」，它打开该记录详情的写作面板；有跟进权限才出现「加跟进」，在原表单带入标题和建议日期，缺日期留给本人。打开和提交各自按当前身份解析。
- 缓存唯一键 (tenant_id,member_id,local_date)，保存经过校验的条目、事实引用、生成时间、生成状态、每日重生成次数和并发请求标记。FORCE RLS，SELECT/变更均要求本人、当前活跃租户；公司管理员只读自己的行，平台通用角色无读取权限。每次读取重新检查套餐、记录与字段权限、设置版本；权限或资料可见性变化使相关结果失效，旧文本不能绕过新权限。缓存命中不调用模型，清单随当前数据刷新。
- 第一次生成另计，每个公司当地日允许再生成 3 次。事务内占用名额和生成令牌，同一人的双击合并；未发送请求释放，实际发送后失败记一次重生成并保留仍可见的上一份结果。超时租约可恢复，旧请求不能覆盖更新的结果。日切后新键生效。
- 公司管理员在设置保存纳入表 ID、久未联系天数（14）、停滞天数（14）、提前提醒天数（3）。天数为正整数，建议设置范围 1–365，校验表属于本租户且已发布。设置带版本，保存后新查询立即生效。无需套餐也可以调整规则清单。

## 5. 帮我写与日报

### 5.1 权限裁剪与输出校验

三项生成均由服务端从认证上下文确定 tenantId/memberId，在发往模型前使用现有对象、记录和字段权限投影及 sanitizer，拒绝客户端自报权限和字段值。派生标题若来自不可见主字段则回退到安全记录编号。选项和工作流标签也须可见。沟通、跟进、任务为用户原文，只取已有读取策略允许的内容；结构化活动的字段变更要按字段裁剪，无法安全投影则舍弃。对关联目标逐条按自身权限再投影。测试捕获最终发送的 JSON（含工具历史、流式追加、用户输入之外的所有上下文），用植入的隐藏哨兵检查输入和输出。拒绝、用量、追踪和平台记录均不保存 B 的业务正文。

**写作。** 详情页抽屉可独立使用 writing，即使没有 assistant 套餐；聊天工具同时需要 assistant 和 writing。本人选类型（微信/短信、邮件、电话提纲、拜访准备）、目的（跟进、邀约、报价说明、催款、感谢或补充）、语气（正式/亲切）、长度（短/中）。聊天搜索重用现有工具，多条同名用现有选记录卡，然后调用同一写作服务。上下文取当前记录可见字段、最近 10 条获准沟通、未完成跟进和一层可见关联（按稳定顺序截取，每条标题和最多三个可见标量），不取附件。控制输入总长，超出时标注被截取的资料范围。

输出为 {kind, subject?, blocks:[{text,factRefs[]}]}，邮件必有主题，拜访准备包含概况与问题。服务端按完整文本块校验后推送流式卡片，保留当前块直至校验完成；避免错误价格先显示再撤回。数字、日期、价格和承诺须能映射到可见事实或用户补充，统一规范数字、金额单位、中文数字与公司时区日期。对缺少事实的量值和承诺使用受控占位符，如【报价金额】【交付日期】；无法验证的句子省略或要求补充。用户的输出偏好、编号、来源引用 ID 不充当业务数字依据。复制、重新生成、更短、更正式均作用于当前草稿；改写仍走同一验证。只有手动点击「已发送，记一笔沟通」才打开现有表单（消息/邮件默认 MESSAGE，电话 CALL，拜访 MEETING，员工可改类型）。保存仍由原表单触发。写作正文只在当前客户端内存中，聊天历史、工具调用持久化与错误追踪只留非正文状态；刷新后可重新生成。

**日报。** 服务端接受 workDate，限公司当地今天及往前七个日历日，拒绝未来。输入只取本人在所选日实际所做的沟通、完成跟进/任务、创建记录、实际流转，以及次日到期的本人未完成跟进和任务。跟进完成结合 completionActivity 的操作者，工作任务按现有完成权限语义校验；无法归属于本人的动作不纳入。按事实 ID 去重，完成跟进产生的活动不当作两次工作。只拿选择日期能授权读取的记录，不采集同事活动。无事实时显示空状态，无需模型。明日事项按所选日期的下一天取。

输出为 {plans,completed,problems,nextSteps}，每个字段是带 factRefs 的段落数组。校验日期、事实类别、所属日期和来源，生成文本只能复述有依据的动作；问题无明确依据时服务端返回空字符串。缺乏计划记录时 plans 留空，不能把完成事项倒推成原计划。页面把验证后的内容映射为现有 DailyReport 的四个文本字段。员工勾选字段，有旧内容时选追加或替换；预览后若本地表单内容改变，按最新内容再次展示差异。采用只改前端表单，最终保存沿用原 workDate 和 version，不抢占另一设备的修改。

**用量。** 新功能在发出每次模型调用前重新做服务端套餐、成员、紧急关闭、额度与每人每分钟 12 次的检查；套餐缺失返回 403。助手的编排步骤计 assistant，实际文案生成计 writing，各一次预占/结算。拒绝和缓存命中不扣模型额度。暂定输出上限的依据分别为五条带理由及动作的建议、单份短/中文案、四段带证据的日报。开发集用足够宽的试测上限记录实际输出 p95（记录截断/失败），按 p95 加 20% 余量向上取整到百位，复验最长合法样本及结构化完整性，再冻结上限跑留出集。以上数字属于试测起点。
