# 角色化经营工作台与记录筛选设计

> 日期：2026-08-31  
> 状态：已确认  
> 适用范围：公司管理员管理工作台、普通员工我的工作台、动态记录状态筛选  
> 优先级：本设计补充并覆盖旧文档中关于 Dashboard 暂不实现的范围；不改变通用对象、发布快照和租户权限边界。

## 1. 背景与问题

当前工作空间首页只提供业务表入口和管理快捷方式，尚未承担真正的工作台职责：

- 公司管理员看不到团队经营结果、管道分布、员工表现和风险业务；
- 普通员工看不到个人业绩、今日任务、个人管道和需要优先处理的记录；
- 动态对象可以自由定义字段，但系统不知道哪个对象代表商机、哪个字段代表金额、阶段或成交日期；
- 记录页的多选状态筛选使用 Ant Design `Select` 的 `maxTagCount="responsive"`，较窄时选中两个值就可能折叠，用户无法直接确认筛选条件；
- 当前 API 以分页记录列表为主，缺少面向工作台的聚合查询，不能用拉取全部记录后在浏览器计算的方式代替。

本设计将工作台从“导航首页”升级为“角色化经营与执行入口”，并保持平台仍是可复用的通用 CRM 构建器。

## 2. 已确认的产品原则

1. 采用通用、可配置的指标映射，不把“百杰线索/跟单/客户”写进动态对象核心。
2. 公司管理员与员工共享同一套业务口径，按照权限和记录负责人得到不同数据范围。
3. 公司管理员看团队经营与异常，普通员工看个人执行与业绩。
4. 所有卡片、图表和列表使用真实数据；未配置或没有数据时显示明确的引导状态。
5. 图表必须能够回到业务：点击阶段、人员或指标后，进入带相应筛选条件的真实记录列表。
6. 首期追求一条完整可运行链路，只保留关键契约、权限和聚合口径验证，不扩张大量端到端测试。

## 3. 方案选择

### 3.1 采用方案：租户级工作台指标配置

公司管理员为当前公司配置一套工作台语义映射：

- 线索对象；
- 商机/跟单对象；
- 客户对象（可选）；
- 阶段字段；
- 进行中、成交、失败对应的选项值；
- 金额字段；
- 预计成交日期或实际成交日期字段；
- 活动/任务对象及负责人、状态、截止时间字段（可选）。

若公司由平台业务模板初始化，上述映射可以作为模板配置随业务表一起带入。公司管理员仍可在自己的工作空间中调整映射，不允许平台模板直接修改租户已发布对象。

### 3.2 不采用的方案

- **写死 CRM 字段代码**：短期较快，但破坏通用平台边界，换公司或换字段即失效。
- **根据中文字段名自动猜测**：可以用于给出推荐值，但不得成为正式计算口径；“金额”“状态”“日期”等同名字段可能表达不同业务语义。
- **纯前端演示数据**：无法验证权限、筛选和真实经营结果，继续制造页面看似丰富但不可用的问题。

## 4. 角色边界与数据范围

### 4.1 平台超级管理员

平台总览继续展示平台运行信息，例如公司数量、状态、模板采用情况和平台任务状态。平台管理员默认不进入租户经营数据，不在平台总览展示公司员工销售排名或客户明细。

### 4.2 公司管理员

公司管理员工作台使用租户内全部可管理记录，并支持时间、业务管道和员工筛选。页面用于：

- 判断公司当前经营结果；
- 对比团队成员表现；
- 发现无人认领、长期未更新、逾期和高价值风险记录；
- 从聚合结果快速进入明细处理。

### 4.3 普通员工

员工使用同一份工作台配置，但所有统计和列表必须服从其有效对象权限、字段权限和数据范围：

- `OWN` 只聚合本人负责的记录；
- `ALL` 可以聚合授权范围内记录，但首页仍优先表达“我的执行”；
- `NONE` 或对象不可读时不展示对应模块；
- 隐藏字段不下发，也不得参与可由员工反推的数据展示。

排行榜默认只在公司管理员页面展示。员工端如以后展示排名，只显示经过产品确认的汇总值，不允许跳转到无权查看的其他员工记录。

## 5. 页面信息架构

工作台遵循“全局筛选 → 结果摘要 → 主要分析 → 异常/待办 → 明细”的顺序，桌面端控制在 5–9 个主要模块。

### 5.1 公司管理员管理工作台

```text
页面标题                                  时间范围  管道  员工
新增线索 | 进行中商机 | 成交单数 | 成交金额 | 转化率 | 逾期跟进
销售管道 / 业绩趋势（主分析区，约 2/3）  | 需要处理（约 1/3）
员工业绩排行                              | 目标进度
风险业务明细 / 最近成交
```

首期模块：

1. **全局筛选**：本月、近 30 天、本季度、自定义日期；商机管道；员工。
2. **指标带**：新增线索、进行中商机、成交单数、成交金额、转化率、逾期跟进。
3. **销售管道**：各阶段记录数量与金额；阶段可点击下钻。
4. **业绩趋势**：成交金额和成交单数按日、周或月展示。
5. **员工业绩排行**：员工、成交金额、成交单数、进行中金额、最近跟进时间。
6. **需要处理**：无人认领、逾期、长期未更新和即将到期的记录计数与入口。
7. **风险业务明细**：展示标题、负责人、阶段、金额、预计日期和最近更新时间。

目标值配置和复杂预测属于第二阶段；首期可以展示“尚未设置目标”的真实状态，不伪造目标完成率。

### 5.2 普通员工我的工作台

```text
问候与日期                                      新建记录
我的成交金额 | 我的成交单数 | 我的进行中 | 我的逾期 | 我的转化率
我的销售管道（约 2/3）                         | 今日待办（约 1/3）
我的业绩趋势                                   | 优先跟进
最近处理的业务
```

首期模块：

1. **个人指标带**：本期成交金额、成交单数、进行中商机、转化率、逾期数量。
2. **我的管道**：仅显示本人有效范围的阶段数量与金额。
3. **今日待办**：今天到期、已经逾期和即将到期的活动；没有活动对象配置时展示配置说明，不伪造任务。
4. **优先跟进**：高金额且即将到期、长期未更新或最近变化的本人记录。
5. **个人趋势**：个人成交结果随时间的变化。
6. **最近业务**：本人最近更新且有权读取的记录。

员工端的核心目标是回答“今天应该先做什么”，不能只是把公司管理员图表缩小复制一遍。

## 6. 视觉与交互设计

### 6.1 页面布局

- 保持现有 B × C 混合方向：阅读和摘要区域适度圆角，图表、排行和明细内部使用直线分隔；
- 工作台使用全部可用宽度，在超宽屏只限制图表可读跨度，不把主内容压成窄列；
- 顶部 KPI 使用一条紧凑指标带，通过分隔线组织，不使用六张相同的浮动大卡片；
- 主图占据视觉中心，右侧放可以立即处理的任务和异常；
- 下方排行榜和风险记录使用 Ant Design Table 的排序、筛选和分页能力；
- 颜色具有业务语义：蓝色表示进行中，绿色表示成交，橙色表示临期，红色表示逾期/失败，灰色表示未配置或无数据；
- 图表不使用渐变、立体效果、装饰性面积或过多图例。

### 6.2 响应式

- `>= 1200px`：主图与行动列表 2:1 分栏；
- `768–1199px`：主图单独一行，排行和行动列表双栏或按内容换行；
- `< 768px`：KPI 横向滚动或两列排列，图表简化标签，表格切换为记录卡片；
- 不通过隐藏已选择条件来维持工具栏单行。

### 6.3 状态多选筛选修复

记录列表中所有单选字段筛选统一调整：

- 移除 `maxTagCount="responsive"`；
- 所有已选标签始终可见；
- 标签使用 12px 字号和紧凑间距；
- Select 最小宽度提高，选择较多时内容换行并撑高控件；
- 筛选工具栏允许换行和增高；
- 保留标签自身颜色，以便快速确认状态；
- 提供清空当前筛选和清空全部筛选；
- URL 查询状态继续保存完整选项值，不改变服务端校验逻辑。

## 7. 配置与数据模型

### 7.1 租户工作台配置

新增租户级配置记录，建议以独立模型存储而不是塞入对象发布快照：

```ts
type DashboardConfiguration = {
  version: number;
  opportunity: {
    objectCode: string;
    stageFieldKey: string;
    amountFieldKey?: string;
    dateFieldKey?: string;
    activeOptionKeys: string[];
    wonOptionKeys: string[];
    lostOptionKeys: string[];
  };
  lead?: {
    objectCode: string;
    convertedOptionKeys?: string[];
  };
  activity?: {
    objectCode: string;
    dueAtFieldKey: string;
    statusFieldKey: string;
    completedOptionKeys: string[];
  };
};
```

正式保存时必须使用对象 ID 和字段 ID 或同时保存稳定代码，并在响应中投影为可读配置。对象重命名不应破坏配置；字段删除、停用或重新发布导致映射失效时，工作台返回“配置需修复”，不静默计算错误指标。

### 7.2 配置入口

公司管理员设置区新增“工作台配置”：

1. 选择商机对象；
2. 选择阶段、金额、日期字段；
3. 将阶段选项归类为进行中、成交、失败；
4. 可选配置线索和活动对象；
5. 即时预览能够生成的指标；
6. 保存后工作台开始使用真实数据。

字段选择器只显示类型兼容的已发布字段，例如金额只允许数字字段，阶段只允许单选字段，日期只允许日期/日期时间字段。

## 8. API 与聚合规则

新增独立工作台模块，避免扩张通用记录列表接口。

建议接口：

- `GET /api/v1/workspaces/{tenantCode}/dashboard/configuration`
- `PUT /api/v1/workspaces/{tenantCode}/dashboard/configuration`
- `GET /api/v1/workspaces/{tenantCode}/dashboard/summary`
- `GET /api/v1/workspaces/{tenantCode}/dashboard/pipeline`
- `GET /api/v1/workspaces/{tenantCode}/dashboard/trend`
- `GET /api/v1/workspaces/{tenantCode}/dashboard/attention`
- `GET /api/v1/workspaces/{tenantCode}/dashboard/leaderboard`（仅公司管理员）

所有查询接受统一的 `from`、`to`，管理员接口可选 `ownerMemberId`。聚合查询必须在数据库端完成，并复用租户上下文与有效权限解析：

- 所有查询包含 `tenantId` 和未删除条件；
- 员工的 `OWN` 范围强制追加当前 `memberId`；
- option key 以发布快照为准；
- 金额字段仅接受有限数值，空值不计入金额，但记录仍可计入数量；
- 成交率的分母、日期归属和时区必须在接口契约中固定；
- 默认使用租户所在时区；首期未配置租户时区时使用系统约定时区并在配置中明确。

首期口径：

- 新增记录：`createdAt` 位于筛选区间；
- 成交单数/金额：配置的成交日期字段位于区间且阶段属于成交；若未配置成交日期，工作台明确降级为按 `updatedAt`，并显示口径提示；
- 进行中商机：当前阶段属于进行中，不受创建日期限制，但可按预计日期区间过滤；
- 转化率：区间内成交数 / 区间内进入终态的记录数；没有终态记录时显示 `—`；
- 长期未更新：进行中记录的 `updatedAt` 早于配置阈值，首期阈值为 7 天；
- 无人认领：`ownerMemberId IS NULL`。

## 9. 状态与错误处理

工作台至少区分：

- **未配置**：公司管理员看到配置入口；员工看到“公司尚未启用工作台”，不看到管理员操作；
- **配置失效**：指出失效对象或字段，公司管理员可前往修复；
- **无数据**：保留筛选和模块标题，解释当前范围没有记录，并给出新建或调整范围动作；
- **无权限**：模块不请求或不渲染，不能通过聚合值推断隐藏对象；
- **部分可用**：例如已配置商机但未配置活动，销售模块正常显示，待办模块显示独立引导；
- **查询失败**：单个次要模块失败不得导致整个工作台白屏，主摘要失败时显示可重试的页面级错误。

## 10. 实施分期

### 第一阶段：可运行工作台

1. 修复记录状态多选标签折叠与工具栏换行；
2. 增加租户工作台配置模型和公司管理员配置页面；
3. 实现摘要、管道、趋势、关注事项和管理员排行榜聚合；
4. 重构工作空间首页，根据角色渲染管理工作台或我的工作台；
5. 图表与列表下钻到真实记录页；
6. 用现有演示公司和成员补充足以验证角色差异的真实记录。

### 第二阶段：经营增强

- 目标与配额；
- 预测金额与阶段概率；
- 跟进活动时间线；
- 更完整的销售周期、丢单原因和来源分析；
- 模板携带工作台配置；
- 公司管理员自定义模块顺序和可见性。

## 11. 验证范围

为了控制开发时间和额度，第一阶段仅执行：

- 配置输入与发布字段兼容性的服务级验证；
- 管理员 `ALL` 与员工 `OWN` 聚合边界验证；
- 成交金额、阶段数量和日期范围的少量口径验证；
- Web 类型检查和受影响页面的构建检查；
- 一条管理员和一条员工浏览器手工流程；
- 状态多选选中多个值均可见的浏览器检查。

不在本阶段增加全仓库回归、视觉快照矩阵或大量 smoke 流程。

## 12. 完成标准

- 选择两个及以上状态时，所有选中标签可直接看见；
- 公司管理员首页使用真实数据展示团队摘要、管道、趋势、排行和风险列表；
- 普通员工首页只展示自己有效权限范围的个人数据和行动入口；
- 未配置与无数据状态不使用假数据；
- 公司管理员能够在页面中完成业务对象与指标字段映射；
- 图表或列表能够跳转到真实业务记录；
- 统计结果不跨租户、不突破员工数据范围和字段权限；
- 页面在桌面和移动端均不存在横向撑破、筛选条件隐藏或主内容被窄宽度限制的问题。
