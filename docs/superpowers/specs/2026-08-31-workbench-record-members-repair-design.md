# 工作台、业务记录与成员管理修复设计

## 目标

修复三个已经影响实际使用的流程：工作台配置保存不透明且展示不随配置适配；业务记录编辑、删除入口隐藏；成员邀请与列表在中等宽度下拥挤、溢出。

## 已确认设计

- 工作台仍以一张核心业务表为统计主轴，不引入任意组件拖拽设计器。
- 配置页明确显示未保存状态、缺失的阶段分类和保存结果；保存成功后刷新服务端页面并可直接查看工作台。
- 工作台标题使用实际业务表名称；金额和日期相关模块仅在对应字段已配置时出现，不能用零值或更新时间伪装业务数据。
- 业务记录列表提供显式操作列。查看打开详情；编辑直接打开编辑态；管理员可软删除，员工只能按已发布权限更新记录。
- 修改和删除后刷新列表及依赖相同记录的工作台统计。
- 成员邀请表单使用纵向标签和完整宽度控件，并按容器可用宽度换行；表格设置稳定列宽、截断与横向滚动。

## 权限与数据边界

- 公司管理员拥有已发布业务表的更新、软删除能力。
- 员工的更新能力继续遵循对象动作权限、ALL/OWN/NONE 范围和字段权限；员工不开放删除。
- 删除保留审计记录和历史数据，不执行物理删除。

## 验证范围

- 工作台配置：一个组件级回归测试。
- 业务记录操作：一个组件级回归测试。
- 成员布局：浏览器在桌面和中等宽度各检查一次。
- 最后运行 Web TypeScript 检查，不跑全仓库 smoke/e2e。
