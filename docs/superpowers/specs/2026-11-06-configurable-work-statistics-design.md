# 任务与日报复用工作台业务统计

管理员在员工默认工作台的指标卡上启用“用于任务与日报”。业务表、状态筛选、计数或金额、统计日期沿用该卡配置；新增归属选择为创建人或当前负责人。无需公海，无需员工重复登记，也不新增统计数据库。

## 规则

- 仅已发布、启用、员工可见的默认工作台生效；草稿不影响使用者。未设置默认时按现有工作台可见目录顺序回退。没有启用此功能的卡片时维持旧界面。
- 仅 COUNT/SUM 指标卡可启用，受众必须为所有成员。必须有且只有一个“跟随工作台时段”的日期筛选；其他日期窗口、CURRENT_USER 筛选不允许用于日报，避免日期错配、管理员与员工口径不同。
- 文本日期支持：TEXT 字段明确选择“跟随工作台时段”后复用记录列表的年在前日期解析；空白、无效或年月日含糊的值不计入。不更改字段类型、不补写历史日期。
- 新客示例：客户表 COUNT，系统创建时间跟随时段，归属创建人。导入创建也算创建；历史业务应改用真实业务日期，系统不猜导入记录原始发生日。
- 开单示例：订单表 COUNT/SUM，状态为已确认，确认日期跟随时段，归属当前负责人。当前状态不等于状态变化历史，不自动推断成交时间，不把更新时刻当成交日期。
- 员工日报只汇总自己的归属，并继续受当前表、字段、记录权限约束。管理员查看员工日报也限定该员工归属，团队动态按成员汇总。管理员和员工的数据可见范围仍可能不同，说明这一点。
- 每条记录只计一次；重复建档仍是多条记录。当前负责人变更会改变按负责人统计的历史结果，历史状态/业务日期变更也会影响结果；本功能不是冻结的绩效账本。
- 归属为空不归入任何员工，团队按成员汇总不含这部分。组员权限不意味着个人日报统计整个小组。
- 原沟通统计、任务统计、日报文字及每日目标提醒口径不变，不将新指标静默映射到旧目标规则。
- 整体查询错误或单指标不可用明确显示，不能展示为零。各公司的配置和结果相互隔离。无数据库迁移、不写生产数据、不部署。

## 实现边界

扩展工作台 JSON 指标卡的可选 workReport 配置；复用现有发布流程、权限引擎、SQL 聚合及日期筛选。执行器增加服务端专用的按成员分组模式，一张卡一个分组查询，不逐员工查询。日报/团队接口携带可选 businessMetrics 结果，前端复用一个展示组件。保留原有记录统计并清楚区分业务表自动统计与人工活动登记。

## 验证

覆盖草稿/发布、非公海表、创建人/负责人差异、跨日边界、状态和金额、重复修改、未分配、跨租户、员工越权和隐藏字段、停用表、查询失败。隔离 PostgreSQL 执行 HTTP 流程；前端检查配置控件与员工/管理员展示，类型、lint、构建和合约检查。
