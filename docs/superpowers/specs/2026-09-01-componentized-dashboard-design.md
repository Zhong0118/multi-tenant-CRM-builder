# 组件化工作台设计

日期：2026-09-01
状态：已确认，等待实施计划

## 1. 背景

当前工作台虽然允许租户管理员映射业务表和字段，但配置根节点仍固定为 `opportunity`，运行时也围绕商机阶段、成交、失败、金额和负责人组织查询与页面。它适合作为销售型 CRM 的示例，却不能作为“租户可以建立任意业务表”的通用平台能力。

本次改造把工作台从“可配置的商机看板”升级为“由组件组成、绑定任意已发布业务表、按当前用户权限执行的租户工作台”。超级管理员可以在业务模板中提供默认工作台，公司管理员可以修改草稿并发布，公司员工只使用已发布版本。

## 2. 目标

- 每家公司维护一套工作台定义，由多个有序组件组成。
- 首期支持指标卡、状态分布/漏斗、趋势图、员工业绩排行和记录列表五类组件。
- 组件显式绑定业务表、字段、聚合方式和筛选条件，不根据字段名称猜测业务语义。
- 同一套工作台通过组件可见角色和现有对象权限，为管理员与员工生成不同的数据结果。
- 工作台采用草稿与已发布快照分离的发布模型。
- 业务模板可以包含默认工作台，应用模板时与业务表一起复制到目标公司。
- 兼容并迁移现有商机工作台配置，不丢失本地演示公司的工作台能力。
- 将配置解析、语义校验、权限收口、查询规划和结果规范化集中在一个深模块内。

## 3. 非目标

首期不实现以下能力：

- 自由公式、计算字段和自定义 SQL。
- 跨业务表关联聚合。
- 透视表和完整 BI 语义层。
- 任意嵌套的 AND/OR 筛选表达式。
- 多套可切换工作台或个人自定义工作台。
- 模板更新后强制覆盖已初始化公司的配置。
- 根据对象名称、字段名称或样例数据自动猜测指标含义。

## 4. 角色与所有权

### 4.1 平台超级管理员

- 在业务模板中配置对象、字段、默认权限和可选的默认工作台。
- 将模板应用到尚未初始化的公司。
- 不直接修改公司已经发布的线上工作台。

### 4.2 公司管理员

- 接收模板产生的业务表草稿和工作台草稿。
- 可以增删业务表、字段和工作台组件。
- 保存草稿、预览草稿并发布工作台。
- 对公司工作台的最终配置和发布时间负责。

### 4.3 公司员工

- 只能读取已发布工作台。
- 看到的组件和数据由组件受众、对象权限、数据范围和字段权限共同决定。
- 不能修改工作台配置。

模板是初始化蓝图。应用模板后产生的是租户独立副本；公司修改不会反向影响模板，模板后续更新也不会自动覆盖公司配置。

## 5. 总体架构

采用“类型化组件配置 + 工作台执行引擎”方案。

### 5.1 工作台定义

每个租户最多有一个 `TenantDashboardDefinition`。它保存当前草稿、草稿版本和当前已发布快照引用。每次发布创建一个不可变的 `TenantDashboardPublication`。

运行时首页只读取当前发布快照。编辑、保存和预览草稿不会改变员工正在使用的版本。

### 5.2 工作台执行引擎

新增深模块 `DashboardEngine`，对调用方暴露两个主要接口：

1. `validateDraft(definition, catalog)`：校验草稿结构、对象、字段、选项、筛选和组件兼容性，返回带路径的具体问题。
2. `evaluate(publication, context, period)`：根据已发布快照、租户上下文和时间范围生成标准化组件结果。

模块内部隐藏以下实现：

- 旧版配置向组件定义的兼容转换。
- 业务对象与发布快照解析。
- 字段类型和筛选操作符校验。
- 组件受众与对象/字段权限计算。
- `ALL / OWN / NONE` 数据范围收口。
- 查询计划生成、同对象查询合并和结果格式化。
- 单个组件失败隔离。

前端不再理解“商机、成交、线索”等固定业务语义，只按照标准组件结果渲染。

## 6. 配置模型

### 6.1 工作台根结构

```ts
interface DashboardDefinitionV2 {
  schemaVersion: 2;
  title: string;
  widgets: DashboardWidgetDraft[];
}
```

草稿允许语义不完整，以便管理员分步编辑；但必须是可解析的结构。发布时，校验器把草稿转换为所有必填引用都完整的 `PublishedDashboardDefinitionV2`。

### 6.2 组件公共字段

所有组件包含：

- `id`：定义内稳定且唯一的标识。
- `type`：五种组件类型之一。
- `title`：页面标题。
- `description`：可选辅助说明。
- `audience`：`ALL`、`TENANT_ADMIN` 或 `EMPLOYEE`。
- `objectCode`：绑定的业务对象代码。
- `width`：`QUARTER`、`HALF` 或 `FULL`。
- `sortOrder`：画布顺序。
- `filters`：全部同时满足的筛选条件。

组件顺序以 `sortOrder` 为准；保存前规范化为无重复的递增序列。

### 6.3 指标卡 `METRIC`

- 聚合方式：`COUNT`、`SUM` 或 `AVG`。
- `COUNT` 不需要数值字段。
- `SUM` 和 `AVG` 必须引用 `NUMBER` 或 `MONEY` 字段。
- 可选显示格式：普通数字、金额或百分比。百分比首期只负责格式化，不计算两个指标之间的比率。

### 6.4 状态分布/漏斗 `STATUS_DISTRIBUTION`

- 分组字段必须为 `SINGLE_SELECT`。
- 可配置包含的选项及显示顺序。
- 展示形式为 `FUNNEL`、`BAR` 或 `DONUT`。
- 统计方式为记录数，或对 `NUMBER/MONEY` 字段求和。
- 发布快照保存选项键、标签和颜色，保证显示稳定。

### 6.5 趋势图 `TREND`

- 日期字段必须为 `DATE` 或 `DATETIME`。
- 粒度为 `DAY`、`WEEK`、`MONTH` 或 `AUTO`。
- `AUTO` 根据请求区间选择粒度。
- 统计方式为记录数，或对 `NUMBER/MONEY` 字段求和。

### 6.6 员工业绩排行 `LEADERBOARD`

- 分组来源为系统记录负责人，或一个 `MEMBER` 字段。
- 统计方式为记录数，或对 `NUMBER/MONEY` 字段求和。
- 显示人数限制为 1 至 50，默认 10。
- 相同数值按成员显示名、成员编号稳定排序。

### 6.7 记录列表 `RECORD_LIST`

- 可选择 1 至 8 个展示字段。
- 默认排序可以使用 `createdAt`、`updatedAt`、`recordNo` 或一个可排序业务字段。
- 默认条数为 8，允许 1 至 20。
- 每行带真实记录标识，点击进入现有记录详情页。

## 7. 筛选模型

首期所有条件使用 AND 连接，不支持嵌套分组。

支持的字段与操作符如下：

- `SINGLE_SELECT`、`MULTI_SELECT`：`IN`、`NOT_IN`。
- `NUMBER`、`MONEY`：`EQ`、`GT`、`GTE`、`LT`、`LTE`、`BETWEEN`。
- `DATE`、`DATETIME`：`TODAY`、`THIS_WEEK`、`THIS_MONTH`、`PAST_N_DAYS`、`NEXT_N_DAYS`、`BETWEEN`。
- `BOOLEAN`：`EQ`。
- `MEMBER`：`IN`、`CURRENT_USER`、`RECORD_OWNER`。
- 文本类字段：`EQ`、`CONTAINS`、`NOT_EMPTY`。

校验器必须验证字段类型、操作符和值形状。相对日期由后端按照租户时区解析，不能由浏览器自行换算。

## 8. 草稿、发布与持久化

### 8.1 数据模型

现有租户工作台配置记录演进为定义记录：

- `tenantId`：租户唯一键。
- `draftConfiguration`：草稿 JSON。
- `draftVersion`：乐观并发版本。
- `activePublicationId`：当前线上快照，可为空。
- `sourceTemplateVersionId`：初始化来源，可为空。
- `createdAt`、`updatedAt`。

新增工作台发布表：

- `id`、`tenantId`。
- `number`：租户内递增发布号。
- `sourceDraftVersion`。
- `configuration`：规范化后的不可变配置，包含所依赖对象发布版本的标识与字段/选项显示元数据。
- `publishedByUserId`、`publishedAt`。

发布记录不更新，只允许创建和读取。定义记录与发布记录受现有租户隔离和 RLS 约束。

### 8.2 保存草稿

- 仅公司管理员可以保存。
- 请求携带 `expectedVersion`。
- 服务端只接受结构可解析、组件标识唯一的草稿；允许语义不完整。
- 保存成功后递增 `draftVersion`，不改变 `activePublicationId`。
- 版本冲突返回 `DASHBOARD_DRAFT_VERSION_CONFLICT`，不覆盖数据库或客户端草稿。

### 8.3 发布

发布在单个事务内完成：

1. 锁定租户工作台定义。
2. 验证请求的草稿版本仍为最新。
3. 加载所有引用对象的当前有效发布快照。
4. 完整验证每个组件和筛选条件。
5. 生成规范化发布配置与依赖清单。
6. 创建新的不可变发布记录。
7. 原子切换 `activePublicationId`。
8. 记录租户审计事件。

任何一步失败都回滚，旧发布版本继续在线。

### 8.4 业务表变化

发布配置绑定对象发布版本，因此业务表草稿变化不会影响线上工作台。对象后来重新发布时：

- 管理员配置页标记工作台引用已过期，并指出受影响组件。
- 已发布工作台仍可使用其快照中的字段和显示元数据计算已有兼容数据。
- 当前对象状态与权限始终实时参与求值；对象归档、读取权限取消或字段变为隐藏时，旧快照不能绕过限制。
- 管理员修复草稿并重新发布后才切换到新的对象版本。

## 9. 权限和数据安全

运行时按以下顺序收口：

1. 组件受众不包含当前角色时，省略组件。
2. 解析当前用户对对象的有效权限。
3. `canRead=false` 或 `readScope=NONE` 时，省略组件。
4. 员工为 `OWN` 时，查询计划强制追加当前成员为记录负责人的条件；配置不能覆盖。
5. 组件引用的统计字段、分组字段、日期字段或筛选字段为 `HIDDEN` 时，省略组件。
6. 记录列表只投影当前用户可见字段。

租户管理员按现有规则拥有租户内全部对象数据权限。员工排行榜在 `OWN` 范围下只返回本人，在 `ALL` 范围下才返回团队排行。

后端返回组件省略的机器可读原因给管理员预览接口；员工运行时接口不暴露对象或字段名称等内部诊断信息。

## 10. 查询计划和性能

工作台执行引擎先把有效组件编译为内部查询计划，再调用仓储适配器执行。

- 按 `objectCode`、权限范围和公共筛选前缀合并可合并查询。
- 指标、分布、趋势和排行尽量使用数据库聚合，不把全部记录载入应用内存。
- 记录列表只读取需要的字段和限定条数。
- 单次工作台请求最多执行配置数量可控的查询；首期限制每个工作台最多 24 个组件。
- 单组件失败不使整个工作台失败；结果包含该组件的 `UNAVAILABLE` 状态，其余组件正常返回。
- 首期不增加缓存。查询稳定后再依据真实性能数据决定是否引入短时缓存。

## 11. 模板集成

`BusinessTemplateConfiguration` 增加可选的 `dashboard` 配置。旧模板没有此字段时继续合法。

模板工作台遵循以下规则：

- 组件通过对象代码和字段键引用同一模板内的对象定义。
- 模板草稿允许工作台不完整。
- 发布模板时，如果包含工作台，则必须对模板对象和字段完成全部语义校验。
- 模板应用事务在创建租户对象后，同时创建租户工作台定义和草稿。
- 新公司的工作台不自动发布，因为租户对象尚未发布。
- 公司管理员发布所需业务表后，工作台页面显示可发布状态。
- `sourceTemplateVersionId` 仅用于追踪来源，不建立持续同步关系。

模板设计器复用租户工作台编辑器的组件模型和属性表单；数据候选目录改为模板对象目录，且不提供真实数据预览。

## 12. 前端体验

### 12.1 公司管理员编辑器

页面采用固定三栏工具布局，不使用临时抽屉：

- 左栏：五类组件库和当前组件目录。
- 中栏：接近最终首页的草稿画布。
- 右栏：当前组件的固定属性面板。

主要交互：

- 点击组件类型新增组件。
- 拖拽组件调整顺序；也提供键盘可用的上移/下移操作。
- 调整组件宽度、复制和删除。
- 在属性面板选择对象、字段、聚合、筛选和受众。
- 无效组件在画布原位显示具体问题，而不是只在页面顶部报错。
- 顶部显示草稿版本、线上发布号、未保存状态和依赖过期状态。

顶部动作明确区分：

- “保存草稿”：保存当前配置，不影响线上。
- “预览草稿”：管理员按管理员权限查看可执行组件，失败组件显示诊断卡片。
- “发布工作台”：对已保存的最新草稿执行完整校验并发布。

不启用自动保存，避免保存状态与发布状态混淆。离开存在未保存修改的页面时进行提示。

### 12.2 运行时工作台

- 按发布配置顺序和宽度渲染响应式网格。
- 组件使用统一标题区、空状态、错误状态和加载骨架。
- 没有真实数据时展示空状态，不生成假数字。
- 没有已发布工作台时，管理员看到配置入口；员工看到“工作台尚未启用”。
- 管理员与员工共享同一渲染器，数据差异由后端权限结果决定。

## 13. 接口设计

保留现有工作台路由前缀，并将语义改为草稿与发布：

- `GET /api/v1/workspaces/{tenantCode}/dashboard/configuration`：管理员读取草稿、发布摘要、候选对象和校验问题。
- `PUT /api/v1/workspaces/{tenantCode}/dashboard/configuration`：管理员按期望版本保存草稿。
- `POST /api/v1/workspaces/{tenantCode}/dashboard/preview`：管理员预览当前已保存草稿。
- `POST /api/v1/workspaces/{tenantCode}/dashboard/publications`：管理员发布最新草稿。
- `GET /api/v1/workspaces/{tenantCode}/dashboard/overview`：管理员或员工读取当前发布工作台结果。

发布接口不接受任意配置正文，只发布服务器上指定版本的已保存草稿，避免“看到的草稿”和“发布的配置”不一致。

## 14. 兼容迁移

现有 `TenantDashboardConfiguration` 数据不丢弃：

1. 数据库迁移增加定义/发布关系并创建发布表。
2. 为每条现有配置建立首个发布记录，并指向它。
3. 发布记录可以暂存旧版原始 JSON。
4. 兼容适配器在读取时把 `opportunity` 配置确定性转换为新版组件集合。
5. 现有总览在迁移后继续显示指标、漏斗、趋势、排行和优先记录。
6. 管理员第一次保存新版草稿后，定义记录写入 `schemaVersion: 2` 配置。

转换规则使用稳定组件标识，重复读取不会生成新配置。旧版 `lead` 和 `activity` 映射在字段足够时转换为指标卡或记录列表；字段不足时保留可诊断但未启用的草稿组件，不影响已迁移的商机组件。

## 15. 错误处理

- 草稿版本冲突：返回 409 和当前服务器版本；客户端保留本地内容并提示重新载入后合并。
- 草稿结构错误：返回带组件路径的 400，不写入数据库。
- 发布语义错误：返回组件级问题，阻止发布，旧快照继续在线。
- 对象或字段权限不足：运行时省略组件；管理员预览可看到原因。
- 单组件查询失败：该组件返回不可用状态，其他组件继续返回。
- 整体基础设施失败：沿用统一 API 错误处理并保留请求标识，便于平台日志定位。

## 16. 审计

记录以下租户审计事件：

- `dashboard.draft_saved`
- `dashboard.published`

审计信息包含租户、操作者、草稿版本、发布号和组件数量，不保存短信密钥、会话信息或记录具体字段值。

## 17. 验证策略

遵循聚焦验证，不扩张为大规模 smoke 测试：

- 配置解析/校验测试：五种组件的有效与关键无效组合。
- 引擎测试：受众、`ALL/OWN/NONE`、隐藏字段、单组件失败隔离。
- 服务测试：保存草稿、版本冲突、发布成功、发布失败保留旧快照。
- 模板应用测试：带工作台与不带工作台两条路径。
- 前端聚焦测试：新增/删除组件、保存草稿、发布按钮状态和错误定位。
- API 与 Web 类型检查。
- 一次浏览器流程：公司管理员编辑并发布，普通员工读取权限收口后的结果。

## 18. 实施边界

本次实施包含后端模型与引擎、API 契约、租户管理员编辑器、管理员/员工运行时、模板配置模型与应用复制、旧配置迁移和演示数据适配。

模板设计器中的完整可视化工作台画布可以复用本次编辑器模块，但若现有平台模板页面接入成本影响主链路，实施时先完成模板配置模型、校验与应用复制，再把平台端可视编辑作为紧随其后的独立前端切片。租户侧组件化工作台、发布机制和运行时权限不因此延期。
