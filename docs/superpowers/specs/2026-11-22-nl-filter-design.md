# 客户表的一句话筛选

2026-11-22 · 待产品审阅

销售在客户表的筛选面板输入「找我负责的、报价或谈判中、预计金额超过 10 万的客户」，面板就地展示三行可编辑条件。销售点击「应用」后列表才变化。之后可沿用「另存为个人视图」，以后打开仍按当时的权限查数据。

## 从输入到应用

| 销售操作 | 面板反馈 | 对当前列表的影响 |
| --- | --- | --- |
| 在现有工具栏点「筛选」 | 在条件编辑器顶部看到「用一句话描述条件」输入框和「生成条件」。桌面和手机用同一编辑器 | 继续显示当前视图的记录和生效标签 |
| 输入描述并生成 | 在原面板内显示加载状态。返回后直接展示「满足所有／任一条件」及字段、比较方式和值，新增行标「新」，每行均可修改、删除 | URL、结果数、分页和已保存视图保持原值 |
| 描述需要澄清 | 显示 2–4 个有具体含义的选项。点选后立即展示完整条件，明确的其余条件一并带入 | 点选只改草稿 |
| 点「应用」 | 调用现有面板的 `onApply`，回到第一页，更新标签和结果。可继续微调或另存视图 | 沿用列表查询、已修改标记和已有的保存权限 |
| 取消或生成失败 | 取消可退出预览；生成失败保留输入和原有编辑内容，可重试或手动筛选 | 仍显示原结果 |

**已有条件怎么处理。** 生成时将面板里当前的草稿作为上下文。销售说「再加上」时保留已有条件，说「换成」时允许移除已有条件。两种情况下模型都返回完整的新规则。生成前保留本次打开面板时的编辑草稿，生成后复用现有控件展示新草稿。已有条件若被移除，面板显示「将移除」及其条件摘要，按钮显示「应用并替换条件」；点「撤销生成」恢复生成前的手动编辑。等价条件不标新。这样「或」的适用范围能在点击前看清。切换业务表、视图或关闭面板后丢弃迟到的生成结果。不可用的共享视图沿用原有不可用状态。

本版只生成销售可以逐行编辑的一层条件。相同字段的多个选项可写成一条 `in`，跨字段的「或」用顶层 `any`。表达式确实需要嵌套时提示「当前面板无法完整表达这组条件」，保留原草稿；已有嵌套规则也不参与本版的生成替换。界面沿用[现有筛选编辑器](../../../apps/web/src/features/records/record-filter-panel.tsx)和[记录列表的应用与视图切换](../../../apps/web/src/features/records/record-list.tsx)。

## 模型输出与服务端边界

拟增只读接口 `POST /api/v1/workspaces/:tenantCode/objects/:objectCode/filter-preview`，请求体为 `{ text, currentRule, baseViewId? }`。从已有视图进入时填写该视图 ID，服务端按会话验证它属于当前对象且对该成员可用。该接口只读取元数据以构造、验证草稿。生成过程不需要读客户记录、查结果数或调用写入工具。

当前草稿也须先通过同一权限校验再发给模型。真实模型输出一份表达式，共同条件保存在 `conditions`。跨字段的混合逻辑可用子组表达，服务端发现子组便整份弃答。需要澄清时，`clarification` 引用一个有歧义的原文短语，并提供该短语的 2–4 种解释。适配器核对引文，逐一合并共同条件与解释，得到完整候选。服务端能够检查结构和引文，原话的逻辑分组以及短语是否确有歧义仍依赖模型判断。可供编辑的结果有以下两种，弃答时界面提示手动编辑。

```ts
type FilterGeneration =
  | { kind: 'rule'; rule: FilterRule }
  | { kind: 'clarify'; candidates: FilterRule[] };
```

以上销售示例，假设该租户的阶段和金额字段键为 `stage` 和 `amount`，活动选项键为 `quote` 和 `negotiation`，生成结果如下。字段键随对象元数据变化，金额按 MONEY 契约用十进制字符串。

```json
{
  "version": 1,
  "match": "all",
  "conditions": [
    { "fieldKey": "$owner", "operator": "in", "value": ["$me"] },
    { "fieldKey": "stage", "operator": "in", "value": ["quote", "negotiation"] },
    { "fieldKey": "amount", "operator": "gt", "value": "100000" }
  ]
}
```

1. **请求上下文。** 服务端解析当前租户、成员及已发布对象，复用 `queryFields(resolved)` 取当前成员可见且允许用于查询的字段。传给模型的只有字段键、展示名、可用操作符、活动选项及允许使用的系统条件。成员条件使用当前请求获准的成员选项；「我」始终是 `$me`。团队待跟进的 `any` 仅作为管理员可选值。相对日期保留注册表的预设值，最终查询按公司时区计算。
2. **规则合法性。** 模型读同一份 `FILTER_FIELD_OPERATORS`、`FILTER_OPERATORS`、`RELATIVE_DATE_PRESETS` 和对象元数据。每个拟返回的完整规则（包括每个候选）先通过列表解析器共用的 `validateRecordFilterRule`，核对版本、字段、操作符、值类型、活动选项、成员范围和 16 条上限；再检查本版一层可编辑、非空、系统条件范围等约束。不会把模型放弃或无效的输出解释成「全部记录」。语言理解交给模型，代码不维护中文词表或正则。
3. **失败与重新校验。** 任一条件或候选非法时，整份结果不可用；响应只给「无法生成可用条件，请调整描述或手动筛选」。隐藏字段和不存在的字段采用相同响应，不回显模型原始输出，也不删掉有问题的条件再返回宽松查询。应用时由现有列表路径用当前身份重新解析，保存时由现有视图服务重新验证；预览不能授予新的数据范围。两个员工打开同一份带 `$me` 的共享规则，各自按本人的身份执行。

规则与校验的依据见[筛选契约](../../../packages/contracts/src/records/index.ts)、[列表筛选解析器](../../../apps/api/src/modules/records/record-filter.ts)和[服务端视图权限](../../../apps/api/src/modules/views/record-views.service.ts)。

## 可复用的澄清选项

销售输入「我负责的、最近联系过的客户」，若有获准的联系日期字段，面板可显示「过去 7 天」与「过去 30 天」。两份候选都含「负责人是我」。服务端从已校验的候选中提取有差异的条件，用字段标签、比较方式和展示值生成选项文案。通用组件接收 `{ prompt, options: [{ id, label, value }], onSelect }`，其中 `value` 对本功能是一份已校验的规则。ID 只在当前面板识别选项；未来助手可使用同一个点选组件，自行处理返回值。

「重点客户」「大客户」也需要澄清。例如对象有「客户等级=A」和「客户规模=大型」两种口径，给销售点选。「预计金额超过 50 万」须有用户输入或可核验的业务配置支持；单有金额字段时，金额门槛交由销售在现有数值控件填写。没有两种可成立的解释时直接引导手动添加条件。候选去重后最多展示四个；多个含糊项无法在一次点选中完整表达时也交回编辑器。点选无需再次调用模型。

## 评测与交付验收

实施时复用[沟通草稿评测的运行与报告方式](../../audits/2026-11-22/communication-eval/rework.md)。每条样本固定输入、可查询字段及选项、角色、租户时区和当前时间，并标注完整规则、可接受的候选或必须拒绝的结果。开发集用于迭代，留出集独立编写并冻结，分别报分。以下是计划配额，尚未运行。

| 样本主题 | 开发 / 留出 | 核验重点 |
| --- | --- | --- |
| 多条件、选项与金额 | 4 / 2 | 示例三条件齐全，金额精度正确，「我」保留占位值 |
| 「或」和混合逻辑 | 3 / 2 | 区分字段内多选和跨字段 `any`，需要不可编辑的嵌套时弃答 |
| 相对日期 | 3 / 2 | 明确范围使用已有预设；跨公司当地午夜时按相同时区口径执行 |
| 不存在的字段或已停用选项 | 3 / 1 | 整份拒绝，原有合法条件也不单独应用 |
| 隐藏字段及越权的系统条件 | 3 / 1 | 请求上下文无隐藏字段，响应不泄露字段，禁止越权查询 |
| 含糊的客户等级、金额门槛或时间范围 | 4 / 2 | 候选可区分且与元数据相符，保留确定条件，缺少门槛时不虚构 |
| **合计** | **20 / 10** | **30 条** |

结构化判分忽略同组条件及多选值顺序，保留 `all/any`、字段键、值类型和日期范围的差异。澄清题同时检查候选覆盖、共同条件和候选合法性；越权或字段泄露单列，任何一例失败都阻止交付。CI 用模拟 provider 验证流程及异常输出，真实模型按数据集记录模型名、通过数和失败样本。

API 验收覆盖跨租户对象和视图访问、两个员工的 `$me`、预览后字段权限变化、伪造的字段或选项、无效候选整份拒绝。浏览器主流程为「输入 → 预览 → 编辑或删除 → 应用 → 另存个人视图」和「含糊描述 → 选解释 → 取消」，分别验证只有应用才刷新记录、取消后原查询保留、共享视图内容没有被改写。

**本版范围。** 客户表的单次生成、一次点选、逐项编辑、应用与另存。多轮对话式修改、图表、批量操作和嵌套条件编辑留待后续。
