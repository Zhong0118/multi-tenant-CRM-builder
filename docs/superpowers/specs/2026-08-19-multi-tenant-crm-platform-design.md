# 多租户 CRM 平台与首家公司模板总设计

日期：2026-08-19
状态：待审阅

## 目标

建设一个把中小企业分散在 Excel、文件夹和员工个人表格中的业务数据，转换为带租户隔离、成员权限、在线表单、统一视图和统计能力的 CRM 平台。首期以第一家公司的“获客 → 跟单 → 客户”闭环验证平台框架，但不得在通用层写入该公司的专属判断。

## 设计范围

设计分为两层：

- 通用平台 MVP：租户、成员、业务对象、字段、记录、视图、权限、Dashboard、导入导出和集成扩展点。
- 首家公司模板：获客、线索审核、跟单、客户、期刊和统计的业务配置与少量显式领域动作。

飞书是平台级可选集成通道；电话 Bot、自动化和机器人业务指令属于首家公司后续阶段，不是通用 MVP 的上线前置条件。

## 方案比较

### 方案 A：共享平台 + 受控配置 + 业务模板（采用）

一套前后端和数据库服务所有租户。平台管理员配置业务对象与字段，模板提供初始配置；需要保证事务一致性的业务动作（例如“跟单转客户”）由后端领域服务显式实现。

优点是首期可交付、可复用且不会把所有逻辑塞入 JSON；缺点是平台管理员在早期承担配置工作。

### 方案 B：完整元数据低代码平台（暂缓）

把关系、公式、工作流、自动化、Dashboard 和权限全部做成租户自助配置。长期扩展性高，但首期必须同时开发查询、权限、执行和版本兼容引擎，超出当前目标。

### 方案 C：每个租户独立代码或部署（拒绝）

可以快速做单个定制项目，但升级、修复、安全和运维成本随租户数线性增长，也无法形成平台产品。

## 系统边界

```text
浏览器 / 移动端浏览器 / 飞书（后续）
                 │
          Web 应用与 REST API
                 │
 ┌───────────────┼────────────────┐
 │               │                │
身份与租户    配置与记录       业务模板服务
 │               │                │
 └───────────────┼────────────────┘
                 │
    PostgreSQL / Redis / 对象存储
                 │
          集成适配层（后续）
       飞书 / 电话 Bot / Webhook
```

每个请求先建立 `TenantContext`，再进行模块、数据范围和字段权限判断。前端传入的 `tenant_id` 不具备授权效力。

## 核心模块

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| Identity | 登录、会话、密码与账号状态 | User |
| Tenancy | 域名/工作空间解析、成员身份、租户状态 | Tenant、TenantMember |
| Configuration | 业务对象、字段、视图、模板及版本 | Tenancy |
| Records | 校验、查询、增删改、负责人和活动 | Configuration、Authorization |
| Authorization | 模块访问、ALL/OWN 数据范围、字段权限 | Tenancy、Configuration |
| Dashboard | 对允许数据范围进行聚合 | Records、Authorization |
| Import/Export | 映射、校验、预览、异步导入与导出 | Records、Object Storage |
| Integrations | 外部身份映射、验签、幂等和审计 | Authorization、Records |
| First Tenant | 获客转跟单、跟单转客户等显式业务动作 | Records |

模块必须通过稳定服务接口通信；控制器不得直接拼接 JSONB 查询或自行实现租户过滤。

## 权限模型

权限按顺序求交集：

1. 租户边界：记录必须属于当前租户。
2. 模块访问：成员是否可进入业务对象。
3. 数据范围：`ALL` 或 `OWN`。
4. 动作权限：`CREATE`、`READ`、`UPDATE`、`DELETE`、`EXPORT`。
5. 字段权限：员工字段为 `EDIT`、`READ_ONLY` 或 `HIDDEN`。

平台管理员不能以普通租户接口绕过权限；需要查看租户数据时必须进入带审计的“代管模式”。

## 数据流

### 普通记录更新

```text
提交表单
→ 解析当前租户与成员
→ 检查对象、数据范围和动作权限
→ 根据字段定义规范化并校验 data
→ 移除无权编辑字段并拒绝越权请求
→ 事务写入记录和审计日志
→ 返回按字段可见性裁剪后的记录
```

### 跟单转客户

```text
校验跟单状态及权限
→ 在事务中锁定跟单
→ 创建或关联客户
→ 复制映射字段并保留来源关系
→ 标记跟单已转化
→ 写入转换事件和审计日志
```

重复请求通过幂等键返回同一转换结果，不得生成重复客户。

## 错误处理

- 401：未登录或会话失效，引导重新登录。
- 403：已登录但无模块、记录、动作或字段权限，不泄露目标记录内容。
- 404：资源不存在，或为避免枚举而隐藏越租户资源。
- 409：状态转换冲突、重复转换或乐观锁冲突。
- 422：字段校验、导入映射或状态规则不满足。
- 429：登录、导入、机器人及公共接口触发限流。
- 5xx：记录关联 ID 后展示可重试提示，服务端保存结构化日志。

## 非功能要求

- 租户隔离是发布阻断项，服务层过滤与 PostgreSQL RLS 双重保护。
- 所有列表必须分页；普通筛选在 10 万条租户记录规模内 P95 小于 800ms。
- 关键写操作必须有审计记录；密码、令牌和敏感字段不得进入日志。
- 桌面端是主工作场景，支持 1280px 及以上高密度表格；移动端保证查看、搜索和关键录入可用。
- 正常业务操作不依赖页面整页刷新。
- 核心路径满足键盘操作、可见焦点和减少动态效果设置。

## 测试策略

- 单元测试：字段校验、权限矩阵、状态机、指标计算和字段映射。
- 集成测试：事务、RLS、JSONB 查询、导入幂等和转换幂等。
- 端到端测试：三种角色的登录、租户切换、列表、详情、跟进与转换。
- 安全测试：构造其他租户 ID、越权字段、批量接口和导出接口。
- 视觉回归：登录、Dashboard、数据表、抽屉、表单设计器和移动端关键视口。

## 首期成功标准

1. 平台管理员可创建租户、管理员和首家公司模板配置。
2. 租户管理员可管理员工并查看本租户全部业务数据。
3. 员工只能查看和修改自己负责且字段授权允许的数据。
4. 首家公司可以完成“线索 → 跟单 → 客户”的完整追溯。
5. 期刊的管理员字段对员工只读，且 API 同样拒绝修改。
6. Dashboard 指标可追溯到一致的数据口径。
7. 通过跨租户与越权自动化测试后才允许部署。
