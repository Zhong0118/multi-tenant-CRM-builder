# 页面助手 V2 验收

2026 年 11 月 22 日，员工赵晨在星云科技演示公司的客户表和客户详情页完成了桌面 1440 × 900、手机 390 × 844 浏览器验收。页面访问本机 API，数据写入独立 PostgreSQL 18.4 验收库。助手使用 fake provider，调用实际 CRM 工具、权限检查、提议确认和审计服务。真实模型在本次浏览器验收中未验证。

## 批量确认

赵晨输入「给我负责的报价阶段客户各新增一条下周一的跟进」。客户表有 10 条可见记录，报价阶段匹配 3 条。每轮确认前，在另一个登录会话用普通记录更新接口修改所选客户的备注。确认后读取业务表、操作状态及关联审计。

| 验收端 | 未勾选 | 版本冲突 | 成功项 |
| --- | --- | --- | --- |
| 桌面首次 | 嘉禾商贸的待办数 0 → 0 | 临江设备 v1 → v2，待办数 0 → 0 | 远山科技待办数 2 → 3 |
| 手机 | 远山科技待办数 3 → 3 | 嘉禾商贸 v1 → v2，待办数 0 → 0 | 临江设备待办数 0 → 1 |
| 桌面复测及截图 | 嘉禾商贸待办数 0 → 0 | 临江设备 v2 → v3，待办数 1 → 1 | 远山科技待办数 3 → 4 |

三轮确认各执行一项，成功项关联一条 `follow_up.created`。每轮冲突项得到 `CONFLICTED / RECORD_VERSION_CONFLICT` 和一条 `ai.proposal_failed`。未选项维持 `PROPOSED`，未产生业务或失败审计。手机点击「重新生成这一项」后，仅嘉禾商贸得到一个按 v2 生成的新提议，等待再次确认。桌面和手机各发一次「把我现有的跟进待办推到下周一」，两次都提示到跟进待办调整，两个轮次均为零操作记录。

## 其余链路

- 搜索「张三」后，界面显示编号 24 和 25。桌面选择 24、手机选择 25，各轮只给选中的记录提出阶段变更，确认前两条记录均为初访。随后在桌面打开同一会话，核对编号 25 的提议并点击「确认执行」。编号 25 的阶段由初访变为谈判，版本由 1 变为 2，操作状态为 EXECUTED，关联一条 `record.updated` 审计。编号 24 保持初访和 v1，更新审计为 0 条。
- 11 月 23 日手机补测，在远山科技页要求把负责人改成钱宇，助手明确拒绝。要求修改赵晨不可见的「所属行业」时，初次返回可见字段清单。调整模拟器后，原请求与对不存在字段的相同修改均返回「当前没有可用的修改项，请核对可编辑字段」。这三个复核请求均为 0 提议、0 问题卡，远山科技的负责人、行业值、记录版本、业务审计数、活动数和待办数在操作前后相同。
- 在远山科技详情页发送「帮我改一下」，刷新后重新打开助手仍能看到表单。仅填「客户备注」，服务端恢复会话并生成单字段提议，确认前未写入备注。
- 在客户表输入「找我负责的、报价或谈判中、预计金额超过 10 万的客户」，预览生成三个条件，表格仍是 10 条。点击「在表格中应用」后剩临江设备和远山科技。手机从「帮我筛选」选择「只看我负责的客户」，得到「负责人 · 我」和显式应用按钮。
- 在远山科技手机版详情页说「帮我记一下」，选择「仅记纪要」后，助手提示粘贴原话。发送「记录：采购预算已确认，周三提醒客户发合同」，打开草稿，核对后点击「确认所选项」，生成一条 `ADD_ACTIVITY_NOTE` 和一条 `record.activity_created` 审计。另一份只打开、未确认的草稿没有关联操作。
- 远山科技简报显示四段，概况与进展带有本轮来源，风险和建议带「推断」标记。截图时读到两条活动与三条跟进。点击记录页页签的移除按钮，关闭面板、刷新、重新打开后仍显示「关联当前页面」。转到带同一 conversation 参数的完整页能回看原会话。
- 输入「模拟服务不可用」触发 fake provider 故障，后端消息保留 `FAILED / AI_PROVIDER_UNAVAILABLE`。界面显示重试按钮，输入框保留了原文。手机抽查时面板宽 390 CSS px，左边界与可视窗口均从 0 开始。

## 本机复查

[登录验收工作区](http://asst-v2.localhost:54880/login)后选用 nebula-demo 的赵晨演示账号。桌面案例的日期以 11 月 22 日发起时的公司时区计算，原提议具有有效期，后续可重新发起测试。账号初始化来自仓库的 demo-company-fixture。

本次从演示数据备份恢复到独立数据库 `crm_test_assistant_v2_qa`，部署迁移至 0053，使用受 RLS 约束的 `crm_app` 连接运行 API。以赵晨身份通过业务接口增加临江设备和嘉禾商贸两条报价记录、两条同名张三记录。Web 使用 54880，API 使用 54881，独立 Redis 使用 54882。API 以 `NODE_ENV=test AI_PROVIDER=fake` 启动，服务端 `DATABASE_URL` 指向验收库，`WEB_ORIGIN` 与 `NEXT_PUBLIC_API_ORIGIN` 使用同一浏览器主机名和各自端口。

开发集、留出集以及逐项质量评分另见[开发集报告](development.md)、[留出集报告](holdout.md)、[质量抽查](quality.md)。
