## 销售流程

1. 赵晨打开“今天待跟进”，看到远山科技和青禾零售。远山的昨日与今日待办都存在，客户只占一行。分别在两个独立登录会话保存、读取“本人负责 + 报价或谈判 + 金额大于 10 万”的个人视图，记录和 280 像素的客户名称列宽一致。将匹配关系改为“任一”后，结果增加到三位客户。[组合条件](a-filter-panel.png) · [独立浏览器](a-second-browser.png) · [任一条件](a-personal-any.png)
2. 管理员创建“本人负责的客户”共享视图，赵晨和钱宇分别登录后看到各自名下客户，两人的字段选择器都没有被隐藏的所属行业。[赵晨](a-shared-employee-a.png) · [钱宇](a-shared-employee-b.png) · [手机](a-after-390.png)
3. 在远山科技的行菜单粘贴“预算还没批，下周再联系”。建议时间是 Asia/Shanghai 下周一（11 月 23 日）09:00。销售将日期改为周三（11 月 25 日）09:00，编辑纪要与标题后确认，同一个卡片立即显示两项实际保存的内容。列表摘要更新，主线沟通抽屉同时显示本次纪要与移植前已有的采购沟通。完整详情的跟进和动态页签分别显示新条目。[建议草稿](main-editable-draft.png) · [保存回显](main-confirmed.png)
4. 详情入口模拟 provider 不可用，原文保留，点击“直接存为纪要”后追加一次活动。包含三个字段的另一段原话只产生两个可编辑字段建议。员工直接提交修改只读联系电话时，服务端拒绝并保留原值。两项合法字段一起确认，记录版本只增加 1。[原文回退](main-fallback.png) · [字段选择](main-field-proposals.png)
5. 在青禾零售确认时，测试代理发送非法跟进日期，服务端先保存纪要。界面重试只发送待办。成功响应丢失后，Web 自动重读保存结果，并核对本次实际只新增一条活动和一条跟进。[部分成功](c-partial.png) · [断线恢复](c-recovered.png)
6. 管理员审计列表核对了纪要、周三待办、手工纪要、字段更新和拒绝记录的五个编号。周三待办审计为 `01a20269-aa67-7cce-a78f-7214b59ebb92`，纪要为 `01a20269-aa2d-76e1-a888-dcd6652ec7d7`。HTTP 回归另外验证管理员删除纪要后，普通员工复读草稿或重试都不会恢复已删除的历史。[公司审计](main-audit.png)
7. 管理员在“今天待跟进”看到本人 0 条，将跟进负责人切到“任何人”后看到 3 个有到期待办的客户。超出金额条件的查询返回空结果，点击“清除条件”后恢复可见记录。在洛杉矶时区的浏览器中，下次跟进仍显示公司时区的日期与时间。[团队到期](main-team-due.png) · [无匹配结果](main-no-results.png)
8. 从本机旧方案导入两条个人视图，无法转换的方案保留在本机并显示原因；重试后两条成功视图的 ID 保持一致。[本机方案导入](main-import.png)
9. 用主线沟通抽屉手工追加“采购负责人确认周三 09:00 接听回访，届时同步预算审批进展。”，在同一客户行直接看到更新后的摘要。390 像素宽的手机实测在搜索框输入“远山”，结果从两位客户收窄到一位，页面没有横向溢出。[桌面工作视图](sales-demo.png) · [手机工作视图](sales-mobile.png)

## 主线权限回归

另建“小组回访核验”业务表。组长孙悦默认只看本人负责的云桥，选择本组多出明川，按组员李昂筛选仅看到明川。组外周岚直接读取他人记录或生成他人草稿收到 404，导出受限表收到 403。修改只创建字段收到 403，伪造草稿确认收到 FAILED 并有独立审计，复读仍为版本 1 与原字段值。浏览器中同组可修改字段只显示“跟进内容”。[组长本人](main-group-mine.png) · [本组](main-group-selector.png) · [指定成员](main-group-member.png) · [同组草稿](main-group-peer-draft.png) · [只创建字段](main-group-create-only.png)
