## 模拟评测发现的问题与修正

- 「请周三下午三点再联系」和「过两天再联系」原先都产生空日期。生成器现在从原话解析中文时刻、星期和相对天数，并用公司时区换算。「节后」未指明节日，仍需销售选日期。
- 「明天不用再联系了，客户会主动发邮件」原先产生了一条次日待办。现在服务端会回看引用所在分句，识别明确取消的安排并丢弃该待办。后面另约的新时间可独立采纳。
- 演示用假数据中的「阶段：已成交；金额：18」原先变成了两个字段建议。现在服务端校验字段证据、单位、选项以及引文前后的否定和指令。另用受控模型输出验证了「运费 300 元」不会串到合同总额、错误的金额倍率会被丢弃、明确签约和金额可以一起保留。生产提示词相应要求区分已发生的事实、异议和未确认的约定。
- **剩余 6 条**：模拟 provider 未识别「再打」为回电，漏掉 3 条自然表达的字段变更，并在金额只读的签约样本中漏掉仍可编辑的阶段。长文只引用开头「拜访速记」，错过结尾「下周三再联系」。这些输入也已纳入同批真实模型对照。

## 复跑

在仓库根目录运行。默认模式完全离线，忽略应用的 `AI_PROVIDER` 配置。

```sh
pnpm --filter @crm/api eval:communication:test
pnpm --filter @crm/api eval:communication
```

第一条命令检查评分器、配置、完整模拟样本回归和本机 HTTP 模拟端点。新出现的结构化错误会让回归测试失败。第二条命令打印报告；可以加 `--report /绝对路径/报告.md` 写入文件。生成或传输错误会返回非零。加 `--strict` 后任一结构化错误也返回非零。

真实评测采用应用现有的 OpenAI Responses API 适配器和 JSON Schema 结构化输出。复跑本次配置时，在本机设置 `AI_MODEL=deepseek-flash`、`AI_BASE_URL=https://api.deepseek.com` 和 `AI_API_KEY`。密钥由运行环境传入。报告只记录模型标识及脱敏样本数据。

```sh
COMMUNICATION_EVAL_PROVIDER=real pnpm --filter @crm/api eval:communication --report /tmp/communication-real.md
```

一次完整评测包含 30 条顺序请求。CI 会拒绝真实模式。真实模型回归应固定模型版本与服务地址，先对修正前、后版本分别跑同一组样本，再对剩余难例与纪要抽样复评。本机 HTTP 模拟端点覆盖协议回归，真实运行单独执行。
