# 记录列表最近沟通与动态抽屉

日期：2026-11-10。基线 `ee0a1c2`，分支 `codex/record-activity-preview`。本轮仅本地开发、测试，没有部署、迁移生产数据库或修改公司现有数据及权限。

## 使用方式

1. 打开任意已发布业务表，列表默认显示「最近沟通」：类型、结果、最多两行内容、填写人和时间。没有记录显示「暂无沟通记录」。
2. 点击摘要，右侧打开「沟通动态」。可以持续加载更早记录，不再只能看到前 20 条。拥有该记录修改权限的人可追加；已有历史仍不可编辑。
3. 关闭抽屉不跳转页面，不更改当前筛选、分页、排序和列表滚动位置。追加成功刷新列表摘要；未保存内容关闭前确认，临时后台刷新失败保留草稿。
4. 点击列表右上角「显示」，可以开关负责人、最近沟通、最近更新，用拖动把手或上下箭头调整与普通字段的混合顺序。设置按本浏览器、公司、成员、业务表隔离，不需要发布。本人范围下不可用的负责人列仍不提供。
5. 隐藏摘要列后，每行「… → 查看动态」仍能打开同一个抽屉。

业务编号保持显示；行选择框和行操作位置固定。普通字段的隐藏、停用及列权限仍照常执行。

## 数据与权限

- 复用 `record_activities`，不增加业务字段、不复制正文、不新增数据库表或迁移。
- 列表 `latestActivity` 只包含 CALL / MESSAGE / MEETING / NOTE 中最新的一条，与现有活动历史范围一致。内部事件不覆盖最近沟通。
- 在业务表已发布状态、租户、记录读取范围校验后，从当前可读页的记录 ID 一次批量查询摘要。使用参数化 `unnest + LATERAL LIMIT 1` 与现有 tenant / record / created_at 索引；不会为 1000 行发 1000 个请求。
- 摘要正文最多返回 240 个字符；抽屉读取完整正文。历史接口仍为分页请求，前端增加「加载更多动态」和失败重试，并对已加载 ID 去重。
- 员工公共池预览不展示原有沟通历史；管理员和已领取记录沿用原权限。只读成员能读不能写；按组开放字段编辑不自动扩大追加动态权限。
- 活动正文是独立的自由文本。隐藏手机号字段不会自动脱敏员工曾写在动态中的号码。
- 「最近更新」仍是业务记录更新时间，「最近沟通」显示活动时间；本轮没有改变记录更新时间或工作统计口径。

## 本地环境边界

- HTTP 集成测试库：`crm_activity_test`；浏览器演示库：`crm_activity_browser_test`，均位于本机 57361 端口的隔离 PostgreSQL。
- 网页预览：`http://activity.localhost:3790`；API：3791。使用专用测试成员与 Cookie 域，未切换其他本地应用的登录状态。
- 准备浏览器库时第一次迁移命令只传入了 DATABASE_URL，而 Prisma 配置使用 DATABASE_ADMIN_URL，因此给本工作树原有的本地测试库 `crm_member_transfer_test_1` 补用了已有的 0047 迁移。发现后改用明确的 DATABASE_ADMIN_URL 初始化专用库。没有生产连接、数据清空或公司数据写入。
