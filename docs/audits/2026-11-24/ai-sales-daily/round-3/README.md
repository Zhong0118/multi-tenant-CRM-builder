## 今日建议

校验同时检查标题、说明的长度和引用事实。任一未通过，该项展示通用动作。退回比例以展示项计，不含因候选编号或事实引用非法而被整项丢弃的输出。

- 开发集 2/93 项退回（2.2%），91 项保留标题与行动说明。
- 留出集 0/44 项退回，44 项保留标题与行动说明。

调提示词前，关闭推理的同一开发集有 25/100 项回退。最终版将内部优先级与可引用的业务事实分开，要求标题和说明都沿用本条事实中的业务对象。生产与评测共用候选输入构造，评测加载器也移除了原来拼进业务事实的英文样本分类。使用同一批旧输出分别按两种夹具复评，回退均为 25/100。最终两组允许模型每次选 3–5 项，因此展示项总数会变化。

另用浏览器实测 26 条候选。此前三次调用均用满 5,400 个输出 token，发生长度截断。最终版只在官方 DeepSeek Responses 的 deepseek-flash 上为今日建议关闭推理。一次端到端调用用时 3.004 秒，输入 1,647、输出 180 token，共选出三项，两项保留，另一项退回。其标题「协助同事回访」有依据，但说明使用了未引用的「协作客户」。回退率 1/3，单列于评测集之外。可查看[同批候选对照和截图](../browser/README.md)。

## 输出质量和失败口径

- 抽查的拜访提纲里，销售要问的问题逐条来自这次拜访的上下文。三份示例均缺乏明确要求销售携带材料的事实，因此最后一栏留空。玉浦钢构的目的用了报价占位符，销售仍需自行明确本次要核对的报价事项。
- 写作开发集有 3 次、留出集有 1 次明确返回长度截断。未交付残缺草稿。另外 3 封成功生成的邮件不满足正文段数要求，分别计为语义评测失败。样本修订前后的通过率使用了不同的评分要求。36 份成功返回的原始写作响应均用最终校验器离线复评，输出正文逐字相同。
- 核对原文后，开发集有 11/101 句和返回文本无法逐字匹配，7 句是拜访事实改为逐字引用来源、句末句号随原始记录省略，真正被删除或替换的是 4/101。留出集唯一的字面差异同样来自源记录句末标点，实质修改 0/32。实际归属与数字、承诺的校验继续生效。
- 另测官方 Responses 关闭写作推理，开发集 p50 1.49 秒、p95 3.06 秒，只有 18/30 条完全通过，7 份拜访调用没有取得可评分正文。本分支继续使用原来的写作配置，独立试验不进入上表。[DeepSeek Responses 参数](https://api-docs.deepseek.com/api/create-response/)
- 日报开发样本 1 首次返回 SDK 调用故障，无可进一步定位的安全原因。单独复跑在 2.45 秒通过，保留首轮 14/15。三项的真实评测均使用各自的正式输出上限。历史阶段 A 的三次 SDK 异常没有保存结束原因；新的诊断在 SDK 抛出异常时也保留安全的结束原因，长度截断分类为 INCOMPLETE_OUTPUT。

上表的短消息 6/6 均在 1–3 句内，只计算有完整返回的短消息。销售试用时可重点看读起来是否自然，例如上方今日建议中的「联系联系人」仍显重复。销售人员尚未为本轮文案打分。

## 业务校验复核

| 场景 | 复核方法及本次修正 |
| --- | --- |
| 同屏两条记录各有不同事项 | 构造 A「补发产品目录」、B「股权收购」。A 的返回文案串用 B 的事项时，服务端改用通用文案。缓存也校验当时发给模型的整批可见资料指纹。 |
| 客户准备审计报告 | 「客户正在准备」不构成销售要携带的材料。只有来源明确指向销售要带或准备的材料才进入该栏。 |
| 中性角色被改成某一方 | 对没有归属的「财务」补写「替我司核对」会被校验剔除，包含否定语句和第三方归属的场景均有回归用例。 |
| 拜访目的使用第一人称 | 「我想了解进度」在内部提纲的目的栏被拒绝。评测也对原始回答的人称和请求句计分。 |
| 模型返回空提纲 | 有事实时，销售仍可看到有来源的情况和对应追问。评测同时检查模型原始输出，空回答记失败。 |

这些测试覆盖复核中实际出现的句式。对新措辞的事实归属仍需通过真实样本和销售试用继续检验。留出样本的期望沿用冻结版本，本轮为重复运行，分数用于回归参考。
