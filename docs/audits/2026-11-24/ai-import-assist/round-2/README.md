## 影响交付的问题

- 新留出集关闭推理后，两个宽表分别命中 4/4、3/3 个可导入行。但 h12 第 2 至 4 行把「Next follow-up date」导向了「拜访日期」，正确来源是另一列「Visit date」。三行均通过 dryRun，三处新错值逐行列在新留出报告。
- 新留出 h18、h19 的客户等级分别有 50、51 个不同原词。关闭推理时，仍有 47、48 行在本地转换时失败。对上了「客户等级」这一列，仅能解决列名；缺少逐值的合法选项或明确的「不对应」，转换仍会拦下这些行。
- 原开发集 d15 和 d16 各有五个物理数据行。直接用生产文件解析器读原件、用标准映射调用数值转换器，实测两份文件各有 120 个字面值 `NaN`，分布在全部五行。标准答案把这些数值格视为空，标注上限分别为 5 行、4 行。正式分数保留原分母，本轮未改冻结标注或数值校验。
- 默认推理在各组的全部调用 p95 均超过 20 秒。关闭推理的时延在三组都达标，但新留出集的错配率为 6/116，高把握错配 1/40，均超过门槛。
- 模型入口的隐私哨兵均为零，权限拒绝和干运行无写入检查通过。新留出的注入配对两种模式均通过。开发集默认推理在相同投影输入下返回不同建议；旧参考组两种模式均未通过配对一致性，旧参考组的两份投影输入摘要也不同。完整注入门槛保留为未通过。
