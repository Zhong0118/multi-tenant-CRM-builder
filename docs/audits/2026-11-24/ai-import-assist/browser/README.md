# AI 导入浏览器验收

2026-11-24，使用 T3 无痕预览、真实 Nest API 与 PostgreSQL 18。刘洋在单字段合成表上使用 DeepSeek 返回的建议，将开发集派生文件的可导入行数从 0/5 提升至 5/5。模型将这项建议标为「把握不大」，须人工点击「采用」才获得提升。5 条记录均已确认写入。

独立数据库 `crm_pr2_browser_audit` 位于 127.0.0.1:56250。前端使用 4270，API 使用 4271。应用迁移至 0062，通过项目 demo 种子创建星云科技演示公司、成员及初始 96 条业务记录。默认套餐先用于验证未开通状态，随后在该库给公司分配仅含 `import_assist` 的专用套餐。截图文件名标识 CSS 视口宽度，分别为 1440 × 900 和 1280 × 800。

## 一次独立的真实模型场景

使用开发集 [d03-synonyms.xlsx](../../../../../apps/api/test/evals/import-assist/fixtures/development/d03-synonyms.xlsx)。保留三个源列、五个数据行和工作表，只给 A2 至 A6 的客户名加「验收-」前缀。原件 SHA-256 为 `b0ac1c92cf69fbb184e6833892a412185bb0918064541caf4a38d32d4aa9fd5a`，此次上传文件为 `60ed88c523fd08b88da5902f7dddfccd7b48372842c3583825ef26ce178262eb`。它是浏览器场景的派生文件，冻结开发集另行计分。

用项目的发布测试夹具创建「验收-合成客户表」，仅含必填文本字段「客户名称」，无受限字段。在发送范围里取消 C2 客商代码和 C3 签单与否。先通过相同文件、相同身份和选择截获模拟 provider 收包，再对真实 HTTP 请求中的用户提示逐项比较一致性，放行目标仅为 DeepSeek 官方 HTTPS Responses 端点。最终字段字典只有 F1 客户名称，源列只有 C1 单位名称，样例、取值、选项三个数组均为空。本次生成使用本机环境凭据。[发送范围与必填提示](10-real-rule-scope-1440.png)

| 同一文件的操作 | READY / 全部 | 结果 |
| --- | ---: | --- |
| 纯规则 | 0/5 | 界面因缺少必填映射而禁用检查。使用同一会话向正式导入接口提交 dryRun，保留原行号 2–6 与规则产生的空取值，每行都返回 FIELD_REQUIRED。 |
| DeepSeek 自动预选 | 0/5 | 模型建议「单位名称 → 客户名称」，标「把握不大」，未自动采用，必填提示仍在。[真实回包后的界面](12-real-review-1440.png) |
| 人工采用后点「检查数据」 | 5/5 | 重复、主动跳过、错误各 0。正式确认之前全库 98 条，与真实场景开始前相同。[检查结果](13-real-ready-1280.png) |
| 确认导入 | 5/5 写入 | 页面显示成功 5、跳过 0、失败 0，数据库核对五个名称及编号。[1440](14-real-imported-1440.png)、[1280](14-real-imported-1280.png) |

首次运行时系统 DNS 将官方域名解析到 198.18.1.90，产品的公网地址校验对该解析返回 NON_PUBLIC_ENDPOINT。界面显示服务暂不可用，草稿保留。该次计量 failed，耗时 0.047 秒，账本记录的输入 3404、输出 4000 均标记为估算。[失败界面](11-real-first-attempt-1280.png)

随后重建测试进程和抽屉，重新上传相同字节，使用本机既有公开 DNS 解析脚本。产品继续执行公网地址检查、TLS 与同一出站内容检查。重建后的运行仅点击一次生成；deepseek-flash 成功，计量耗时 5.446 秒，输入 918、输出 406 token，两项均为提供方实际用量。
