# 模拟预览质量抽查

评分人是 Codex 模型。根据冻结的业务描述和实际预览逐项阅读，没有真人参与评分。定向抽取租赁完整预览、内置能力、明确要求的选项、英文字段与合理追问，样本分数不外推为全数据集均分。

每一维度 0–2 分。方案划分看实体是否覆盖所需业务且职责清楚。字段实用性看识别记录、关键类型和办理业务所需信息是否充分。选项贴合度看选项个数、语义和单选或多选是否符合场景。0 表示缺失或错误，1 表示部分可用，2 表示满足所审请求。业务无需选项时记「不适用」。明确需求被追问时，所有原本可评的维度记 0；预期首轮即追问的用例单列。

| 样本 | 方案划分 | 字段实用性 | 选项贴合度 | 依据 |
| --- | ---: | ---: | ---: | --- |
| dev-01 | 2 | 2 | 2 | 客户、合同、设备、回款分开记录。合同有租金与到期日，设备的可租、已出租、维修中便于判断可用性。字面评分将「合同」与「租赁合同」判为不匹配，金额字段还命名为「租金」。 |
| dev-08 | 0 | 0 | 0 | 招聘业务已指定职位名称与工作模式。系统仍询问行业，没有返回现场、混合、远程三个选项。 |
| dev-14 | 2 | 1 | 不适用 | 客户表有联系方式，负责人已说明使用平台能力。未采纳清单写作「跟进记录」，未指明原文要求的下次跟进日期。 |
| holdout-02 | 0 | 0 | 0 | 美术班已说明试听预约的标题、电话、三个可多选时段和围裙标记，实际返回行业问题。 |
| holdout-04 | 0 | 0 | 不适用 | 生成的是 Customers。邮件字段绑定到客户，预期的包裹名称、报关金额和关联买家说明均缺失。 |
| holdout-09 | 不适用 | 不适用 | 不适用 | 描述中没有明确行业或清单实体。首轮询问行业符合预期。 |

逐条生成结果包括原始模型候选、服务端返回、拒绝原因、未采纳项和最终准入状态。[完整轨迹](./fake-traces.json) · [分集指标](./fake-evaluation.md)

在仓库根目录复现模拟结果。

```sh
pnpm --filter @crm/contracts --filter @crm/database build
pnpm --filter @crm/api eval:table-builder:test
pnpm --filter @crm/api eval:table-builder --report ../../docs/audits/2026-11-23/ai-table-builder/fake-evaluation.md --trace ../../docs/audits/2026-11-23/ai-table-builder/fake-traces.json
```

指定 `--dataset development` 或 `--dataset holdout` 可单独运行一个数据集。模型调用或执行故障、最终权限或内置能力违规、确认复验失败、伪造请求进入持久化路径时退出码非零。`--strict` 另要求每个样本质量指标均通过。

真实模型由本机显式配置 `TABLE_BUILDER_EVAL_PROVIDER=real`、`AI_MODEL` 和 `AI_API_KEY`。可用 `AI_BASE_URL` 指定兼容端点。将真实评测写入独立的报告与轨迹文件。
