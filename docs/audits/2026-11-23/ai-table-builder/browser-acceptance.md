# AI 建表浏览器验收

2026-11-23，使用 1440 × 900 Chromium、fake provider、本地 HTTP 服务和独立 PostgreSQL 数据库 `crm_test_builder_qa`。刘洋以公司管理员身份操作，赵晨以员工身份操作。写入限于 `builder-qa`。

| 场景 | 操作与实际结果 |
| --- | --- |
| 设备租赁建表 | 刘洋从空工作台进入「用 AI 描述生成」，输入设备租赁，管理客户、合同、设备、回款，并要求销售只能看自己的客户。预览生成四张表，分别有 3、5、3、3 个字段。「销售只能看自己的记录」留作待配置意图。 |
| 单表调整、授权与发布 | 移除回款表，选合同，要求「添加签约日期，删除备注」。检查差异并采用后，保存客户、合同和设备三张草稿。发布分析阻止隐藏的必填标题。刘洋在现有员工权限编辑器逐表将标题设为可编辑，仅对客户开启新建及查看，查看范围选「仅本人负责」。重新分析后，三表均预计发布 v1，单击「确认发布 3 张表」。赵晨的导航仅出现客户。赵晨在新建表单填写「设备租赁验收客户」并进入记录详情，记录 ID 为 `d40bd5c1-303d-4852-b917-b8625711ca99`。 |
| 模糊需求 | 仅输入「建表」，先选行业「设备租赁」，再选主要资料「客户」。第二次回答后出现一张客户表和三个字段。 |
| 公式与关联 | 请求合同、毛利公式、关联客户和附件。「已内置／未采纳」列出三项，分别建议手工录入金额、使用记录关联和记录附件区。 |
| 已有表重名 | 已创建客户草稿后输入「只管理客户」。对应表显示「业务表名称或编码已占用」，确认按钮禁用。 |
| 第三张写入失败 | 独立验收库临时触发器仅在 `builder-qa` 写入第三张表「设备」时抛出异常。刘洋在浏览器确认，收到服务错误及请求编号 `28066ce3-02fa-4e74-a1d2-58e38fc466bc`，三表预览保留。直接用 SQL 对比前后，业务表、字段、视图、对象权限、字段权限、租户审计的行数均为 0。删除触发器及函数并核对后，直接重试同一页面成功。 |
| 为已发布表补字段 | 刘洋在客户设计器选择「用 AI 补充字段」。客户名称、联系电话和电子邮箱只读，确认新增来源、行业和规模。读取草稿显示六个字段，三个新增字段对员工均为 HIDDEN。再次读取客户运行时结构，仍为发布 v1 的三个原字段。 |
| 员工边界、名单与权限输入 | 发布前赵晨的工作台无建表入口，可用表接口返回空数组。直接访问建表地址显示无权访问页。以赵晨的浏览器会话逐一调用 preview、validate、refine、confirm，均返回 403。刘洋尝试在合法预览的确认体附加 employeeAccess，HTTP 400，后续发布分析仍显示三张原草稿的隐藏字段。 |
| 模型不可用 | 输入「模拟服务不可用」，重新生成时收到 AI 服务错误及请求编号。输入框保留原文，上次预览仍在；点「手动建表」并确认离开后，进入同租户的新建表单。 |

首次联调发现选项投影夹带手动配置不支持的 sortOrder，导致含单选字段的合同和设备出现阻塞。修复并重启 API 后，重新从设备租赁原文生成了上述可确认预览。
