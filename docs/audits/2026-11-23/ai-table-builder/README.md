# AI 建表本地试用

审阅修复后的 DeepSeek 开发集为 18/20，冻结留出集为 9/10。分表数耗时、两条调用故障、权限预设和最终验证见[复测报告](./review-retest/README.md)。

[打开空租户的 AI 建表页](http://builder.localhost:54910/workspace/builder-trial/settings/objects/ai-builder)。管理员刘洋使用演示账号 18800001002。设备租赁演示原话为「我们做工程设备租赁，要管客户、租赁合同、设备台账和回款，销售只能看自己的客户」。初次浏览器验收使用 fake provider。选择「确认创建草稿」之后，可以到权限编辑器给员工授权，再做发布分析并发布。

最终构建启动后，在空租户实际验证了登录、管理页访问和上述四表预览。试用租户已有草稿数为零。九个浏览器场景在另一租户完成，含人为制造第三张表失败、检查表与审计均回滚、管理员手动授权以及员工成功建记录。[详细验收与五张截图](browser-acceptance.md)

一次全量 E2E 执行中 PostgreSQL 停止，连接返回 57P01。恢复同一实例后从头重跑，全量 438 项通过。边界回归包含 6 张表、每张 40 字段的大批次，超过原 100 KiB 请求大小的编辑／确认，以及给尚未配置完毕的手动草稿补字段。

**模型效果。** 模拟开发集完整命中 1/20，冻结留出集 1/10。两组分别有 4 和 1 份可确认方案，全部通过业务复验。其余样本包含固定能力范围之外的请求，模拟器经常返回追问。三类伪造权限请求均被拒绝，随后单独用 DeepSeek 完成了试用和两组各一次的评测，开发集 16/20、留出集 8/10。[真实模型试用与失败原因](deepseek-trial.md)。[分集评测](fake-evaluation.md) · [抽查方法与结果](fake-quality-review.md)
