## 管理员试用

刘洋在空租户输入了以下业务描述。

> 我们做独立乐器维修，只需要维修工单和备件采购两张表。维修工单记录工单名称、来电号码、收件日期和故障说明。备件采购记录采购单名称、供应商、采购金额和预计到货日期。

| 预览表 | 浏览器中显示的字段和类型 |
| --- | --- |
| 维修工单 | 工单名称（文本）、来电号码（电话）、收件日期（日期）、故障说明（长文本） |
| 备件采购 | 采购单名称（文本）、供应商（文本）、采购金额（金额）、预计到货日期（日期） |

| 集合与样本 | 用户要求 | 实际结果与失败原因 |
| --- | --- | --- |
| 开发 dev-10 | 维修表自动计算含税费用 | 已说明公式不受支持，但仍创建了同名的手填金额字段。 |
| 开发 dev-11 | 报价关联客户记录 | 已说明应使用记录关联，但仍创建了「对应客户」文本字段，文本不能建立关联。 |
| 开发 dev-15 | 保留「排班」原名，即使同名 | 期望看到重名冲突。模型要求补充信息，页面返回行业追问，没有进入重名检查。 |
| 开发 dev-18 | 交代七个实体，由管理员选择 | 模型识别出全部七个实体及六表上限，却只返回追问。页面询问行业，没有展示候选表。 |
| 留出 holdout-08 | 招聘七表，优先前六张 | 模型原始输出已列出用户指定的前六张，但仍要求再确认。最终页面询问行业，六张表均未进入预览。 |
| 留出 holdout-10 | 预计毛利随报价与成本自动更新 | 已说明无法自动计算，仍保留「预计毛利」为手填金额，与用户明确的「员工不用手填」冲突。 |
