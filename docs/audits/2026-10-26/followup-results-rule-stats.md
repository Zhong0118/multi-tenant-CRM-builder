## 跟进完成结果

- 在记录详情或“跟进待办”点击“完成”，填写活动类型、实际沟通结果及完成说明；保存后，任务完成与活动追加处于同一个事务。
- 电话、微信/消息、拜访、备注复用现有活动类型。电话接通、微信已沟通/新加上微信、已见面属于明确联系成功；没有填写结果、未接通、未回复或备注不推断联系成功。
- 待联系客户明确联系成功后进入跟进私域；已在跟进私域的有内容活动按配置续期。普通编辑、未来待办及仅标记任务完成不算活动。成交保护不重新增加到期时间。
- 询单仍是管理员配置的业务字段，由员工在明确需求或询价后标记，不由完成任务自动推断，更不代表成交。
- 已完成任务展示结果、实际记录人和公司时区时间；旧任务没有结果时保持空值，不补造历史活动。新界面要求结果说明，旧 API 客户端不传结果仍可按原方式完成。
- 同租户、同记录的活动关联由数据库约束保证，一条结果活动只能关联一个任务；版本冲突、权限变化及已到期租约不会部分保存。

迁移 `0039_follow_up_completion_results` 仅增加可空关联列及约束，复用现有活动表，无新数据库、无新服务、无历史回填。以后部署应先备份，再应用迁移；旧应用回滚可保留这个新增列，不需要删除结果数据。

## 规则执行统计

公司管理员进入“设置 → 业务表 → 选择业务表 → 跨表自动化 → 执行统计”。可切换近 7/30/90 天，查看每条规则的成功、失败、已记录去重及明细；明细支持状态筛选、上一页/下一页、来源和目标记录链接。

- 成功取自已提交的跨表执行记录；失败取自已有失败审计；本轮新增对重复请求/自动触发去重的审计，不重复开单。
- 统计仅覆盖已留存的执行与审计记录。鉴权、DTO 校验等执行前拒绝不等于规则执行失败；早期没有记录的去重不补算。未新增成功率或推测指标。
- 时间窗口为最近 N × 24 小时，公司时区仅用于显示。窗口内晚提交事务可以增加统计，刷新后重新查看最新记录。
- 明细每页 20 条，使用时间、ID、状态游标；COUNT 和明细在同一 SQL 快照读取。跨租户、规则、状态或窗口复用游标被拒绝。晚提交不会把上一页末尾重复推到下一页。
- 员工不可访问管理统计；停用或删除记录不会让历史统计丢失，已不可打开的记录只显示历史标识。错误只显示受控错误码及说明，不回传执行输入或堆栈。

## 复核中实际修复的问题

1. 管理员替员工完成跟进与员工确认联系并发时，原先的成员/记录加锁次序会互相等待。先按固定顺序锁定操作者和观察到的负责人，再锁表与记录，并复核负责人未变化；真实并发测试覆盖跟进结果和直接追加联系活动。
2. 完成请求已提交但响应丢失，重试得到版本冲突时，界面原先不能确认结果已保存。现按任务版本及完整结果核对服务端；匹配才恢复成功，不匹配保留草稿。提交成功后的刷新重试只读，不再次追加活动。
3. 固定结束时间加 OFFSET 分页仍会受晚提交事务影响，造成跨页重复。现使用范围绑定游标及同语句 COUNT，真实延迟提交测试证明原有记录不重复、不漏项。

## 操作示例

1. 管理员确认客户表已开启分段公海，跟进期限为 30 天；确认询单字段、客户到合同自动化、合同签约保护规则已发布。已有配置无需重复创建。
2. 新建客户，负责人留空；员工到“线索公海”，在该行“更多操作”中领取。
3. 打开客户，在“跟进”安排一项待办。实际打完电话后点击“完成”，选择“电话 / 已接通”，填写沟通内容，点击“保存并完成”。在“已完成”和“动态”均能核对同一结果。
4. 客户明确提出需求后，编辑“业务进度”为“询单中”。这不会停止回收；继续登记实际跟进结果即可按期限续期。
5. 在“自动化”执行已发布的“生成开单”，填合同编号、金额及拟定状态，先预览再创建并关联。拟定合同不会直接保护客户。
6. 管理员到合同记录执行“确认签约”。返回客户，应显示成交保护状态且不再显示回收倒计时。
7. 管理员按上述入口打开“执行统计”，核对成功次数、来源/目标链接及失败说明。已记录去重表示请求被识别为重复，不代表又创建了一条记录。

员工目标提醒与完整流程模板继承不在本轮实现范围；不因这两个功能完成而声称它们已经完成。
