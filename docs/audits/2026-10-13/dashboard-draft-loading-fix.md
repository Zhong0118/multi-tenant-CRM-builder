# 工作台草稿重新打开失败

2026-10-13

## 故障

公司管理员进入 `/workspace/<公司代码>/settings/dashboards/home`，页面显示未加载。Web 日志为 `Invalid dashboard response`；同一时段工作台配置 API GET 返回 200，并非路由不存在或后端服务停止。

线上已保存草稿的排行组件 `objectCode` 为空。后端允许暂存尚未选择业务表的组件，并在预览、发布时报告配置问题；前端读取草稿却将空字符串作为无效响应，导致整个设置页崩溃。该解析器也处理保存、复制的响应，因此会出现后端已保存、前端却显示失败，接着使用旧版本重试又收到 409 的连锁现象。

这与上一轮数据库 RLS 错误是两处独立缺陷。服务器日志证实 RLS 修复后出现了成功保存 200 和发布 201。

## 修复范围

仅在工作台草稿的可编辑文本位置允许空字符串：标题、组件标题、业务表绑定、分组字段、日期字段、排序字段和筛选字段。非字符串仍拒绝；已发布运行时数据仍保留非空绑定校验。不删除用户草稿、不代选字段、不取消发布检查。

五种组件均增加未完成草稿回读测试，同时验证保存/复制共用的 parseDraft。修改前五组测试失败，修改后通过。

## 本地验证

- 工作台及模板草稿相关测试：7 文件、62 项通过。
- 前端类型检查、修改文件 ESLint、Prettier 检查通过。
- 真实浏览器使用普通公司管理员，将线上故障草稿保存至本地独立测试工作台：保存 200，重新打开显示编辑器，没有“页面未加载”。
- 公司首页、设置页、旧 settings/dashboard 跳转、新 settings/dashboards/home、指定工作台、成员、跟进、AI 入口均可访问，未观察到同类加载失败。旧入口正确跳转到新入口。
- 仓库未检出拼错的 `settings/dashboads` 链接；正确单词为 `dashboards`。

上述检查聚焦工作台草稿及相邻入口，不代表全系统所有业务流程都已重新验收。
