## 两项优先缺陷

| 问题                    | 修复                                                                                               | 验证                                                                             |
| ----------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 创建公司返回 500        | 21 个模型 ID 改由数据库函数 `crm_uuid_v7()` 生成，迁移 0016 给表列补真实 DEFAULT；现存 ID 保持原值 | 普通 Node/Prisma 与 SQL 均不传 ID 创建成功；真实 API 创建→纠错→接受邀请→启用通过 |
| 接受与撤销/重发邀请竞态 | 状态变更限定仍为 PENDING，接受邀请事务内加锁；竞争失败返回冲突，不能覆盖已接受状态                 | 独立 PostgreSQL 中确定性并发接受/撤销与接受/重发用例通过，邀请状态与成员结果一致 |

UUID 回归包含版本、格式、时间戳及批量唯一性检查。同毫秒内的 UUID 不保证严格单调顺序；业务连续编号继续使用已有独立机制。

## 本轮三角色交付

| 角色       | 新增能力与入口                                                                                | 边界                                                                                                 |
| ---------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 超级管理员 | 公司详情更正首管手机号；日志动作/资源中文说明与详情；数据库实际 SELECT 1、Redis PING 健康探测 | 首管纠错仅限未开通且没有有效管理员的公司；旧邀请撤销并审计。超级管理员不自动获得公司业务权限         |
| 公司管理员 | 成员名册角色升降、移交管理员、离职交接；侧栏公司审计                                          | 保护最后一名管理员；交接同一事务转移记录与 OPEN 待办后停用。审计接口按当前公司强制隔离，员工访问 403 |
| 员工       | 跟进事项转派；命名保存/应用/删除常用筛选；详情关联可见业务记录；附件上传、下载、删除          | 接收人须有效且有该记录权限；关联校验两侧访问权限；附件随记录权限执行，写入还需更新权限               |

管理员移交用于公司内部主动交接：接收人升为管理员，发起人降为员工。超级管理员的跨公司救援/代管仍未开放。

离职交接接收人目前限定为公司管理员，保证跨业务表资料转交后可访问。移交包括软删除记录的归属及所有未完成待办；普通停用遇到未交接业务会拒绝。写记录、转派、附件与关联操作会重检有效成员，避免停用过程中继续新增归属。

## 页面与使用方式

- 成员管理把升降角色、管理员移交和离职交接放在对应成员行，危险操作需在界面确认；服务端仍独立校验权限及最后管理员约束。
- 跟进事项显示接收人，管理员可查看当前记录的全部跟进，个人待办页继续只显示自己的任务。逾期仍采用“到期且未完成”的简单规则。
- 常用筛选按公司、成员、业务表隔离，保存在当前浏览器；账号切换清空选择和草稿，服务端渲染与客户端水合保持一致。
- 关联记录用业务表选择、搜索、可见记录选择完成；这是显式关联，尚无线索转客户等自动转换动作。
- 附件当前支持 PDF、PNG、JPEG、TXT、CSV、DOCX、XLSX；单个 5 MB、每记录 10 个、合计 25 MB。数据库持久保存，下载经过鉴权并强制附件响应，删除释放文件内容。未接对象存储、病毒扫描或在线预览；附件面板未与任意动态附件字段值联动。
- 继续沿用控件 8 px、卡片 12 px 圆角及柔和配色，详情新增面板保持相同间距。桌面成员表和公司审计已浏览器走查；记录附件/关联窄屏详情已检查。

## 升级与后续

本地已应用 0014（业务关联）、0015（附件）、0016（默认 UUID）。其他环境拉取后必须先备份并执行仓库既有迁移部署流程，再启动新代码；不要只更新前端。数据库附件会增加数据库和备份体积，正式扩大使用前应迁移到私有对象存储。
