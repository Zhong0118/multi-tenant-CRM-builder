# 批量分配与导入负责人验收

日期：2026-10-15。基于已部署版本 `0d3d854`，功能分支 `codex/import-bulk-assignment`。用户已授权同步 GitHub 和服务器，发布记录在部署后补充。

## 使用方式

- 业务表列表右侧选择每页 20 / 50 / 100 条，默认仍为 20 条。切换条数回到第一页，保留查询条件。
- 公司管理员勾选当前页记录，打开「更多操作 → 批量分配负责人」，选择本公司的有效成员并确认。最多选择当前页 100 条，不会自动选择其他页。
- 分配过程中显示成功、失败、未处理数量；重试只处理失败项。冲突项应关闭窗口，刷新列表后重新选择。已成功记录不会在同一窗口内重复分配。
- 分配沿用现有单条 ASSIGN 规则：移出公共池、更新负责人、按业务表配置重新计算到期时间；公共池关闭时暂停回收。
- 普通批量修改只修改业务字段，后端单次上限从 50 提升至 100 条。
- 「导入 Excel / CSV」新增「导入负责人」。管理员不选则保持未分配；员工不能指定他人，新增数据归自己。文件里的姓名不会自动绑定真实成员。
- 改变导入负责人后需要重新检查数据；开始实际导入后锁定选择。重复行跳过，保留原负责人和原期限。
- 文件总量仍为每工作表最多 10000 行，前端自动分批，不受列表每页 100 条限制。

## 实现边界

复用现有负责人、回收期限、归属变更接口及导入流程，无数据库迁移，无新依赖。浏览器检查没有执行对演示公司已有记录的分配或实际导入；写入验收使用独立本地测试数据库。

## 验证

- API 单元测试：102 个套件、1394 项通过；原有 1 个套件、3 项跳过。
- Web 全量测试：95 个文件、755 项通过；架构测试 3 项通过。其他工作区测试通过。
- HTTP/真实 PostgreSQL 集成：13 项通过，包括 100 条批量修改、101 条拒绝、指定负责人导入、重复保护、员工越权拒绝、禁用成员拒绝，以及成员集合不相交的并发创建/导入。
- 锁兼容性测试：旧代码稳定触发 lock_timeout，修改后通过。统一成员锁先于导入 advisory/counter 锁；业务表使用 FOR NO KEY UPDATE，允许新增记录外键检查的 KEY SHARE。
- API、Web 类型检查通过；其他 workspace 包的类型检查亦通过。
- 本次生产代码、集成测试和 Web 修改文件 ESLint 通过；前端生产构建通过。
- 浏览器 1440px / 390px 检查：分页选择更新 URL 为 limit=100；批量分配与导入负责人入口可打开；移动端列表无页面横向溢出，分配抽屉位于视口内。
- 定向审查指出的两处锁反转均已修复并复审确认。

发布前复跑发现 Supertest 并发请求会自动关闭共享临时服务器，出现间歇 501 / socket hang up。该测试套件改为显式启动一个服务，统一在结束时关闭；连续两次 13 项通过。生产服务启动方式未修改。

服务器部署结果另记；线上检查采用只读预检查，不对真实业务记录批量分配或新增数据。
