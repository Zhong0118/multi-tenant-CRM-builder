# 任务与日报业务统计验收

日期：2026-11-06。分支：`codex/configurable-work-statistics`。本轮仅本地开发和生产只读排查，未部署、未修改生产数据或成员权限。没有数据库迁移。

## 根因与实现

原“当天记录”的电话、微信、拜访等数字来源于动态登记，创建“通过表”或“询单表”记录不会自动写入这些活动。这是统计来源未关联，不能据此判断业务记录保存失败。

复用工作台已发布指标卡，新增“用于任务与日报”和创建人/当前负责人归属配置。员工日报按选定日期及本人归属查询；管理员团队动态沿用同一规则按成员汇总。保留原活动计数和每日目标提醒口径，不将业务指标混写为活动。

支持普通业务表，不要求公海；支持计数、金额求和和现有状态/布尔筛选。明确选择文本字段的“跟随工作台时段”后，复用列表的日期解析，不改变原字段类型。空白、无效及年月日含糊的日期不参与按日统计。

## 网页验收

在独立测试数据库和 3780/3781 临时服务中验收，未使用其他 agent 的数据：

1. 管理员打开工作台配置，修改业绩归属，保存并刷新：日报开关、归属、文本日期和布尔筛选保留。
2. 恢复按负责人归属并发布成功。
3. 员工任务与日报显示“新增微信 3”，管理员团队汇总同样为 3；人工活动计数保持 0，无重复登记。
4. 390px 手机宽度无横向溢出，业务指标与原工作记录分开展示。
5. 验收后关闭专属浏览器测试页、API/Web 进程及 `crm-work-statistics-test` 容器，移除临时会话文件。其他服务保持原状。

## 使用与边界

配置步骤参见 [工作台统计指南](../../guides/workbench-sales-metrics.md)。选择员工默认工作台的指标卡，勾选“用于任务与日报”，设置一个跟随时段的日期条件、业务条件和归属，保存并发布。

统计反映当前记录，非冻结绩效账本：转交负责人、修改状态/日期、删除记录都会影响结果。员工仍受当前数据和字段权限约束。每日目标提醒尚未接入这些自定义业务指标。本地功能完成不代表线上已启用；生产仍使用原统计逻辑。
