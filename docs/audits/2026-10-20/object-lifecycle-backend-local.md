# 整张业务表停用与恢复 — 后端本地验收

日期：2026-10-20。实施提交 `ae318f9`，并发与依赖补修 `eccfafe`。这两个提交没有推送或部署；生产仍为 `9136cdc`。

## 实际行为

复用 DRAFT / ACTIVE / ARCHIVED，不复制业务记录。公司管理员可检查、停用、恢复；操作校验公司、权限及版本并写入审计。恢复重新启用原发布快照，保留待发布草稿、成员权限和记录，不调用发布。

停用后配置只读，普通业务访问关闭。有权限的用户得到 OBJECT_ARCHIVED；无权限或跨公司访问不泄露业务表信息。工作台仅将对应组件标记不可用。来自其他已发布流程 CREATE_RECORD 动作、启用的公海保护规则的依赖会阻止停用，并返回具体来源。

恢复只顺延停用时尚未到期、非公共且有负责人的公海持有期限。已到期、永久保护、人工跟进截止日期保持原样。历史停用记录缺少停用时间时，必须确认保留原期限；不会猜测暂停时长。已成交保护不会因单纯停用/恢复或元数据保存被误清除；真实取消成交证据会标记待复核。

## 复核修复

独立后端审查发现并补修两项问题：

1. 请求先读到使用中，随后表被停用，旧请求仍可能提交。实际数据库事务现在先获取共享生命周期锁，再重新检查状态和权限；停用使用同一租户锁的独占模式。已进入的操作完成后才能停用；停用后的新操作被拒绝。记录、导入、流程、附件、关系、跟进及 AI 确认路径都覆盖。
2. 重新启用公共池时，省略保护规则参数可能跳过对保留规则的检查。现在合并实际生效配置后，在同一配置锁内验证依赖。

`ae318f9..eccfafe` 的独立限定范围复核确认两项均已解决，未发现新增问题。
