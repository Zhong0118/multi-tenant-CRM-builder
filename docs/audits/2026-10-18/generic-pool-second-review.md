# 通用公海第二轮复核与界面调整

日期：2026-10-18。本轮只修改本地，未提交、推送 GitHub 或部署服务器。

## 发现并修复的后端问题

1. **等待记录锁时跨过截止时间仍可续期或保护。** `statement_timestamp()` 固定为语句开始时间，不能代表拿到记录锁的时间。0030 改为锁后读取实际时间，活动续期及成交保护均拒绝已经过期的记录。真实 PostgreSQL 两项并发测试先失败、修复后通过。
2. **无关事件重新触发旧成交保护。** 管理员解除保护后，删除一条关联草稿、改其非成交状态、添加或移除无关关联，都会再次命中其他旧成交依据，导致操作失败或记录重新受保护。0031 区分新增有效依据与复核已有保护：只有来源新进入有效状态，或新建有效依据关联，才允许启动保护。五项回归先复现、后通过。
3. **配置变更与确认成交并发时，保护状态不一致。** 规则删除或来源归档和成交确认交错提交，会留下没有有效依据却未提示复核的受保护记录。0032 在读取规则/锁定目标记录前，以稳定顺序锁定相关业务表配置。配置先提交时不新建保护；成交先提交时保留保护并标记待复核。四项真实并发回归通过。

没有修改已应用的 0028/0029，也没有回填或重归类旧数据。三份新迁移只替换相关函数/事件逻辑，保留租户隔离、权限检查及事务回滚。复杂跨记录竞争仍可能由数据库回滚其中一个事务，不承诺任意请求都不会发生重试。

## 界面调整

方向：沿用现有白底与品牌青绿，让管理员明确区分当前生效规则、正在编辑的设置和保存动作。

- 公海设置抽屉在桌面扩展至 600px，手机适应屏幕宽度。
- 开关与名称左右对齐，补充简短用途说明。
- 联系期、跟进期并排分组，显示小时对应的天数；增加一行流转过程说明。
- 阶段名称和保护依据分区，未选择来源时不显示错误式警告。
- 保存与取消固定在底部，保存立即生效的说明保留。
- 阶段标签显示独立数量徽标，选中背景、边框、字重明确。
- 删除重复的顶部长警告，关闭时才显示暂停影响；提高辅助文字对比度。
- 保留抽屉进出动画，增加轻量的分组出现、选中颜色过渡和按钮按压反馈；遵循减少动态效果偏好。没有引入依赖或改变整体站点主题。

独立静态视觉评审一轮，不打分。修正了评审提出的辅助说明偏淡和手机介绍末尾单字换行。实际交互与滚动由主代理验证。
