# 业务日期排序与筛选：排查、修复与使用

## 结论与现状

2026-11-05 只读核对生产：运行版本为 `5159d11`。询单表的「日期」字段 `col_2` 为 TEXT，已发布默认排序是 `createdAt desc`。因此新导入的 2025 年记录会排到今天刚录入的记录前面，这不代表旧数据被覆盖。导入实现执行新建或跳过重复行，不更新匹配的原记录。

本轮修复位于隔离分支 `codex/record-date-sorting`，没有修改生产记录、字段配置或已发布版本，没有部署；电话 PR #70 未参与。

## 排序如何选择

| 规则 | 含义和用途 |
| --- | --- |
| 创建时间倒序 | 最近进入 CRM 的记录在前；导入旧资料也会在前 |
| 最近更新时间倒序 | 最近编辑过的记录在前 |
| 记录编号 | 按系统记录编号排列，与业务日期无关 |
| 文本列 | 原来的普通文字顺序，不等同于日期先后 |
| 数字、金额列 | 按数值排列 |
| 日期、日期时间列 | 本轮统一使用真实日期或时间点比较 |
| 单选列 | 按配置的选项顺序排列 |
| 开启日期识别的文本列 | 按识别出的业务日期排序，保留原文 |

打开业务表时使用管理员发布的默认排序。手动点击表头、URL 或保存的筛选视图可以指定其他排序，并优先使用该选择。刷新页面保留当前 URL 中的排序、筛选；导入完成后重新查询，同样遵循当前排序。相同日期使用记录 ID 作第二排序键，空值和无法识别的日期始终排在末尾。

推荐询单表选择业务「日期」倒序。之后补录 100 条 2025 年数据，仍排在 2026 年记录之后，无需依靠刷新纠正顺序。每张业务表可以选择不同的默认排序列；系统不猜测多列日期中哪列才代表业务发生时间。

## 管理员配置步骤

1. 进入公司设置 → 业务表 → 询单表 → **字段与表单**。
2. 配置「日期」字段。若原类型是文本，开启 **按日期排序和筛选**，保存。无需把已发布的 TEXT 字段强制改成 DATE，也不改写已有值。
3. 到 **列表展示与搜索**，将默认排序字段改为「日期」，方向选择降序，保存。
4. 发布变更。检查发布内容，避免把无关的待发布草稿一起带上线。
5. 回到业务表，退出旧的筛选视图或清除 URL 中手动指定的其他排序；新打开该表应显示业务日期倒序。
6. 点击表格上方的日期按钮，选择今天、昨天、近 7 天、近 30 天、本周、本月、上月，或自定义起止日期。其他日期列可在「筛选」中添加。
7. 可保存为个人筛选视图。相对时间（如本月）会随日历变化，不会固定在保存当日。

员工没有该日期列的查询权限时，默认排序安全回退为最近更新时间，不可借排序、筛选或导出推断隐藏列。既有表权限、成员例外、组长权限继续生效。

## 日期识别边界

- 支持完整年份且年在前的 `2026-11-05`、`2026/11/5`、`2026.11.5`。
- 文本日期识别开关支持 `26.11.2`，明确解释为 2026-11-02；两位年范围固定为 2000–2099，不猜测上世纪。
- 不猜测 `11.2`、`7.7` 的年份，不把备注中的局部日期提取为业务日期，不把空号或数字编号当日期。
- `2026-02-31` 等无效日期不会被 JS 自动滚动成另一日。旧文本仍保留、排列到末尾、日期范围筛选不包含它；无效新 DATE/DATETIME 输入会报错。
- 新建表的文件识别支持完整年份点格式。含两位年时保守建议 TEXT，并提示管理员确认，不静默决定世纪。
- Excel 自带日期格式的数字单元格继续通过已有解析器识别，包括 1900/1904 日期系统。
- DATE 按日历日比较；DATETIME 筛选使用公司时区的午夜至下一日午夜，覆盖结束日。相对日期也按公司时区计算。
- 本轮未迁移旧值。既有 DATETIME 导入中无时区输入仍沿用原有 UTC 解释；如导入精确时刻，使用明确时区的 ISO 时间。将无时区 Excel 时刻改为公司时区属于后续独立兼容性任务，不能直接重写历史数据。
