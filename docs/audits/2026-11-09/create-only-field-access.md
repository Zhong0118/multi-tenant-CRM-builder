# 仅新建时可填写的列权限

## 规则与使用

保留原有 `EDIT`、`READ_ONLY`、`HIDDEN`，新增 `CREATE_ONLY`（仅新建时可填写）。

| 列权限 | 新建记录 | 已保存记录 |
| --- | --- | --- |
| 可编辑 | 可填写 | 可修改 |
| 仅新建时可填写 | 可填写 | 只读，包括首次未填写的空值 |
| 只读 | 不可填写 | 只读 |
| 隐藏 | 不显示 | 不显示 |

以上均受表级新建、查看、修改权限约束。公司管理员保持原有纠错权限。组长对组员已有记录的列权限仍为可编辑、只读、隐藏，不提供新建专用选项。

- 个别员工：成员 → 查看和设置 → 展开业务表 → 设置列权限 → 仅新建时可填写 → 保存，立即生效。
- 全体员工默认：业务表设计器中设置员工列权限，保存并发布后生效；成员例外继续优先。
- 如果整条记录都不允许员工修改，已有表级权限就能完成：允许新建和查看，关闭修改。不需要把每列单独改一遍。
- 旧记录不会获得再次录入机会；权限生效后，员工也不能修改旧记录的对应列。
- 导入新记录可填写该列，也可用它查重；重复记录跳过。批量编辑、直接 API 更新、工作流更新均不能改该列。
- 跨表自动化创建新记录可映射该列，并遵守新建校验；不能借此更新已有值。

## 实现与数据影响

复用字段权限、成员例外及统一记录写入引擎。创建和修改按操作类型校验，不依赖前端禁用控件，也不根据字段是否为空决定可否修改。

迁移 `0047_create_only_field_access` 仅增加 PostgreSQL 枚举值，不重写记录或旧权限。不自动将原有只读权限改成新权限。

本轮仅在隔离工作树 `codex/create-only-fields` 和本地测试数据库中验证，没有部署或修改生产数据。主目录未提交修改与电话工作树未动。

将来部署须先应用新增枚举迁移，再部署匹配的 API 和 Web。启用新权限后，旧版 API 不识别该权限，不能直接回滚旧镜像；应前向修复，或先明确恢复涉及的新权限配置。迁移本身不会删除旧数据。
