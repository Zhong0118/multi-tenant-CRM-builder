# 组长按小组成员查看记录

## 行为与操作

适用于管理员已为组长授予「本组成员名下」查看范围的业务表。

1. 从左侧菜单打开业务表，默认只显示组长自己负责的记录。
2. 筛选区新增「小组成员」，默认显示本人姓名及「我」。可输入姓名搜索，选择本组成员后只显示该成员负责的记录。
3. 选择「全部本组」查看整个授权小组；选择本人恢复自己的记录。
4. 切换成员回到第 1 页，保留搜索、字段筛选、排序和每页数量。刷新、打开详情再返回仍保留所选成员。
5. 公共池继续展示公共记录，不按某个人过滤。进入公共池后，私有阶段的数量按本人计算，切回私有阶段也显示本人，避免标签数量与实际列表不一致。

这只是查看范围的筛选。组员记录的可编辑、只读、隐藏列仍由管理员的原权限决定；不会给组长开放管理员批量分配等功能。未分配数据不会因成员筛选进入本组范围。

## 根因与实现

原前端只向公司管理员提供负责人筛选；API 在 GROUP 权限分支直接返回全组负责人集合，忽略传入的 ownerMemberId。现有授权小组名单已由运行时 schema 提供，无需新成员接口或数据库结构。

- 复用 ownerMembers 和姓名头像选项，在组长界面新增独立成员筛选。
- 浏览器初次查询在服务端渲染阶段即设置 scope=mine，避免先显示全组再由客户端修正。
- 增加显式 scope=group，区分「主动查看全部本组」和「默认查看本人」，支持 URL、保存视图及详情上下文。
- 列表和 CSV 共用的负责人查询将所选成员与实时小组、标题可读范围相交。跨组、跨公司或调出小组的成员请求被拒绝；标题隐藏的记录仍不会返回。
- API 未传 scope 的原语义保持不变，避免影响 AI、统计等调用。
- 无数据库迁移，无生产配置或数据修改。
