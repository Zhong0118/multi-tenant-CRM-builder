发现并修复：

1. 完整回归时新测试用全库活动数量断言，混入其他测试租户活动；改为租户/记录范围，并验证其他租户活动不变。
2. 供应商话单中的 `seats_id` 是数字，严格字符串校验拒收；先复现 HTTP 400，再仅转换安全整数，真实供应商格式回归 HTTP 200。对象、数组和不安全整数仍拒绝。
3. 原有数据库跟进触发器会在插入 CALL 活动时续期公海；机器话单通过精确的通话/活动关联跳过续期，测试确认阶段、期限、版本不变，人工跟进原逻辑保留。

核心覆盖：跨租户、本人/组员记录与列权限、停用成员/表、当前权限撤销后的隐私投影、密钥加密和不回显、并发请求幂等、每成员一通未结束呼叫、超时 UNKNOWN 不重拨、重复与乱序话单、晚到录音、无效回调认证、未知关联、模拟不写真实业绩。

## 页面验收

在真实浏览器、独立演示库中执行，未模拟前端 API 响应：

1. 刘洋登录设置页，启用 MOCK，绑定刘洋和赵晨的演示坐席及接听手机，授权客户表的“联系电话”；刷新后开关、绑定和字段选择均保留。
2. 退出并用赵晨登录，客户表仅显示本人的 2 条记录。打开记录拨打抽屉，主叫为赵晨的绑定手机，被叫为该记录电话；未勾选确认时不能提交。
3. 确认模拟拨打后显示“模拟通话已完成 / 30 秒”，记录详情“通话”和独立“通话记录”均显示同一通话，可返回原记录继续使用既有跟进表单。
4. 员工直接访问管理员电话设置 URL 返回无访问权限页面，未返回配置表单。
5. 管理员在赵晨负责的同一客户上模拟拨打，主叫仍取刘洋自己的绑定手机，不冒用记录负责人。
6. 管理员独立通话页显示 2 条；选择赵晨后为 1 条，叠加“未接通”得到明确空态，清除筛选恢复 2 条。
7. 1440px 桌面历史表格、390px 手机历史卡片及拨打抽屉无页面横向溢出。手机卡片拨打入口可用，Escape 可关闭抽屉。
8. 验收前后业务记录均为 96 条，真实跟进活动均为 0；仅新增 2 条带 MOCK 标记的通话记录。

前端独立复核和浏览器发现的问题均在 `a82abd2` 修复：

- 已停用电话字段留下不可取消的旧配置：只在完整成功加载当前已发布表及字段后，明确列出全部失效表/字段，管理员可一次原子清理，保留其他有效配置；请求失败不推断失效。
- 上下文刷新变更主叫/被叫/字段后未重置确认：确认绑定具体号码组合；已发起请求仍锁定原目标及请求 ID，不能借重试换目标。
- 仅按业务表筛选缺少清除按钮：补齐，浏览器验证清除后恢复全部 2 条模拟通话。
- 关闭拨打抽屉未恢复按钮焦点：等待关闭动画，恢复实际点击的按钮；导航后不恢复到旧页面。390px 手机卡片实测 Escape 关闭后原拨打按钮获得焦点。

前端改动与本轮修复均经过独立代码复核；两份任务复核的问题已关闭。新外呼前端行为测试共 31 项。主分支没有被改动，原工作树两份未提交发布记录仍保留。
