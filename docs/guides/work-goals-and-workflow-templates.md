# 员工目标提醒与完整流程模板

这两个功能分别上线。本文对应本地已开发的版本，是否已部署以发布验收记录为准。

## 公司管理员：设置员工每日目标

1. 打开公司工作空间的「团队动态 → 每日目标 → 配置目标」。
2. 选择有实际记录来源的指标：拨打电话、接通电话、添加微信、跟进客户、完成跟进、完成任务。
3. 设置每日目标、提醒时间、工作日，以及全体员工或指定员工。按公司的时区判断日期和提醒时间。
4. 保存后查看团队的今日进度；员工在「任务与日报 → 我的每日目标」查看自己的进度。
5. 到提醒时间后，未达标员工收到站内消息。每项规则、每名员工、每天最多一条；停用规则后不再生成新提醒。

提醒根据系统已经记录的工作统计，不会自动读取员工手机通话或微信。通知保留发出时的完成量，工作页显示当前进度；员工后来完成目标，旧通知里的数字不会被改写。

## 平台管理员：从一家公司的流程建立模板

1. 先由来源公司的管理员配置并发布业务表、字段、员工默认权限、状态流程和跨表自动化。公海设置另行保存后即时生效。
2. 在管理中心打开「模板」，创建或打开一个业务模板。有未保存修改时先保存，再点击「从公司复制流程」。
3. 搜索并选择来源公司，点击「读取流程预览」。查看包含的表、字段、状态、跨表规则、公海和全体员工目标数量。
4. 预览会列出未复制的内容。成员例外权限、指定员工目标、客户记录、人员和执行历史不会复制；未发布的业务表与字段修改也不会作为已发布配置导入。原模板的工作台配置保留。
5. 若提示绑定了具体成员，先在来源公司改为适合各公司复用的配置，按需要重新发布后再读取。不要直接把另一公司的成员 ID 当作新公司的负责人。
6. 点击「替换本地模板草稿」，检查内容，再点击「保存草稿」。这一步尚未产生新的可用模板版本。
7. 点击「发布模板」，检查阻断项和变更摘要，确认发布。

同名表和字段以稳定的代码及字段键关联。已有字段键可能是 `contractNo` 等历史形式，复制时不会重命名。修改字段后，发布检查会验证关联流程是否仍有效。

## 为新公司启用完整流程

1. 管理中心进入「公司管理 → 新增公司」，填写公司与首位管理员手机号。
2. 初始化方式选择「从模板开始」，选择已发布模板并创建公司。
3. 首位管理员登录自己的账号并接受邀请，由平台管理员启用公司，管理员才能进入工作空间。此时公司继承的是独立草稿，模板不会替他伪造发布记录。
4. 公司管理员进入「业务表」，检查初始化的表、员工权限、公海和关联配置。
5. 点击「发布初始化流程」，确认本组待发布的业务表。客户表和订单表可一起完成首次发布，避免相互依赖时需要猜发布顺序。
6. 若配置被其他管理员改动，先重新读取、检查并确认；若有校验错误，整组保持未发布。已经发布的业务表不由这个操作重新覆盖。
7. 如模板含工作台，在工作台配置页单独检查并发布。确认业务表和权限配置后，再邀请员工使用。

## 用客户到开单检查继承结果

前提是来源模板已配置客户公海、询单进度字段、生成开单规则，以及订单确认/签约状态对应的成交保护规则。

1. 管理员在新公司的客户表创建一条专用测试客户。当前已开启公海的表，新建时不指定负责人会进入线索公海；已有未分配记录不会因为开启公海就自动进入。保存后在「线索公海」确认这条新客户的位置。
2. 员工在公海领取客户，检查负责人变为自己，进入待联系阶段并开始联系期限。
3. 员工确认已联系。客户提出需求或询价后，将业务进度标记为「询单中」。这个进度不会自动取消回收期限。
4. 新增并完成跟进，填写实际结果；查看跟进记录和期限是否按该表规则更新。
5. 在客户详情执行模板配置的「生成开单」规则，填写合同编号、金额等必填信息；检查生成的订单与客户关联，负责人按规则继承。
6. 此时尚未确认订单，客户不应提前进入成交保护。具有权限的人执行「确认签约」或模板指定的确认操作后，再检查客户进入成交保护。

注意：询单进度是普通业务字段，成交保护是公海系统状态。确认签约会触发所配置的保护规则，但不会凭空把普通字段从「询单中」改成「已开单」；如业务需要同步该字段，应明确配置对应动作。

## 已有公司和后续模板更新

模板是创建时复制一次的配置快照。发布新模板版本不会自动覆盖已使用旧版本的公司，现有公司继续维护自己的表、规则和数据。模板应用仅允许符合空公司条件的工作空间，不能借此重置已有业务数据。

全体员工目标可随模板复制，并按新公司的员工与时区计算。指定员工目标需要在新公司重新选人。默认员工权限可继承，单个成员的例外权限需要在新公司自行配置。
