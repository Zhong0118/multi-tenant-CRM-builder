# 工作台怎么展示新增记录和开单

工作台按公司配置。「新增客户」不是系统预设的业绩事件。每张卡只查管理员选定的一张已发布、启用中的业务表，只统计当前用户有权查看、且未删除的记录。一个工作台可以同时展示不同表的指标。

## 配置一个可以切换时段的首页

公司管理员打开「我的工作台 → 配置工作台」。在组件库添加「指标卡」，然后按下表配置。标题由管理员填写。

| 想看什么 | 业务表和聚合 | 筛选条件 |
| --- | --- | --- |
| 本期新增客户档案 | 客户表，记录数 | 记录创建时间（系统）→ 跟随工作台时段 |
| 本期新建订单 | 开单表，记录数 | 记录创建时间（系统）→ 跟随工作台时段 |
| 实际确认开单数 | 订单或合同表，记录数 | 成交状态包含「已确认」或「已签约」，再添加「确认日期 → 跟随工作台时段」 |
| 确认成交金额 | 同一张表，求和，选择成交金额，显示格式选金额 | 与确认开单数使用相同条件 |
| 累计客户档案 | 客户表，记录数 | 不加时段筛选 |

- **统计对象：**在客户表创建一条记录，就是一条新增档案。以后修改、分配负责人或跟进这条记录，不会再次计为新增。导入时实际创建的新行也在导入当天计入；如果客户重复建档，仍是两条记录，不是按人去重。
- **统计日期：**「记录创建时间（系统）」由系统写入，不需要先给业务表加字段。要按实际成交日出报表，请选记录里的日期或日期时间字段。例如，上月创建、本月签约的合同应按签约日期计入本月。只有当前状态但没有成交日期时，只能如实展示“目前标记为已成交的记录数”，不能得出历史各月的成交笔数。文本日期不能充当可靠的趋势日期。
- **固定和可切换的指标：**用「今天」「本月」可以固定统计口径；用「跟随工作台时段」，首页切换本周、本月、近 7 天、近 30 天时，指标跟着变化。累计指标不变。趋势图始终跟随所选时段。时间按公司时区计算。
- **趋势或排行：**添加「趋势图」，选择同一业务表，日期字段选系统创建时间或实际业务日期，聚合选记录数或求和。要看每个负责人名下的数量，可添加「员工业绩排行」，成员来源选记录负责人，配上同样的筛选。它按当前负责人分组，并不表示历史上由谁成交。
- **实际微信新增：**「团队动态」里的新加微信是另一项统计：员工在记录动态明确登记添加微信，同一员工和同一条记录的组合只在首次登记时算一次。它不会从导入行数或任意表的“是否通过”复选框自动推断。

## 发布与自查

1. 点击「保存草稿」，再点「预览草稿」，核对卡片标题、数据源和结果。预览按管理员本人的权限统计。
2. 点击「发布工作台」。如果公司有多个工作台，在「工作台设置与目录」中核对管理员默认和员工默认分别指向哪一个，并检查组件受众。
3. 用员工账号重新打开「我的工作台」：只能看自己记录的员工，看到的数比管理员少是正常的；无表读取权限或无统计所需字段权限时，该组件可以不出现。
4. 建议在测试公司做一次核对：先记下两张卡的数字，新增一条客户记录，只有客户卡应加一；修改这条记录，不应再加一。创建订单后，新建订单卡加一；确认订单并填入确认日期后，确认开单卡才加一。切换到不含测试日期的时段，确认记录不会计入。

## 同一规则用于任务与日报、团队动态

公司管理员进入「工作台配置」，找到**员工默认工作台**，为指标卡勾选「用于任务与日报」，并选择「业绩归属」。保存草稿、预览并发布后生效，不需要修改业务表，也不要求开通公海。管理员默认工作台可以与员工默认不同；日报统一取员工默认工作台的配置。

| 指标示例 | 业务表与聚合 | 筛选 | 归属建议 |
| --- | --- | --- | --- |
| 新增客户档案 | 客户表，记录数 | 系统创建时间 → 跟随工作台时段 | 创建人 |
| 新增分配客户 | 客户表，记录数 | 系统创建时间 → 跟随工作台时段 | 当前负责人 |
| 确认开单 | 订单表，记录数 | 状态包含已确认；确认日期 → 跟随工作台时段 | 当前负责人 |
| 确认开单金额 | 订单表，求和，金额字段 | 与确认开单相同 | 当前负责人 |

日报指标需要选择「所有成员」，只支持记录数和求和，并且必须指定一个「跟随工作台时段」的日期条件。不能使用“当前用户”筛选，避免管理员查看某员工时变成管理员自己的条件。日报按选中的那一天查询；团队动态按今天、本周、本月或自定义时段查询。

员工打开「任务与日报」，右侧会出现「业务数据 · 自动统计」。管理员在「团队动态」查看每位成员的同口径结果，也可点「看日报」。这部分直接读取业务表，无需再追加动态。原电话、微信、拜访等工作记录仍从沟通登记读取，日报文字仍手写；每日目标提醒仍使用原有沟通/任务指标，本次没有把新指标自动替换进提醒规则。

### 数字的边界

- 新建记录按创建时间：导入创建的行也计入导入当天；同一条反复修改不增加记录数，重复建档仍算多条。历史业务应使用真实业务日期，不能由系统猜原始发生日。
- 按创建人：转交记录不改变创建人。管理员替员工批量导入时，创建人是导入者；要按获分配员工统计，应选当前负责人。
- 按当前负责人：转交后历史日期的归属结果也会变化。未指定归属的行不归入任何员工，团队成员合计不包括这些行。
- 状态筛选反映当前状态。没有确认日期，无法得出“那天开了几单”。状态、日期、金额更改或记录删除后，统计随之变化，不是冻结的绩效快照。
- 员工只能看到当前权限允许的统计。字段隐藏、表不可读等权限会限制指标；管理员范围更广时，两者数字可能不同。组长的个人日报仍只计自己归属的数据。
- 查询失败或业务表停用会显示“暂不可用”，不会当成 0；缺少读取权限的指标不显示。可刷新页面重新查询。

### 验收步骤

在测试公司创建两张上述指标卡并发布；由员工新建一条客户档案，新客加一；再次修改同一条，新客不再增加。创建未确认订单，确认开单不增加；填写确认日期并改成已确认，该日期的开单数增加。管理员查看团队动态和该员工日报，核对同一日期、同一归属规则。再切到不包含该业务日期的时段，确认记录不计入。

### 加微信与询单示例

若公司在“通过表”记录加微信结果，可配置“新增微信”：记录数、是否通过等于“是”、通过日期跟随工作台时段、按当前负责人归属。“是否通过”为是/否字段时选布尔“是”，为单选时选对应选项，不按列名猜字段。

“询单档案数”可以读取询单表，并按其业务日期统计。询单状态中的“开单”只能说明当前已标记开单；若要统计真实开单当天，应另有确认日期，不能把询单日期冒充开单日。

现有文本日期不必迁移字段类型：在工作台筛选中对 TEXT 列明确选择“跟随工作台时段”，会复用记录列表的日期解析，支持 `2026.11.6`、`2026-11-06`、`26.11.6`、年在前的斜杠日期。空白、不可能日期或日/月顺序含糊的值不参与当天统计。历史已通过但没有通过日期的记录，只能用于不按日期的累计工作台卡片，不能自动补成今天。
